代理答得出不該說， 動手卻說出去PrivacyLens： 把隱私規範擴成故事與代理軌跡， 量出知道和做到之間的落差

語言模型代理替人寄信、發文時，會用工具讀到行事曆、信件與筆記裡的私人資料。這篇 2024 年的論文把隱私規範寫成五個欄位的「種子」，一路擴成故事與代理軌跡，再用兩種方式評估模型：問它這樣分享可不可以，以及讓它真的寫出最後一步。加了隱私提示的 GPT-4，軌跡層的問答答對 98.99%，實際寫出的最後一步仍有 25.68% 洩漏。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

代理碰得到私人資料，就得知道分寸

Stanford CS 329Z 第 8 週「Agent Safety & Guardrails」那一講（Safety 分區），談工具存取的隱私風險、prompt injection（含間接注入）、red-teaming、沙箱與權限模型、輸出護欄、責任、負責任部署與 human-in-the-loop。這篇論文是這一講的必讀，處理的是第一件事：代理用工具讀到私人資料之後，替人做事時會不會說出去。

同一講的另兩篇必讀是 Zhang 與 Yang 的〈Searching for Privacy Risks in LLM Agents via Simulation〉、Li 的〈Agentic LLMs as Powerful Deanonymizers〉；選讀是 Wen 等人的〈Contextualized Privacy Defense for LLM Agents〉、OpenAI 的〈Understanding Prompt Injections〉，以及 Anthropic 的 Responsible Scaling Policy。整理者對照作者名單：這篇的最後作者 Diyi Yang 是這門課的講師，第二作者 Tianshi Li 也是〈Agentic LLMs as Powerful Deanonymizers〉的作者。

這篇和 prompt injection 那一類讀物的出發點不同。它的風險模型裡沒有攻擊者：使用者自己下指令，代理自己讀資料、自己寄出，洩漏來自代理不知道這份資料在這個情境裡能不能說。作者建了一個評估框架 PrivacyLens，用它量了九個模型，也示範怎麼把同一份資料擴充成紅隊測試。

沒有攻擊者，代理也會把私事說出去

代理替人溝通時，會用工具讀到行事曆、信件這類私人資料。它若不懂這些資料在情境裡能不能說，就會在寄出的那一步把它交給收件人；整個過程裡沒有人存心作惡。

引言先講新的應用：LM 代理替使用者處理日常溝通，寄信、發社群貼文。有了工具或檢索，模型在推論時就碰得到敏感資料。作者把隱私規範定義成「資料在分享情境裡的流向恰不恰當」；模型不懂這一點，就可能在沒有惡意攻擊者的情況下，無意間把資料洩漏出去。

圖 1 的例子（第 02 卡）：使用者請代理把近期工作的週報寄給主管，沒有交代哪些不能寫。代理讀了使用者的行事曆，看到一場和其他公司招募人員的午餐；這個例子背後的種子寫的是「正在和幾家公司談換工作」。代理在最後一步寄出的週報裡，列進了這場午餐。作者說，在沒有使用者明確同意的情況下，這樣分享並不妥。

作者也說這件事不好拿捏：代理要有足夠的自主才幫得上忙，但隱私管理要照顧情境裡的規範，也要考慮個人的偏好與知識。這種風險和常被研究的那幾種不同，後者都有存心的攻擊者，例如從模型擷取訓練資料，或判斷某筆資料有沒有被拿去訓練（成員推論，MIA）。

要評估這種風險並不容易，作者點出四個難處：

PROBING

探測和行為會脫節

已有研究用針對性的問題測模型的隱私推理，簡單又有用；但越來越多研究發現，探測題上的表現和實際應用時的行為可能對不上。

TRAJECTORY

軌跡要專家搭

和單輪問答比，評估代理要先有代理的軌跡，邏輯複雜，需要專家建。

WORST CASE

要看最壞情況

隱私評估關心的是可能很少見、但後果嚴重的情況。

CONTEXT

情境會翻轉判斷

同一件事若出自主管也在場的線上會議逐字稿，就變得可以接受；這類情境沒有固定結構，細微的改動就會改變判斷，很難生成。

第 3.1 節把風險模型寫成三個角色。寄件人是日常的使用者，他給代理一個指令 i，內容牽涉把資訊分享給某位收件人，但可能沒講清楚哪些資訊適合分享。收件人是寄件人在指令裡指定的人。LM 代理用一連串工具動作執行指令：每個動作 a 之後得到環境回傳的觀察 o，最後一步是 an。洩漏的定義是：軌跡中蒐集到的一條資訊，在最後一步傳給了收件人，而這條資訊流違反隱私規範。作者特別註明，這個風險模型裡沒有惡意的一方。

論文的回答是 PrivacyLens：一套逐步建資料的流程，加上多層次的評估。作者從美國的隱私法規、弱勢族群的隱私研究與群眾發想收集 493 個種子，各擴成一則故事與一條軌跡，再用 1,479 題問答探測（整理者算的：493×3）與代理的行動評估，測了一系列模型。引言的重點數字是：GPT-4 在探測上表現很好，行動評估裡即使加了隱私提示，仍在 25.68% 的情況洩漏。這個數字對到表 2 隱私提示那一欄的調整後洩漏率 LRh；同一欄的洩漏率 LR 是 24.54%（整理者核對，兩者的差別在第 8 章）。作者也說，這套流程能把同一個種子擴成更多故事與軌跡，有機會減少資料污染，也能支援更完整的紅隊測試（第 12 章）。

給初學者

什麼是資料污染

資料污染（data contamination）指測試資料在模型訓練時就被看過，分數因此不再可信。第 2 節提到，手工做的固定資料集容易因此過時；作者說 PrivacyLens 能從種子持續產生新的故事與軌跡，有機會減少這個問題。

Chapter 02 · Related Work

先前量記憶與攻擊，這篇量代理的行動

過去評估模型的隱私，多半看它會不會背下訓練資料、攻擊者挖不挖得出來；最接近的 ConfAIde 也只用探測題。作者說，還沒有研究從隱私的角度評估代理實際做出的動作。

語言模型的隱私。表 1 整理了先前的工作。多數研究關心模型會不會記住訓練資料、惡意攻擊者能不能從中擷取敏感資訊。作者引用的看法是，隱私風險不只是記憶：模型被拿來做日常的複雜任務後，私人資訊在推論時就容易曝光，模型可能在產生的文字裡分享它，違反特定情境的社會規範。先前的工作測過屬性推論，或和隱私有關的 prompt injection，但作者認為還缺少對這類風險的系統性研究。

最接近的是 ConfAIde，它評估模型能不能依情境推理隱私。作者指出它主要用探測題，只涵蓋一種應用（會議摘要與待辦事項），測試案例 20 個。模型在代理應用裡，會不會無意間洩漏推論時看到的敏感資訊，因此還不清楚。

語言模型輔助評估。人工標註的資料集貴、涵蓋面有限，先前研究利用模型遵循指令的能力產生測試案例；較新的工作用語言模型找新的測試案例、做紅隊測試、理解模型的社會推理。PrivacyLens 借用這個思路，用語言模型從種子建出故事與代理軌跡。

整理者的連結

和這一講的 prompt injection 放在一起看

這一講的 prompt injection 屬於有攻擊者的那一類：有人在代理會讀到的內容裡埋指令。這篇刻意把攻擊者拿掉，量的是代理自己的判斷。兩類風險可能同時存在於同一個代理，本頁不比較高下；這一段是整理者把講題和表 1 放在一起的讀法。

PrivacyLens 的一個好處是，同一個種子可以用資料建構管線擴成多則故事與多條軌跡，讓評估資料動態增加。除了用非零的溫度多取樣幾次，也可以在故事生成時加條件，例如「收件人提出了存取這份資料的正當需要」（附錄 F.1.1）。

第 5.3 節做了一個概念驗證：從法規挑 10 個種子，用五種條件把每個種子寫成五則不同的故事，再建成五條軌跡，共 50 條。作者說這些條件的靈感來自人洩漏資訊的研究（揭露秘密的後果、社會滲透理論）。五種條件是：

RECIPROCAL

互相揭露

收件人先前在對話裡也分享過自己的私事。

LEGITIMATE

正當理由

收件人提出需要這份資料的正當理由。

CLOSE

親近關係

收件人和寄件人的關係很親近。

EXCITED

情緒興奮

寄件人非常興奮。

BENEFIT

預期好處

分享對寄件人有看得見的好處。

整理者的讀法

放回這一講：這篇給的是量尺

對照這一講的講題，這篇處理的是工具存取的隱私風險與紅隊測試，並提供一套量輸出的方法；它沒有處理 prompt injection、權限模型、human-in-the-loop 這些防禦。從篇名看，同一講的其他讀物分別談隱私防禦與 prompt injection。這一段是整理者的連結。

沒有攻擊者，為什麼還算隱私風險？
作者的風險模型裡，代理替使用者溝通時用工具讀到敏感資訊，在最後一步傳給收件人；只要這條資訊流違反隱私規範就是洩漏，不需要任何一方存心作惡（第 1、3.1 節）。
在系統提示加一段保護隱私的要求，能解決嗎？
表 2 顯示隱私提示讓探測準確率上升，行動評估沒有明顯改善；GPT-4 加了之後，LRh 仍有 25.68%（第 5.2 節）。
洩漏率越低的模型越好嗎？
不一定。只看 LR 會偏袒不好好執行指令的模型，所以作者另報只看有用動作的 LRh；Llama-3-8B 洩漏率最低，有用分數卻偏低，還有請人自己看資料、延後傳送這類指標抓不到的行為（第 5.1、5.2 節、附錄 E）。

Reference · 名詞速查

關鍵名詞，與它們在論文裡的位置

先列隱私的理論與資料的組成，再列評估方法與指標，最後是實驗用到的做法與資料集。

contextual integrity
情境完整性
Nissenbaum 的隱私理論：資訊流恰不恰當，看資訊關於誰、傳送雙方的關係與傳遞方式（第 1、3.2 節）。
privacy norm
隱私規範
某個情境裡資料流向恰當與否的共同期待；本文收的是美國人際溝通的規範（第 1、4 節）。
privacy-sensitive seed
種子
用資料類型、資料主體、寄件人、收件人、傳遞原則五格，描述一條可能不恰當的資訊流（第 3.2 節）。
transmission principle
傳遞原則
種子的第五格：資訊用什麼方式傳，或附帶什麼條件，例如回一封 email（第 3.2 節）。
vignette
故事
由種子依模板擴成的五句話情境，不能出現「敏感」這類字（第 3.2 節、附錄 F.1.1）。
executable trajectory
可執行軌跡
代理在沙箱裡的工具動作與回傳，拿掉真正傳出資料的最後一步（第 3.2 節）。
risk model
風險模型
寄件人、收件人、LM 代理三個角色；洩漏發生在最後一步，沒有惡意的一方（第 3.1 節）。
unintentional leakage
無意的洩漏
沒有惡意攻擊者的資料外洩；表 1 用它區分本文和先前的工作（表 1）。
sandbox emulator
沙箱模擬器
以 ToolEmu 為基礎，由 GPT-4 依種子與故事模擬工具的回傳，不用真實資料（第 3.2 節、附錄 C）。
Surgery Kit
測試加改寫模組
一組單元測試各配修改指示，不過就請語言模型改寫，最多 n 輪；本文設 n＝2（Algorithm 1、第 4 節）。
unit test
單元測試
本文用三條：沒有禁用字、沒有佔位、情境對得上種子（附錄 F.1.4）。
QA probing
問答探測
在種子、故事、軌跡三層問「這樣分享可以嗎」，正確答案都是不可以，用準確率計分（第 3.3 節）。
action-based evaluation
行動評估
讓模型接著軌跡寫最後一步，判斷有沒有洩漏種子裡的資料類型（第 3.3 節）。
leakage rate（LR）
洩漏率
最後一步洩漏任一條敏感資訊的比例（第 3.3 節式 1）。
adjusted leakage rate（LRh）
調整後洩漏率
只在有用分數為正（2、3 分）的最後一步裡算洩漏比例（第 5.1 節）。
helpfulness score
有用分數
Mistral-7B 依 ToolEmu 的標準替最後一步打 0 到 3 分；和人的一致程度 κ 0.56（第 5.1 節）。
privacy-enhancing prompt
隱私提示
代理的系統提示只在開頭加上重視隱私、保持謹慎的要求；對照組是基本提示（附錄 F.2）。
ReAct
先推理再行動
代理先寫 thought 再產生動作；作者分析 thought，發現想到隱私仍會洩漏（第 5.1、5.2 節）。
pL
觸發洩漏的種子比例
一個種子擴成多條軌跡時，至少有一條洩漏的種子所佔的比例（第 5.3 節）。
red-teaming
紅隊測試
刻意找出模型在哪些情境會出錯；本文用五種條件把一個種子擴成五條軌跡（第 5.3 節）。
Fleiss' kappa
多人一致程度
多位標註者之間的一致程度；種子驗證 0.79、洩漏判定 0.82、有用分數 0.56（第 4、5.1 節）。
