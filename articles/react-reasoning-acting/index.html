REACT · SYNERGIZING REASONING AND ACTING · 圖卡＋教材整合版

讓模型邊想邊查， 推理與行動交錯ReAct：thought 決定下一步做什麼， 行動帶回的觀察再修正推理

大型語言模型能一步步推理（chain-of-thought），也能產生行動去操作環境，但在這篇論文之前，兩種能力多半被分開研究：只推理的模型會編造事實，只行動的模型查得到資料卻整理不出答案。這篇論文提出 ReAct，讓模型在同一條軌跡裡交錯寫出 thought 與行動：thought 規劃下一步、消化查到的東西，行動去 Wikipedia 查資料，或在文字遊戲、購物網站裡做事，觀察回來再接著想。作者在兩個知識任務與兩個決策任務上測試：它穩定勝過只行動的做法，和只推理的 CoT 各有勝負，兩者互相當後援時最好；在決策任務上，一兩個示範就勝過用成千上萬筆資料訓練的模仿學習與強化學習。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

課堂上的 ReAct 模式，就是這篇論文的 thought、行動、觀察迴圈

Stanford CS 329Z 第 4 週「Agent Design Patterns & Scaffolds」那一講，談 workflows 與 agents 怎麼分、五種可以組合的 workflow、ReAct 與 plan-and-execute、reflection 這些 agent 模式，以及 scaffold 為什麼是一個設計決策。這篇 2022 年的論文是 ReAct 模式的出處，排在這一講的必讀。

做 agent 的人說「用 ReAct」，指的通常是一種迴圈：模型先寫一段想法，再決定呼叫哪個工具，工具的回傳接回 prompt，模型接著想下一步，直到給出答案。這個迴圈的原型就是這篇論文。論文裡的行動就是 prompt 文字裡的一行，例如 Search[Apple Remote]；作者用的是一個凍結的 PaLM-540B，加上幾條人寫的示範軌跡，想法、行動、環境的回傳都寫在同一段文字裡，一行一行標成 Thought、Act、Obs，由 prompt 教模型照樣寫下去。

放回這一講的分類，下面是整理者的讀法。依常見的分法，workflow 是由程式事先排好每一步的流程，agent 則讓模型依每一步看到的東西，自己決定下一個動作。ReAct 屬於後者：模型每一步都自己決定要查什麼、做什麼，論文在 ALFWorld 的實驗甚至讓模型自己決定什麼時候該停下來想。這一頁會一路標出論文裡哪些選擇其實是 scaffold 的設計決策：thought 寫得多密、示範怎麼寫、工具做得多強、答不出來時退回哪個方法。

第一作者 Shunyu Yao 當時在 Princeton，這項工作是他在 Google 實習期間做的；作者群來自 Princeton 電腦科學系與 Google Research 的 Brain 團隊。論文 2022 年 10 月貼上 arXiv，2023 年 3 月的 v3 是 ICLR 2023 的定稿版本，這一頁的數字都依 v3。實驗用的是 PaLM-540B 與 GPT-3（text-davinci-002）這些 2022 年的模型，數字只對它們成立；這一頁更在意迴圈怎麼設計，以及每一種設計各自失敗在哪裡。

讀論文和讀部落格文章不同，這一頁的處理方式也要先說清楚。章節跟著論文的論證走，不跟著節號走：第 1 到 3 章是問題與方法（論文第 1、2 節），第 4 到 8 章是知識任務（第 3 節），第 9 到 11 章是決策任務（第 4 節），第 12 章是相關工作，第 13 章是結論與代價。有幾處合併：切換策略與微調，各自把「方法」和「結果」併成一章；附錄 A.2（過時的標籤）併進失敗分析，附錄 A.3（人工編輯 thought）併進第 11 章，附錄 A.1（改用 GPT-3）併進決策任務的結果。數字只用正文與表 1 到表 5；圖 2、圖 3 的點與長條沒有標數字，這裡只轉述原文的趨勢，不替它們補數字。整理者算的差距會標出來。軌跡與 prompt 的例子都是教學用的精簡版，動作名稱照原文，想法的文字是整理者改寫的中文。

先把幾個名詞對齊

  • chain-of-thought（CoT）：在 prompt 裡示範「先寫推理步驟、再寫答案」，讓模型照著一步步推理。
  • few-shot prompting：不改模型的權重，只在 prompt 裡放幾個完整的示範，讓模型照樣做。
  • 代理（agent）與環境：代理每一步看到環境給的觀察，選一個行動；環境執行行動，再給下一個觀察。
  • 多跳問答（multi-hop QA）：答案要串起兩份以上的資料才找得到，例如先查出 A 是誰，再查 A 的某個屬性。
  • 幻覺（hallucination）：模型寫出聽起來合理、但和事實不符的內容。

論文從人怎麼做事講起。人在兩個動作之間常常會用語言想一下：菜切好了，提醒自己該燒水；發現沒有鹽，改用醬油和胡椒；不會揉麵糰，想到該上網查一下。反過來，人也會為了想清楚而去做點什麼：翻開食譜、打開冰箱看看有什麼材料，好回答「現在能煮什麼」。作者引用 Vygotsky、Luria、Baddeley 等人的研究說，這種「內在語言」被認為能幫人自我調節、擬定策略，並維持工作記憶。行動與推理緊密配合，讓人能快速學會新的工作，在沒見過的情況或資訊不確定時，仍然能穩健地做決定與推理。

語言模型這邊，兩種能力當時各有一條研究線。一條是 chain-of-thought：適當 prompt 過的大模型能寫出好幾步推理，在算術、常識、符號推理題上從問題推出答案。作者對這條線的評語是：

"this “chain-of-thought” reasoning is a static black box" 「這種 chain-of-thought 推理是一個靜態的黑盒子」：第 1 節對只推理做法的評語。

靜態的意思是，模型只用自己內部的表示產生想法，沒有接地到外部世界，所以沒辦法邊看邊反應，也沒辦法更新自己的知識。後果是事實幻覺，以及錯誤沿著推理過程一路傳下去。另一條研究線讓預訓練語言模型在互動環境裡規劃與行動，例如 SayCan 與 WebGPT：把觀察轉成文字，用語言模型產生領域專用的行動或計畫，再交給控制器挑選或執行。這些做法不讓語言模型對高層目標做抽象推理，也不維持支援行動的工作記憶；唯一的例外是 Inner Monologue，它做了有限的語言推理，用來複述目前環境狀態的空間事實。作者說，在這些只需要操作幾塊積木的簡單具身任務之外，還沒有研究問過：推理與行動能不能為了一般的解題工作互相配合，合起來又會不會比單獨做任何一樣都好。

作者列的貢獻有四項：提出 ReAct 這個以 prompt 為基礎的範式；在多個基準上和只推理或只行動的方法比較；用消融實驗分析行動對推理任務、推理對互動任務的重要性；分析 ReAct 在 prompting 設定下的限制，並做初步的微調實驗。另外有一個貫穿全篇的主張：推理寫在軌跡裡，人就能分辨哪些資訊來自模型內部、哪些來自外部環境，也能讀推理軌跡，了解模型為什麼採取某個行動。

第 2 節先把問題寫成一般的代理設定。在時間 t，代理從環境收到一個觀察，依照某個策略選一個行動；策略看的是到目前為止的 context，也就是觀察、行動、觀察、行動一路排下來的紀錄。作者指出，當「從 context 到下一個行動」的對應很隱晦、需要大量計算時，這個策略很難學。圖 1 有兩個例子：(1c) 的 Act 查到了該查的頁面，卻產生不出正確的最後一步，因為那需要對整段軌跡做複雜的推理；(2a) 在 ALFWorld 裡的 Act 看不出水槽 1 上根本沒有胡椒罐，於是一再送出不可能成功的「拿起胡椒罐」。

ReAct 的想法很簡單：把代理的行動空間擴大成「原本的行動」加上「語言」。落在語言空間的行動，作者稱為 thought 或推理軌跡（reasoning trace）。它不影響外部環境，所以沒有觀察回來；它的作用是對目前的 context 做推理、把有用的資訊組合起來，再接到 context 後面，支援之後的推理或行動。下面用虛擬碼把這個迴圈寫出來：

ReAct 迴圈 · 教學用虛擬碼（整理者寫的，不是論文的程式） 
context = 示範軌跡 + 問題                  # 示範是人寫的完整軌跡
for step in range(max_steps):
    text = llm(context)                   # 模型自己決定這一步寫什麼
    if is_thought(text):
        context += text                   # thought：不送進環境，沒有觀察
    elif is_finish(text):
        return answer_of(text)            # finish[答案] 結束這一題
    else:
        obs = env.step(text)              # search[...]、go to ...、click[...]
        context += text + obs             # 觀察接回 context

作者也說明這個設計的難處：語言空間是無限的，在擴大後的行動空間裡學習很困難，需要很強的語言先驗。所以論文主要的設定是凍結的大型語言模型 PaLM-540B：不更新權重，只靠 prompt 裡幾個示範，讓它同時產生領域專用的行動和自由形式的 thought。每個示範都是一條人寫的解題軌跡，裡面有行動、thought 與環境的觀察（附錄 C 列了全部的 prompt）。註腳補充，附錄 A.1 用 GPT-3 跑的結果比 PaLM-540B 還好，第 10 章會看到數字。

背景

context、策略與行動空間

A · 好設計

在自己的行動上面寫想法

寫示範的人只要在自己做過的每個行動上面，用語言打出當時的想法。論文沒有特別挑格式、設計 thought 或挑選示範。

B · 通用

一套做法，四種任務

thought 的內容與出現方式都很自由，所以同一套做法能用在問答、事實查核、文字遊戲、網頁操作這些行動空間與推理需求都不同的任務。

C · 效果好

一到六個示範就類推

作者說它在不同領域都穩定勝過只推理或只行動的基線，對示範的挑選也不敏感；第 5 章會看到，HotpotQA 上單獨的 ReAct 其實略輸 CoT。

D · 可控制

人讀得懂，也改得動

人能檢查推理與事實是否正確，也能在執行途中編輯 thought 來修正代理的行為（附錄 A.3，第 11 章）。

思考題 · 01

你的 agent 該用密集還是稀疏的 thought？

想一個你手上的 agent 任務：它一次要走幾步，每一步的觀察有多長，多少步驟只是移動或點擊。

步數少、每一步都得從觀察裡找線索的任務（查資料、查核），像 HotpotQA 那樣每一步都寫；步數多、多數步驟只是移動或點擊的任務，像 ALFWorld 那樣只在拆目標、換子目標、推測東西在哪時寫，其餘交給模型自己決定。

關鍵觀念 · 一

答對不等於做對

表 2 的假陽性是一個容易被略過的類別：答案對了，推理卻是編的或錯的。附錄 E.1 有一個 CoT 的例子：模型寫出兩所大學各自的創立年份，比較時卻推出錯誤的先後，最後給的答案又和自己的推理對不上，偏偏這個答案是對的。只看最後答案的 EM，這種軌跡會被算成成功。

整理者的讀法：這正是論文主張的可解釋性派得上用場的地方。ReAct 的軌跡把「模型說它知道什麼」和「它查到什麼」分開寫，人工檢查時才分得出真陽性與假陽性；只推理的 CoT 把兩者混在同一段文字裡。

兩個方法都有接近三成的失敗其實是標籤不一致（29% 與 28%）：預測是對的，只是字面和標準答案不同。附錄 A.2 還有一種更極端的情況：資料集的標籤本身已經過時。圖 4 的題目問某間飯店有幾個房間，而房間數在 HotpotQA 建立之後增加了。Standard 與 CoT 因為幻覺答錯；Act 雖然能上網，卻因為缺少推理、不知道怎麼互動，沒有給出答案；只有 ReAct 查到最新的資訊，給出合理的答案。作者由此推測，把推理能力整合得更好，可能對當時新出現的一批能上網的語言模型有幫助。

def react_then_cotsc(q, max_steps):        # HotpotQA 用 7 步，FEVER 用 5 步
    answer = run_react(q, max_steps)
    if answer is None:                      # 步數用完還沒 finish
        answer = majority(sample_cot(q, n=21))
    return answer

def cotsc_then_react(q, n):
    answers = sample_cot(q, n)              # 溫度 0.7 抽 n 條 CoT
    best, count = most_common(answers)
    if count * 2 < n:                       # 多數答案不到一半：內部知識沒把握
        return run_react(q)
    return best

ALFWorld 是一個合成的文字遊戲，設計成和具身任務基準 ALFRED 對齊。它有 6 類任務，代理要在模擬的家裡用文字行動（例如去咖啡桌 1、拿起紙 2、使用檯燈 1）完成一個高層目標（例如在檯燈下檢查一張紙）。一個任務可能有超過 50 個地點，專家策略也要超過 50 步，所以代理得規劃並追蹤子目標，還要有系統地探索（例如把書桌一張一張找過去找檯燈）。遊戲裡內建一個難點：要判斷常見的家用品可能放在哪裡（檯燈多半在書桌、架子或梳妝台上），這正好讓語言模型運用預訓練學到的常識。

作者從訓練集替每類任務隨機標註 3 條軌跡，軌跡裡有稀疏的 thought，做四件事：拆解目標、追蹤子目標是否完成、決定下一個子目標，以及用常識推理東西在哪裡、拿到之後要做什麼。評估照 ALFWorld 原作者的設定，在 134 場沒看過的遊戲上依任務類別進行。為了測穩定性，每類任務從 3 條標註軌跡取 2 條排列，做出 6 組 prompt；Act 的 prompt 用同樣的軌跡，只拿掉 thought。這些軌跡是從訓練集隨機挑的，對 ReAct 與 Act 都沒有偏袒，是一個公平、受控的比較，專門測稀疏 thought 的價值。基線是 BUTLER，一個每類任務用 10⁵ 條專家軌跡訓練的模仿學習代理。

WebShop 要回答的是：ReAct 能不能在有雜訊的真實語言環境裡做實際的事？它是一個線上購物網站環境，有 118 萬件真實商品與 1.2 萬條人寫的購物指令，商品標題、描述與選項都是從 Amazon 抓來的，結構化與非結構化的文字混雜。代理要依使用者的指令（例如要一個有抽屜、鎳色表面、140 美元以下的床頭櫃），透過搜尋與點選「顏色：現代鎳白」「回到搜尋」這類按鈕，買到符合的商品。評分用 500 條測試指令，看兩個數字：平均分數（選中的商品涵蓋了幾成指定的屬性，對所有回合取平均）與成功率（選中的商品滿足全部要求的回合比例）。

Act 的 prompt 只有搜尋、選商品、選選項、購買這些動作；ReAct 的 prompt 另外會推理要探索什麼、什麼時候買、哪些商品選項和指令有關。對照的基線有兩個：用 1,012 條人工標註軌跡訓練的模仿學習（IL），以及再加上 10,587 條訓練指令做強化學習的 IL+RL。

關鍵觀念 · 二

改兩句 thought，救回一局遊戲

附錄 A.3 做了一個人機協作的實驗：讓人檢查並編輯 ReAct 的推理軌跡。圖 5 的任務是把兩個鑰匙圈放進保險箱。原本的軌跡在第 17 步寫了一句幻覺的 thought，最後失敗；人只刪掉第 17 步那句幻覺，再在第 23 步補一點提示，ReAct 的行為就大幅改變，順著編輯過的想法完成任務。

作者指出這對人很省力：從打出幾十個行動，變成只改幾句 thought。這種執行途中的修正，Act 與先前的強化學習方法很難做到，因為人改不了模型的參數，改掉幾個行動也未必改得動模型其餘的行為。它也超出用對話更新目標或子目標的做法：編輯 thought 可以改模型的內在信念、推理風格，或任何 thought 空間支援的東西。作者把更系統的研究留給未來。

思考題 · 03

你的 agent 寫的 thought，是在推理還是在複述？

打開你的 agent 最近一次失敗的軌跡，把每一句 thought 分成兩類：只是描述剛剛看到什麼、目標還差什麼；或是判斷完成了沒、下一步做什麼、東西可能在哪。

如果幾乎都是第一類，情況就像 ReAct-IM。可以從示範下手：在示範軌跡裡補上「完成了哪個子目標、接下來做什麼、為什麼先找這裡」這幾種 thought，再用同一組題目比較成功率。

Chapter 12 · Related Work

推理與行動原本是兩條研究線，ReAct 把它們接進同一個輸入流

用語言模型推理的一脈，從 chain-of-thought 延伸出很多變形，但推理都是孤立、固定的；用語言模型做決策的一脈，讓模型操作瀏覽器、API 或機器人，卻沒有明確地建模推理過程。

推理這一條，最有名的是 chain-of-thought（Wei 等人 2022），它顯示大型語言模型能為解題寫出自己的「思考程序」。之後的延伸包括：把複雜問題由簡到繁拆解的 least-to-most prompting、不用示範的 zero-shot-CoT，以及取多數答案的 self-consistency。Madaan 與 Yazdanbakhsh（2022）有系統地研究 CoT 的形式與結構，發現符號、模式與文字的存在，對 CoT 的效果很關鍵。也有工作把推理做成比 prompting 更複雜的架構：Selection-Inference 把推理分成「選擇」與「推論」兩步；STaR 用模型自己產生的正確理由微調模型，來 bootstrap 推理過程；Faithful reasoning 把多步推理拆成三步，每一步由一個專門的語言模型負責；Scratchpad 在中間的計算步驟上微調語言模型，也在多步計算問題上看到進步。作者的定位是：ReAct 做的不只是孤立、固定的推理，它把模型的行動與對應的觀察整合成一條連貫的輸入流，讓模型推理得更準，也能處理推理以外的任務，例如互動式決策。

決策這一條，語言模型越來越常被當成互動環境裡的策略模型。WebGPT 用語言模型操作瀏覽器、瀏覽網頁，回答 ELI5 裡的複雜問題；和 ReAct 相比，它沒有明確建模思考與推理的過程，而是仰賴昂貴的人類回饋做強化學習。對話系統方面，BlenderBot、Sparrow 這類聊天機器人，以及 SimpleTOD 這類任務導向的對話系統，也訓練語言模型決定何時呼叫 API；它們同樣沒有明確考慮推理過程，也仰賴昂貴的資料與人類回饋來學策略。相較之下，ReAct 學策略的方式便宜得多，因為決策過程只需要用語言描述推理；作者在註腳說，人類回饋也可以互補地加進來，留待未來。

在互動與具身環境裡，最相關的是 SayCan 與 Inner Monologue。SayCan 讓語言模型直接預測機器人可能採取的行動，再用一個以視覺環境為基礎的可行性（affordance）模型重新排序，做出最後的預測。Inner Monologue 加入同名的內心獨白，實作方式是把環境的回饋注入 prompt；作者說它是第一個展示這種閉迴路系統的研究，ReAct 也建立在它之上，但他們主張 IM 並沒有真正的內在想法（第 11 章）。最後，作者提到在其他設定下，把語言當作語意豐富的輸入來做互動決策也很成功，而大型語言模型的進展也催生了 Reed 等人（2022）那種多才多藝的通才代理。

整理者的讀法

放回這一講：scaffold 裡的設計決策

下面是整理者的連結，論文沒有用 scaffold 這個詞。把 ReAct 當成一個 scaffold 來看，論文其實回答了好幾個設計決策：thought 要多密（知識任務每步都寫，決策任務讓模型自己決定）、thought 要寫哪幾種（第 11 章的消融顯示，只複述回饋的 thought 成功率低很多）、工具要多強（Wikipedia API 刻意做弱，逼模型用推理決定查什麼）、失敗時退回哪裡（ReAct 與 CoT-SC 互相當後援），以及要不要把軌跡拿去微調。這一講談的 plan-and-execute、reflection 等其他模式，可以用同一組問題去比較。

ReAct 一定比 CoT 好嗎？
不一定。表 1 裡單獨的 ReAct 在 FEVER 勝過 CoT（60.9 對 56.3），在 HotpotQA 略輸（27.4 對 29.4）；兩題最好的成績都來自 ReAct 與 CoT-SC 互相當後援的組合（35.1 與 64.6）。
需要訓練模型嗎？
主要實驗不用：凍結的 PaLM-540B 加一到六個人寫的示範就能跑。微調是另一個選項：用 3,000 條答對的軌跡微調 PaLM-8B 與 62B 之後，ReAct 是四種方法裡最好的。
thought 會不會自己亂想？
會。表 2 裡 ReAct 失敗的 47% 是推理錯誤，包括一再重複前一步；附錄 A.3 也有一局遊戲因為一句幻覺的 thought 而失敗。因為 thought 寫在軌跡裡，人讀得到，也能直接改掉那一句。
理由寫在行動旁邊：模型查得到該查的，人也看得出它為什麼這樣查。 整理自第 1、2、3.3 節

先列 ReAct 本身的零件，再列對照組與組合方法，最後是四個基準、指標與決策任務的基線。

ReAct
推理加行動
讓語言模型交錯產生 thought 與任務行動的 prompting 範式；名字來自 Reason + Act（第 2 節）。
thought／reasoning trace
推理軌跡
語言空間裡的行動：不影響環境、沒有觀察，只把推理接到 context 後面。
action
行動
送進環境的動作，例如 search[entity] 或去櫃子 1。
observation
觀察
環境對行動的回傳，接回 context。
context
脈絡
到目前為止的觀察、行動與 thought 的完整紀錄；策略依它選下一個行動。
trajectory
軌跡
一題從開始到結束的 thought、行動、觀察序列；示範就是人寫的軌跡。
dense／sparse thought
密集／稀疏的 thought
知識任務每一步都寫 thought；決策任務只在關鍵位置寫，何時寫由模型決定。
Standard

示範只剩問題與答案，刪掉所有 thought、行動、觀察的基線。
CoT
思維鏈
只留推理的基線：刪掉行動與觀察。
CoT-SC
自洽性取多數

Act
只行動
刪掉 thought、只留行動與觀察的基線。

先查再想
