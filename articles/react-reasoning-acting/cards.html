REACT · SYNERGIZING REASONING AND ACTING · 圖解卡 · 16:9 · 13 張
推理決定查什麼，
查到的再改寫推理。
整理自 arXiv 論文〈ReAct〉（2022-10-06，Shunyu Yao 等 7 人，Princeton、Google Research；ICLR 2023）。讓語言模型在同一條軌跡裡交錯寫出 thought 與行動：想法決定下一步查什麼、做什麼，行動帶回的觀察再修正想法。
只推理或只行動的問題
ReAct 的做法與結果
模型本身／終點
中性節點
整組共用同一套語意色：橘是只推理、只行動的做法和它們的失敗，綠是 ReAct 的做法與結果，深藍是模型本身與終點。
一條軌跡，三種行
thought 規劃與消化 · 行動去查、去做 · 觀察接回 context，下一步再想
四個基準：HotpotQA、FEVER、ALFWorld、WebShop；主要模型是凍結的 PaLM-540B，附錄另外測了 GPT-3。

只推理：靜態的黑盒子
CoT 只用模型內部的表示推理，沒有接地到外界；一個事實編錯，後面每一步都跟著錯。
第 1 節：事實幻覺與錯誤傳播。
只行動：查得到，收不了尾
Act 搜到了 Front Row (software) 那一頁，卻沒有推理把線索接起來，最後送出 finish[yes]。
先前的行動型方法不對高層目標推理，也沒有工作記憶。
交錯：為行動而推理，為推理而行動
推理建立、維護、調整行動計畫；行動去 Wikipedia 取回資訊，再接回推理。
人做菜也是這樣：發現沒有鹽，就改用醬油和胡椒。

03 / 13thought 也是一種行動
thought 也是一種行動，只是不送進環境
第 2 節：代理在時間 t 收到觀察、依 context 選行動。ReAct 把行動空間擴充成「原本的行動 ∪ 語言」，落在語言的那一種就是 thought

凍結的 LLM
PaLM-540B＋1 到 6 條示範

寫出
接回

只接回 context
行動：search、lookup、go to、click…
觀察：環境回傳的一段文字

HOTPOTQA · FEVER：WIKIPEDIA API

決策任務裡，THOUGHT 也寫成一個動作
think: 先找胡椒罐，可能在櫃子或流理台
環境只回 OK
context：問題＋到目前為止的每一個 thought、行動、觀察，一步接一步排下去；下一步由模型讀完整段 context 決定
Act 得從 context 直接猜
對應很隱晦時，模型收不了尾（圖 1 的 1c），或一再做不可能的動作（2a）。
例：水槽上根本沒有胡椒罐，它還是一直去拿。
thought 先把 context 整理好
拆目標、抽重點、記進度、處理例外；它不改變環境，只把這一句接到 context 後面。
下一個行動因此比較好選。
語言空間無限大，要靠大模型
在「行動＋語言」裡學策略需要很強的語言先驗，所以用凍結的 PaLM-540B 加幾條示範。
附錄 A.1：換成 GPT-3，效果更好。
注意：o_t、a_t、c_t 與「行動空間 ∪ 語言」照第 2 節；環境面板裡的動作是整理者從第 3、4 節與附錄 C 挑的例子。
04 / 13一條軌跡裡的四個 thought
thought 拆目標、抽重點、處理例外、收尾
圖 1 (1d) 的 ReAct 軌跡攤開成四步。第 2 節列 thought 的種類時，引用的就是這幾步；知識任務每一步都寫 thought
問題
除了 Apple Remote，還有什麼裝置能控制 Apple Remote 原本設計要搭配的那個程式？
THOUGHT 1
拆解目標、訂計畫
要先查 Apple Remote，找出它原本設計要搭配的是哪個程式。
Act 1　search[Apple Remote]
Obs 1：Apple 的遙控器，原本設計用來控制 Front Row 媒體中心程式…
THOUGHT 2
從觀察抽重點
它原本搭配 Front Row 媒體中心程式；下一步查 Front Row，看還有什麼能控制它。
Act 2　search[Front Row]
Obs 2：找不到這個條目；相似的有 Front Row (software) 等幾個。
THOUGHT 3
處理例外、改計畫
Front Row 這個條目不存在，改查相似清單裡的 Front Row (software)。
Act 3　search[Front Row (software)]
Obs 3：Front Row 是一個已經停產的媒體中心軟體…
THOUGHT 4
抽重點＋綜合答案
它可以用 Apple Remote 或鍵盤功能鍵控制，所以答案是鍵盤功能鍵。
Act 4　finish[keyboard function keys]
答對 ✓　同一題的 Standard、CoT、Act 都答錯（第 2 卡）。
第 2 節列的五種
拆解目標、訂計畫 · 帶入常識 · 從觀察抽重點 · 追蹤進度、切換計畫 · 處理例外、調整計畫；上面四步用到三種，另外兩種見第 10 卡的 ALFWorld 例子
thought 放多密，依任務而定
知識任務：每一步都寫
HotpotQA、FEVER 的示範是密集的 thought：thought、行動、觀察輪流出現，就像上面這四步；每個 thought 都替下一個行動做準備。
示範各 6 條與 3 條，都是人寫的軌跡；作者說再多也不會更好。
決策任務：模型自己決定何時寫
ALFWorld、WebShop 一題可能要走幾十步，thought 只需要稀疏地出現在最相關的位置；什麼時候寫，由模型自己決定。
例：拆目標、判斷東西在哪、換子目標的時候。
示範：在行動上面打出想法
寫示範的人在自己做過的每個行動上面，用語言寫下當時的想法；論文沒有特別挑格式、設計 thought 或挑選示範。
作者列的四個特點之一：直覺、好設計。
注意：thought 類型的標法照第 2 節對圖 1 的引用；thought 與觀察是整理者改寫的中文精簡版，動作名稱照原文。
05 / 13Wikipedia API 的三個動作
三個動作的 Wikipedia API，刻意做得很弱
第 3.1 節：模型只拿到問題或宣稱，沒有附上支持段落；要知道什麼，就得自己決定去查什麼，每次只拿回一小段
search[entity]
條目存在：回傳頁面的前 5 句；不存在：回傳搜尋引擎找到最相似的 5 個條目名
lookup[string]
在目前的頁面裡，找下一句含有這個字串的句子，就像瀏覽器的 Ctrl+F
條目名
前 5 句／相似條目
字串
下一句符合的句子
問題或宣稱
只給問題，不附段落
LLM＋ReAct 示範
PaLM-540B；HotpotQA 6 條、
FEVER 3 條人寫的軌跡
評分
HotpotQA 看 EM
FEVER 看準確率
答案
這一題結束
finish[answer]
送出答案、結束這一題：HotpotQA 是一段答案文字，FEVER 是三個標籤之一
刻意做得很弱
多半只能靠確切的條目名，取回一段文字的一小部分，比當時最好的字面或神經檢索器弱得多。
目的：模擬人怎麼用 Wikipedia，逼模型用推理決定查什麼。
示範只要 6 條與 3 條
HotpotQA、FEVER 各從訓練集隨機挑 6 題與 3 題，人工寫成 ReAct 軌跡；作者說再多放示範也不會更好。
每一步都有 thought、行動、觀察（密集的 thought）。
兩個資料集，都只給問題
HotpotQA 要串起兩段以上的 Wikipedia 段落；FEVER 的宣稱標 SUPPORTS、REFUTES 或 NOT ENOUGH INFO。
模型只能靠自己記得的，或查回來的。
注意：三個動作的定義照第 3.1 節；成對箭頭與輸入、評分兩端是整理者的畫法，Wikipedia 端的實作細節原文沒有再多說。

ReAct 特有的錯
一再重複前一步的 thought 與行動、跳不出迴圈，算在推理錯誤裡；作者懷疑和貪婪解碼有關，換成 beam search 這類解碼也許有幫助
CoT：幻覺是主要病因
答錯的軌跡裡 56% 是幻覺；答對的也有 14% 是靠編出來的推理或事實湊中，ReAct 是 6%。
沒有外部知識可以核對，編錯的事實會一路傳下去；ReAct 能查知識庫，這一類是 0%。
ReAct：結構換來推理錯誤

13 / 13結論：想和做寫在同一條軌跡
想和做寫在同一條軌跡：看得見、查得到、改得動
第 6 節：一個簡單的方法，在多跳問答、事實查核與互動決策上都有更好的表現，軌跡也能被解釋；代價是示範的長度、推理錯誤與接上行動空間的風險
01　想和做寫在同一條軌跡
推理要接地，
行動要有理由
thought 決定下一個行動，行動帶回的觀察再改寫 thought。CoT 少了編造事實的空間（幻覺 56% 對 0%），Act 也收得了尾（ALFWorld 45% 對 71%）。
✗ 只推理：靜態的黑盒子
✓ 交錯：為行動而推理，為推理而行動
02　內外知識互相當後援
有依據與有彈性，
用規則切換
ReAct 有依據但推理較僵，CoT 結構好但會編。用步數上限與多數答案的比例決定何時換邊；只抽 3 到 5 條，就追上 CoT-SC 抽 21 條。
✗ 只押一種方法
✓ HotpotQA 35.1、FEVER 64.6 都來自組合
03　thought 的內容是設計決策
寫什麼、寫多密，
直接改變成功率
只複述回饋的 thought 讓 ALFWorld 從 71% 掉到 53%，密集或稀疏也依任務而定。thought 寫在軌跡裡，人也能中途改一句，救回一局。
寫哪幾種、寫多密、要不要微調，
