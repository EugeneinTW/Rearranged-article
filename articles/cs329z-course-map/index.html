Prologue · 整理者的引言

一頁看完 15 個單元，再往下走

這一頁是三層裡最上面的一層。往下是 15 頁單元對照，再往下是 50 篇讀物頁；每一層都連到下一層，讀物頁的開頭也有一個灰框連回所屬的單元頁。

Chapter 07 · 主線五

多一個代理，好處與失敗都有人量過

這條主線問的是：一個 agent 夠不夠？AutoGen 在自己的應用裡加減一個角色量到好處，MAST 在別人的系統上數失敗，Neubig 談交接與維護的代價；單元 2 的兩篇各說了把工作分給子 agent 的理由。

單元 8 的四篇證據方向相反，但量的不是同一件事：AutoGen 在自己的應用裡加減一個角色來比，MAST 在別人的系統上數失敗，Neubig 談的是交接與維護的代價（單元 8 第 2 章）。把檢查交給另一個代理，四篇也都碰到：AutoGen 的幾個獨立檢查者都量到好處；Neubig 舉的 CodeR 例子裡，檢查者因為和其他代理分開而拿不到工具；MAST 發現有檢查者的系統失敗較少，但檢查常只做表面（單元 8 第 4 章）。

單元 2 的兩篇都有「一個主控、幾個工作者、最後合成」的形狀，理由不同。Agents 篇說的是注意力集中、子任務事先不知道；Context 篇說每個子 agent 有乾淨的 context window，主 agent 只收一份摘要。單元 8 的 Neubig 把同一種交接列為多代理的麻煩：只傳摘要，常常丟掉下游用得到的脈絡（單元 2 第 4 章）。

單元 6 是另一個角度：卡住時缺的常識，可以寫進同一個代理的 thought，也可以交給另一個代理。ReAct 論文把常識寫在示範的 thought 裡，拿掉就掉分；AutoGen 在 ReAct 式的兩代理系統上，加一個卡住時補常識的代理。兩邊的模型與試驗次數不同，數字不互比（單元 6 第 3 章）。

這條線上的判斷題

  • 單元 2：把探索交給子 agent、只收摘要，省下的比丟掉的多嗎？
  • 單元 6：卡住時缺的常識或檢查，該寫進 thought，還是另外加一個代理或一輪反思？
  • 單元 8：在你的任務上，多代理比單代理好，要看到什麼才算數？
  • 單元 8：檢查該交給另一個代理，還是留在同一個代理裡？
課程層級的問題 · 五

第二個 agent 要帶來什麼，才值得它的交接成本？

證據在：單元 8 的四篇最集中，單元 2 說了分工的理由，單元 6 比了常識放在哪裡。

還缺的證據：同一組任務、同一個模型、同樣的呼叫預算下，單一代理與多代理並排的結果；單元 8 的整理裡，只有 AutoGen 的 OptiGuide 做過一組。

做兩個版本：一個 agent 拿全部工具，另一個把檢查或探索分給第二個 agent；同樣的題目與呼叫上限各跑二三十題，除了成功率，也記交接時丟掉了哪些資訊。

Chapter 09 · 主線七

防線放在哪一層，三個單元各有安排

這條主線問的是：邊界守得住嗎？誰批准一次工具呼叫、規則寫在 prompt 還是 prompt 之外、什麼能寫進長期記憶，三個單元的讀物各把防線放在不同的地方。單元 12 的兩篇模擬研究，都在防守看起來穩了之後，再針對它找一輪攻擊。

單元 4 的 MCP 規格要人留在迴圈裡，主機在呼叫工具之前取得同意；工具在哪裡執行，讀法頁整理的規則沒有規定。其他單元的讀物各有做法：OpenHands 與 SWE-agent 每題開一個容器，OpenClaw 的沙箱預設關閉，Claude Code 文件把批准與沙箱放在同一節（單元 4 第 4 章）。

單元 12 先釐清攻擊者站在哪裡：PrivacyLens 的風險模型沒有攻擊者，兩篇模擬研究的對手是另一個 agent，OpenAI 說的第三方把指令藏在內容裡，Li 的論文裡用 agent 的人就是對手，RSP 同時管刻意的濫用與模型自主的行動（單元 12 第 2 章）。把隱私規則寫進 prompt，三篇模擬研究量到的結果不一樣：PrivacyLens 人寫的一段通用提示，沒有明顯減少洩漏；隱私風險搜尋的 D2 是對著一組攻擊搜出來的，對當時的攻擊洩漏 7.1%；CDI 論文訓練過的提示，再被攻擊一輪就鬆動。OpenAI 與 RSP 則把防線放到 prompt 以外（單元 12 第 3 章）。

再找一輪攻擊的結果，兩篇的數字方向相同。隱私風險搜尋請 LLM 直接寫的周全防守指令，對基本攻擊洩漏 1.4%，針對它搜一輪之後升到 46.3%；搜出來的 D2 再搜一輪，找不到超過 7.1% 的攻擊。CDI 論文訓練過的三種防禦再攻一輪，prompting 從 89.0 掉到 55.1、CDI 從 89.7 掉到 79.5（隱私保護率）（單元 12 第 4 章）。防守變嚴也有代價：D2 讓良性閒聊裡的有用動作只剩 31.2%，加一句提示回到 96.2%（單元 12 第 5 章）。攻擊只寫到類型，和單元 12 的寫法一樣。

單元 14 的關口在寫入長期記憶的那一刻：GUM 的稽核模組讓模型依情境完整性判斷一筆觀察該不該記；OpenClaw 的文件在寫入時標上來源，外來的內容在結構上升不進長期記憶；NAP 的防護放在研究的基礎設施上，另外替一般人列了三條退路（單元 14 第 4 章）。

這條線上的判斷題

  • 單元 4：工具呼叫要逐次批准，還是放進沙箱讓它跑？
  • 單元 12：隱私規則寫進 prompt，能當主要的防線嗎？
  • 單元 12：上線前的紅隊找不到問題，算不算夠？
  • 單元 12：防守變嚴之後少幫的忙，要怎麼量、補不補得回來？
  • 單元 14：使用者模型的門口，該交給模型判斷，還是交給不看內容的規則？
課程層級的問題 · 七

你的 agent 的防線，該放在哪一層？

證據在：單元 12 的四章最集中，單元 4 談批准與沙箱，單元 14 談寫進記憶之前的關口。

還缺的證據：同一套防守放在 prompt、放在程式、放在寫入的關口，各自面對同一組攻擊的並排結果。

替你的 agent 列一張表：每一種外來內容進來之後（網頁、信件、第三方工具的描述），會碰到哪幾道防線，哪一道是程式擋的、哪一道只寫在 prompt 裡。

一、只讀必讀：23 篇，照課程順序

單元 1 複合式 AI 系統 → 單元 2 Building Effective Agents → 單元 3 RAG → 單元 4 MCP 規格 → 單元 5 DSPy → 單元 6 ReAct → 單元 7 MemGPT → 單元 8 AutoGen → 單元 9 Snell 等、GEPA → 單元 10 資料飛輪、SWE-smith、EvalGen → 單元 11 ABC、Demystifying Evals、MT-bench、AutoMetrics → 單元 12 PrivacyLens、隱私風險搜尋、去匿名化 → 單元 13 SWE-agent、OpenHands → 單元 14 GUM。單元 15 沒有必讀。

二、照一條主線讀：以主線三「好壞誰來判」為例

  1. Si 等（單元 1）：一律跑實驗、拿成績當分數，判定者是執行結果。
  2. MT-bench（單元 11）：讓 LLM 當評審，量它和專家的一致度與偏誤。
  3. EvalGen（單元 10）：人挑評估器時，自己的標準會變。
  4. ABC（單元 11）：拿一份檢查清單，逐條查別人的基準哪裡判錯。
  5. SWE-bench（單元 13）與 OSWorld（單元 15）：測試與腳本當判定者，各自怎麼搭。
  6. AutoMetrics（單元 11）：從少量人評學出指標，再拿去當最佳化的目標。

三、自己動手建 agent harness 之前

  1. Building Effective Agents（單元 2）：工作流與 agent 的分法、由簡到繁。
  2. ReAct（單元 6）：thought、行動、觀察的迴圈，多數讀物搭 agent 的起點。
  3. MCP 規格（單元 4）：工具的定義、錯誤與批准的邊界。
  4. Effective Context Engineering（單元 2）：每一輪送進模型的 token 怎麼管。
  5. MemGPT（單元 7）：視窗放不下的東西搬到哪裡。
  6. SWE-agent（單元 13）：替模型設計的介面，以及換掉一個元件的代價。
  7. Effective Harnesses 與 Claude Code 文件（單元 13）：跨 session 的交接、驗收與權限。

四、評估一個 agent 之前

  1. Demystifying Evals（單元 11）：評估的名詞、三種 grader 與起步的步驟。
  2. Good LM Benchmarks（單元 11）：一次評估的四元組，題目怎麼出。
  3. ABC（單元 11）：基準本身會判錯的地方。
  4. MT-bench（單元 11）與 EvalGen（單元 10）：LLM 評審與人的標準各會偏在哪裡。
  5. SWE-bench（單元 13）與 OSWorld（單元 15）：兩個真實環境的考場怎麼搭。
  6. 隱私風險搜尋（單元 12）：固定的評估之外，再針對防守找一輪攻擊。

四條路線都只是一種排法。課程頁的順序是第一條；後三條照主題重排，同一篇可能出現在好幾條路線上。

Reference · 跨單元的用詞

同一個詞，在不同單元指的不一樣

只收出現在兩個以上單元、意思會跟著換的詞。每一條列各單元怎麼用，細節在各單元頁的「同一件事的名字」那一章。

agent
agent 指什麼
單元 1：Zaharia 等人把呼叫外部工具的 LLM agent 當成控制邏輯的一種選擇，Ng 指 Planning 裡自己決定步驟的 agent。單元 6：Anthropic 指依環境回饋自己決定流程與工具的系統，ReAct 用的是強化學習的意思（收到觀察、選一個行動），AutoGen 指能接上 LLM、人或工具的可對話代理。
workflow
工作流
單元 2：Agents 篇指路徑由程式預先寫好的系統，分五種。單元 6：Ng 的 agentic workflow 指讓模型多次處理、逐步改進，和一次寫完相對；同一個詞，範圍不同。
trace · trajectory
軌跡
單元 1：Zaharia 等人指追蹤應用走過的每一步，Si 等人把執行軌跡附進 prompt。單元 9：BetterTogether 指每個模組的輸入與輸出，GEPA 分執行軌跡與評估軌跡。單元 10：SWE-smith 指 agent 解一題的完整紀錄，平均 58 輪。單元 13：OpenHands 叫 event stream，Effective Harnesses 用 git log 加上進度檔。
demonstration
示範
單元 5、9：DSPy 與 MIPRO 的示範由最佳化器 bootstrap 出來，BetterTogether 每個模組最多挑 3 個，GEPA 不調示範，Snell 等人用固定的 4-shot。單元 6：ReAct 的示範是人寫的完整軌跡，每個任務 1 到 6 條；SWE-agent 拿掉示範是 16.3%。
reflection
反思、修訂
單元 1：Ng 的 Reflection 是生成、批評、重寫；Si 等人把失敗的紀錄交回模型重寫，最多兩次。單元 6：DyLAN 拿 Reflexion 當 WebShop 的對照。單元 9：GEPA 的反思 LM 讀軌跡改寫指令，Snell 等人的修訂模型看著前幾次的答案再寫一次。
baseline
基線、對照組
單元 1：Zaharia 等人比的是單次呼叫的模型，Ng 比 zero-shot。單元 6：ReAct 的 Standard、CoT、Act 都是刪減 ReAct 軌跡做出來的，後來 DyLAN、OpenHands、DSPy 又拿 ReAct 當對照組。單元 8：AutoGen 用單一代理的消融版本。
budget
預算
單元 1：Zaharia 等人指延遲與成本預算，Si 等人指固定的訓練時間與取樣預算。單元 2：Context 篇的注意力預算，每多一個 token 就用掉一些。單元 13：SWE-agent 每題上限 4 美元，OpenHands 估完整跑一次 SWE-bench 要 6.9k 美元。
grader · judge
評分者
單元 1：Si 等人讓執行器當獎勵函數。單元 10：資料飛輪的 LLM 判官，EvalGen 的評估器與斷言。單元 11：Anthropic 的 grader 分程式、模型、人三種，Press 叫 scorer，MT-bench 叫 judge，AutoMetrics 的 metric 可以是程式、模型或 LLM 評審。
sandbox
沙箱
單元 4、13：工具在哪裡執行，OpenHands 與 SWE-agent 用 Docker 容器，OpenClaw 預設關閉，Claude Code 文件指作業系統層的沙箱。單元 12：PrivacyLens 的沙箱是評估用的模擬環境，工具回傳由 GPT-4 模擬；RSP 管的是權重的圍堵。
human-in-the-loop
人在迴圈裡
單元 4：MCP 規格要人留在迴圈裡、由主機取得同意。單元 8：AutoGen 的 human_input_mode，指南建議開發新應用時先設成 ALWAYS。單元 12：OpenAI 的購買前確認與 Watch Mode；去匿名化那篇由作者人工核對候選，人在的是攻擊的流程裡。
context
脈絡
單元 2：Context 篇指取樣時放進模型的整組 token；Agents 篇的擴增型 LLM，是接上檢索、工具、記憶的模型。單元 4：MCP 讓伺服器只拿到必要的脈絡，看不到整段對話。
delegation
分工
單元 2：Agents 篇的平行化與協調者-工作者，Context 篇的子 agent 架構。單元 13：OpenHands 把瀏覽交給 BrowsingAgent，Claude Code 文件有 subagent，以及寫與審分開的兩個 session。
ACI · scaffold
模型外面那一層
單元 13：SWE-agent 提出 agent-computer interface，OpenHands 說 AgentSkills 的編輯工具改編自它；Effective Agents 也用 ACI，原文沒有連到 SWE-agent。單元 4：Effective Agents 說替 ACI 投入的心力，要和 HCI 一樣多。單元 6：講題說 scaffold 是設計決策，GEPA 把 ReAct 這類腳手架算進複合式系統。
observation
觀察
單元 6：ReAct 的 observation 接回 context，SWE-agent 預設只保留最近 5 個。單元 14：GUM 指截圖的轉寫、通知與使用者的回饋，NAP 叫 event。單元 15：WebShop 給模型 simple 模式的頁面，OSWorld 給截圖、無障礙樹，或兩者都給。
verification
檢查做對了沒
單元 8：AutoGen 的 Safeguard 與 grounding 代理、DyLAN 的 Ranker、MAST 的 verifier。單元 13：SWE-bench 的兩組測試、SWE-agent 的 linter 護欄、Effective Harnesses 的端對端測試、Claude Code 文件的對抗式審查。
heartbeat
心跳
單元 7：MemGPT 的函式帶上 request_heartbeat 之後，立刻再推論一輪。單元 14：OpenClaw 的 Gateway 預設每 30 分鐘在 main session 跑一輪 agent。同名不同物。
