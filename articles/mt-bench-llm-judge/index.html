Prologue · 整理者的引言

讓 LLM 當評審之前，先量它和人合不合

Stanford CS 329Z 第 8 週「LLM-as-Judge & Evaluation Infrastructure」那一講（Evaluation for Agentic Systems 分區），談三種 grader、judge prompt 怎麼設計、已知的偏誤、pairwise 對 pointwise、非確定性的指標（pass@k 對 pass^k）、harness 設計，以及 Anthropic 的八步路線圖。這篇論文是這一講的必讀，它把「讓 LLM 當評審」當成要檢驗的方法。

同一講的另兩篇必讀是 Anthropic 的〈Demystifying evals for AI agents〉與 AutoMetrics（Ryan 等人），選讀是 AutoLibra。這篇的年代比它們早，處理的對象也單純一些：聊天助手對一個問題的回答，還沒有 agent 的多步驟軌跡。它回答的是這一講最基本的兩個問題：用一個 LLM 替另一個 LLM 的回答打分，和人的判斷對得上嗎？會在哪些地方偏掉？

Chapter 01 · Introduction · Motivation

選擇題考不出，人偏好哪個助手

調過的聊天助手人明顯比較喜歡，MMLU、HELM 這類傳統基準卻分不太出它和原本的基底模型。人評分得出來，但又慢又貴；作者提議讓 GPT-4 這類強 LLM 代替人當評審，並先系統性地檢查這個做法。

作者說，基底 LLaMA 在傳統基準上表現有競爭力，開放式問題的回答卻常常不被人喜歡。第 5 節的表 8 有這兩個模型的數字：MMLU（5-shot）LLaMA-13B 47.0、Vicuna-13B 52.1；用 GPT-4 評的 MT-bench 分數，前者 2.61、後者 6.39（第 11 章）。論文因此把核心問題定成：需要一個穩健、可以擴大的自動方法，評估 LLM 和人的偏好對不對齊。

作者說，人的偏好是量聊天機器人在開放、多輪互動裡有多有用最直接的尺，現有基準卻大多沒有量它。所以他們建了兩個以人評為主要指標的基準（第 2 章）。問題是人評又慢又貴。第 3 節開頭說明兩條自動化的路為什麼走不通：MT-bench 與 Arena 的題目大多是開放式、沒有參考答案，很難寫規則程式來評；ROUGE、BLEU 這類拿輸出和參考答案比相似度的指標，對這些問題也不管用。

作者的做法是用 GPT-4 這類最強的 LLM 代替人。理由是這些模型多半經過 RLHF，本身已經和人的偏好高度對齊。他們把這個做法叫 LLM-as-a-judge；作者自己的 Vicuna 部落格與同期的其他工作已經這樣用過，但還沒有人系統性地研究它。這篇的兩個貢獻是：一份對 LLM-as-a-judge 的系統研究，以及來自 MT-bench 與 Arena 的人類偏好資料集。作者也主張未來的基準採混合評估：既有的能力基準，加上用 LLM 評審的偏好基準，同時看模型的核心能力和它與人的對齊。

整理者的讀法

評審寫得出理由，不等於每一句都查過

圖 1 裡 Vicuna 的第一個例子說，聯準會買債、推高債券需求時，房貸、車貸、信用卡的利率可能上升。照一般對貨幣政策的說法，央行買進債券通常會壓低利率，方向和這句相反。GPT-4 的評語仍然說 B 切題而且正確。論文沒有討論這一點，它用這張圖示範的是兩個助手的差距與評審會寫理由；這一段是整理者的讀法。

第 3.4 節給了兩個處理位置偏誤的做法。第一個是交換位置。保守的做法是呼叫評審兩次、對調兩個回答的順序，兩個順序都偏好同一個回答才算它贏；兩次結果不一致，就記為平手。比較積極的做法是隨機指派位置，大規模評分時，期望值是對的。之後所有實驗都用保守的做法：

1
對調順序各判一次先把 A 放前面判一次，再把 B 放前面判一次。
2
兩次都贏才算贏兩個順序都偏好同一個回答，它才算勝出。
3
不一致就記平手兩次判定相反，這一題算平手；第 8 章的 S1 算法就把這種票當成平手。

第二個是 few-shot 評審：在 prompt 裡放三個好的判斷範例，分別是 A 較好、B 較好、平手；範例的題目是 MT-bench 風格的問題，回答由 GPT-3.5 與 Vicuna 產生，判斷由 GPT-4 產生。表 12 顯示三個評審的一致率都明顯上升：GPT-4 從 65.0% 到 77.5%，Claude-v1 從 23.8% 到 63.7%，GPT-3.5 從 46.2% 到 55.0%。附錄 D.2 補充：GPT-4 的位置偏誤幾乎消失（偏前 10.0%、偏後 12.5%），GPT-3.5 的偏誤卻從第一個位置移到第二個（偏前 16.2%、偏後 28.7%）。

一致程度的定義是：兩類評審各隨機挑一位（不能是同一位），在隨機挑的一題上投出相同票的機率。比 GPT-4 和 Claude，就是兩者在隨機一題投票相同的機率；比 GPT-4 和人，是 GPT-4 和隨機一位人在隨機一題相同的機率；人和人之間，則是隨機挑兩位不同的人，在隨機一題相同的機率。另一個指標是平均勝率：一個模型對其他所有參賽者勝率的平均。兩個指標都可以選擇含或不含平手票。

表格裡的一致程度有兩種算法。S1 包含非平手、平手，以及因為位置偏誤而前後不一致的票，不一致的票算成平手；每票有三種結果，兩個亂猜的評審一致的機率是 33%。S2 只算非平手票，只有兩種結果，亂猜是 50%。表 5、表 6 每一格上面是一致程度，下面是票數。

附錄 D.3 用一個例子說明，人和人的一致程度為什麼可能比 GPT-4 對人還低。一題有三個人投票，分別投 A、A、B。三個人兩兩配對有三對：(A, A)、(A, B)、(A, B)，只有一對相同，所以人和人的一致程度只有 1/3。GPT-4 若投 A，它和三個人各配一對，有兩對相同，一致程度是 2/3；投 B 則是 1/3。

為了看得更完整，作者加了一種評審：人的多數決（human-majority），也就是每一題取人的多數票。GPT-4 對多數決的一致程度，就是 GPT-4 和當題多數票相同的機率；沒有多數時各算一半，例如 A、B 票數一樣、GPT-4 投 A，這一題就算 1/2。作者說，GPT-4 對人的一致程度，上限就是多數決對人的一致程度。

給初學者

一致程度要和亂猜比

一致程度本身沒有絕對的好壞，要看同樣的算法下，兩個亂猜的評審能有多少：S1 有三種結果，亂猜是 33%；S2 只有兩種，亂猜是 50%。同一個 85%，放在 S2 裡是比亂猜高 35 個百分點（整理者算的）。比較兩個數字之前，先確認它們是不是同一種算法。

思考題 · 02

你的 LLM 評審，和你的團隊比起來一致嗎？

假設你要把產品的評分交給一個 LLM 評審，手上有兩三位同事可以幫忙評一小批。

照第 8、9 章的做法：同一批題目讓幾位同事和 LLM 評審都評，分別算人對人、LLM 對人的一致程度，含平手與不含平手各算一次。LLM 對人追得上人對人，才考慮把大部分評分交給它。這是整理者依原文整理的建議。

作者的讀法有兩點。第一，在高品質的對話資料（ShareGPT）上微調，能穩定提升 MMLU，而且隨微調資料量增加：Vicuna-7B 從 selected 的 37.3、single 的 44.1 到 all 的 47.1。第二，少量的高品質對話能很快教會模型 GPT-4（大致也就是人）偏好的風格，卻不會明顯提高 MMLU：selected 只用了 4.8M token、3K 段對話，MT-bench 就有 5.95 分，MMLU 只有 37.3。從表 8 看，沒有單一基準能決定模型的品質，所以需要全面的評估。

作者由此認為，用 LLM 評審近似人的偏好高度可行，可能成為未來基準的新標準；他們也維護一個定期更新、收錄更多模型的排行榜。作者另外提到 DynaBench：一個動態收集資料、讓人參與其中的研究平台，說它和自己的精神一致。它處理的是靜態標準化基準會飽和、會被過度擬合的問題，LLM 評審可以把這類平台自動化、做大。

整理者的讀法

放回這一講：評審本身也要被評估

這一講談評估的基礎建設，這篇可以帶走三件事。第一，先決定用成對比較還是單一答案評分，並知道各自的代價。第二，把偏誤當成要量的東西，用對調順序、重複清單、參考答案這類小測試量出來。第三，拿一小批人評對一次，和人與人之間的一致程度比。論文沒有處理 agent 的多步驟軌跡，也沒有談 pass@k 這類非確定性的指標，這些由同一講的其他讀物處理。這一段是整理者的連結。

GPT-4 當評審，可以完全取代人評嗎？
作者沒有這樣說。他們的結論是 GPT-4 和人的一致程度超過 80%，和專家之間相當，是可擴充的近似方法；同時列出位置偏誤、冗長偏誤、數學題評不準等限制，解法也還是初步的（第 3.3、3.4、6 節）。
成對比較和單一答案評分該用哪一種？
成對比較在模型多時，配對數會平方成長；單一答案評分可能分不出細微差距，換評審模型時分數也比較不穩。作者在 MT-bench 的分數上用 GPT-4 單一答案評分，因為它和成對比較、和人都很一致，又比較容易擴充（第 3.1、4.2、5 節）。
為什麼人和人的一致程度只有八成？
一致程度是隨機兩位評審投相同票的機率，人本來就不會全部同意；附錄 D.3 的例子裡，三個人投 A、A、B，人對人只有 1/3。作者因此加了人的多數決，當作 GPT-4 對人的上限（附錄 D.3）。
思考題 · 03

你會先替哪一種偏誤設計小測試？

回想你手上的 LLM 評審：它評的是長文、短答、程式，還是數學題？

長文容易被長度騙，可以仿第 5 章做一個只加長度的版本；比兩個相近的系統時，先照第 4 章對調順序；題目有標準答案時，照第 6 章先另外解好、當參考答案。先挑離你的任務最近的那一種。這是整理者依原文整理的建議。

Reference · 名詞速查

關鍵名詞，與它們在論文裡的位置

先列評審的做法與兩個基準，再列偏誤與緩解，最後是一致程度與延伸實驗用到的名詞。

LLM-as-a-judge
LLM 評審
讓強的 LLM 讀問題與回答，判斷好壞或打分數，用來近似人的偏好（第 3 節）。
MT-bench
多輪問題基準
80 題人工設計的兩輪問題，分寫作、角色扮演、擷取、推理、數學、程式、STEM、人文 8 類（第 2.2 節）。
Chatbot Arena
群眾對戰平台
使用者同時問兩個匿名模型、投票選較好的，投完才揭曉身分；一個月約 30K 票（第 2.3 節）。
pairwise comparison
成對比較
給評審一個問題與兩個回答，選較好的或判平手；模型多時配對數平方成長（第 3.1 節）。
single answer grading
單一答案評分
只給一個回答，評審直接打 1 到 10 分；較好擴充，但可能分不出細微差距（第 3.1 節）。
reference-guided grading
參考答案引導
評審的 prompt 附上參考答案；數學題先讓評審另外作答，再當參考答案放進去（第 3.4 節）。
position bias
位置偏誤
評審偏好某個位置的回答，多半是第一個；對調順序後判定會變（第 3.3 節、表 2）。
name bias
名字偏誤
Claude-v1 在改名的 prompt 下偏好「Assistant A」這個名字，而不是位置（表 2 的 rename）。
consistency
一致率
位置偏誤測試裡，對調兩個回答後判定維持不變的比例；不代表判得對（表 2）。
verbosity bias
冗長偏誤
評審偏好較長、較囉嗦的回答，即使它沒有比較清楚或正確（第 3.3 節）。
repetitive list attack
重複清單攻擊
把回答裡的清單改寫後接在前面，只加長度不加資訊；評審選了長版就算失敗（表 3）。
self-enhancement bias
自我偏好
評審偏好自己產生的回答；作者從勝率看到跡象，但資料太少、無法判定（第 3.3 節）。
chain-of-thought judge
CoT 評審
在評分 prompt 裡要評審先獨立解題再評分；仍常照抄回答裡的錯（第 3.4 節、圖 15）。
few-shot judge
few-shot 評審
prompt 裡放三個判斷範例；GPT-4 的一致率從 65.0% 升到 77.5%，但 API 貴 4 倍（表 12）。
swapping positions
交換位置
對調順序各判一次，兩次都贏才算贏，不一致算平手；論文實驗都用這個保守做法（第 3.4 節）。
multi-turn judge
多輪評審
把兩個助手各自的完整兩輪對話放進同一個 prompt；拆成兩個 prompt 會對錯回答（第 3.5 節）。
agreement
一致程度
兩類評審各隨機挑一位，在隨機一題上投出相同票的機率（第 4.1 節、附錄 D.3）。
S1、S2
兩種算法
S1 含平手與前後不一致的票，亂猜 33%；S2 只算非平手票，亂猜 50%（表 5）。
human-majority
人的多數決
每題取人的多數票；多數決對人的一致程度，是 GPT-4 對人的上限（附錄 D.3）。
