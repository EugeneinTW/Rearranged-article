AUTOLIBRA · METRIC INDUCTION · 圖卡＋教材整合版

從人的一句回饋， 長出評估 agent 的指標AutoLibra：把回饋對到行為、 分群成有定義與正反例的指標， 再用覆蓋率與冗餘率檢查

評估 agent 最常看任務有沒有完成，一條很長的軌跡只換來一個分數。這篇以 Stanford 為主的團隊寫的論文，改從人的開放式回饋出發：AutoLibra 把人對執行軌跡的一句評語對到具體的行為，再把相近的行為分群成有定義、有好壞例子的指標，交給 LLM 評審打分；覆蓋率與冗餘率兩個後設指標，則回頭檢查這組指標漏了什麼、多了什麼。作者在協作、社交、網頁與文字遊戲的 agent 上試，也拿歸納出的指標當目標改進 agent。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

評估指標，可以從回饋裡歸納

Stanford CS 329Z 第 8 週「LLM-as-Judge & Evaluation Infrastructure」那一講（Evaluation for Agentic Systems 分區），談怎麼用模型當評分者、評分者有哪些偏誤、評估的基礎設施怎麼搭。這篇 2025 年的論文是同一講的選讀，它處理評分之前的一個問題：評估 agent 的指標從哪裡來。

這一講的講題有七個：三種 grader、judge prompt 怎麼設計、已知的偏誤、pairwise 對 pointwise、非確定性的指標（pass@k 對 pass^k）、harness 設計，以及 Anthropic 的八步路線圖。同一講的必讀是 Anthropic〈Demystifying evals for AI agents〉、MT-Bench 論文（Zheng 等）與 AutoMetrics（Ryan 等）。AutoLibra 的回答是：先收人對 agent 執行軌跡的開放式評語，從裡面歸納出指標，再把指標交給 LLM 評審打分。

兩件整理者對照出來的事。對照參考文獻：論文第 2.3 節說明 LLM 評審時引用的 Zheng 等 2023，就是同一講必讀的 MT-Bench 論文。對照作者名單：最後一位作者 Diyi Yang 是這門課的講師。

摘要先點出現況的三個問題：agent 主要靠任務成功率來評估與最佳化，這種指標很粗、要靠專家手工設計，也不會獎勵過程中自己冒出來的中間行為。引言從人怎麼學技能講起：人從別人的開放式指示與回饋學習，並把回饋內化，變成自我調節學習時持續改進的訊號（作者引發展心理學與教育研究）。作者想知道，AI agent 能不能用同樣的方式，從人的回饋裡歸納出可以推廣的指標，並從中受益。

AutoLibra 是一個歸納指標的方法，作者也把它定位成一套新的評估框架。回饋可以來自 agent 的終端使用者，也可以來自專家。作者說這樣做有兩個好處，第一個是：

"It is much easier to provide concrete feedback for trajectories than creating metrics" 「對軌跡給具體的回饋，比設計指標容易得多」：第 1 節列的第一個好處。

第二個好處是可以從使用者的角度評估 agent。歸納出來的指標寫清楚了用模型評估時要找哪些行為，可以拿來理解 agent 在做什麼，也可以當成改進 agent 的最佳化目標。

歸納分成兩步，參考社會科學裡主題分析的「編碼、歸納主題」兩個步驟。第一步是回饋落地：把回饋的每個面向，對到整條軌跡裡的某一段行為。第二步是行為分群：把這些面向聚成幾群相似的行為，每一群整理成一個指標。圖 1 的例子是網頁 agent：使用者說它沒有選 iPhone 14 或 15，這句話被對到它在下拉選單選了 iPhone 16 Pro 的那一步；和它相似的行為聚成一群，整理成 Element Interaction Accuracy（介面元素操作的準確度）這個指標（第 3 章）。

評估的那一段，負責替歸納提供閉環的回饋訊號。歸納時用過的軌跡，交給 LLM 評審依歸納出的指標打分，得到一組特徵；再把人的回饋拆出的面向（例如「食譜裡沒有藜麥」）和特徵（例如 task-requirement-achievement）配對，就能反過來評估這組指標：覆蓋率是面向裡配得到特徵的比例，冗餘率是偵測到的特徵裡沒有人提到的比例（第 4 章）。有了這兩個數，就能去找冗餘率最低、覆蓋率最高的一組指標。作者發現指標越多，冗餘率越高，覆蓋率則收斂到最大值（第 5 章）。

第 2 節開頭把設計要求寫成三條：指標要從 agent 的行為歸納，扎根在軌跡上，不由專家預先定義；要能自我驗證，挑出能涵蓋沒看過的回饋、又夠抽象可以跨任務使用的最小一組指標；要能推廣，適用各種 agent 環境，不綁特定領域的設計。整個系統是一條閉環：從人收來的回饋（第 2 章）進入歸納流程，產出指標（第 3 章）；評估流程再用這些指標替新的 agent 行為打分、並評估指標本身的品質（第 4 章）。

回饋落地。標註者的一句回饋常常包含好幾個面向。論文舉 CoGym 的一句使用者留言：agent 很會排出前後一致的行程與度假計畫，只是最後幾分鐘當掉了。這句話裡有一個正面的面向（行程前後一致），也有一個負面的面向（最後當掉）。作者把面向定義成三元組：行為、回饋、正負號。以正面那個為例，行為是 agent 替馬爾地夫排出 20 天行程的那些動作，回饋是這份行程前後一致，正負號是正。作者說這一步和主題分析裡的編碼很像。

做法是把軌跡和回饋一起交給 GPT-4o（作者說它在前導實驗裡表現好），指示它先把回饋拆成條列，再替每一條找出回饋指的那一段軌跡，最後用限制解碼逼它照三元組的格式輸出。實驗裡多數資料集，每條軌跡能產生 1 到 5 個面向，平均 1 到 2 個。

行為分群。第二步把面向分成 N 群，每一群就是一個指標。論文用同一個資料集的另一句留言說明：AI 很快就寫好並執行了 Python 腳本。這個面向是正面的，但它和前面「最後當掉」反映的是同一個行為維度，只是方向相反，所以會落進同一個指標。每個指標有三個部分：一段定義，寫出什麼樣的行為算好；一組好行為的例子；一組壞行為的例子。作者說這一步和主題分析裡歸納主題的那一步很像。

把相似的 agent 行為聚在一起，對統計式的分群方法很難。作者在註腳說，他們在前期實驗試過把面向用 text-embedding-3-large 轉成向量再做 K-means，分出來的群大多依任務分，而不是依行為分。他們改學 LLM 做語意分群與概念歸納的研究（作者引 LLooM 等），直接請 LLM 分群；用的是 o3-mini high，因為它在後面的評估裡得到最準的覆蓋率與冗餘率。M 條軌跡的所有面向一起分成 N 個指標，N 是第 5 章要調的參數。給分群模型的指示大意是：分群的粒度要盡量小，只有非常相似的行為才放在一起；但不要只限於某一個網站或某一個角色。作者說這樣做出來的指標比較具體，又還能跨任務使用。

圖 1 的上半是一個完整的例子（第 04 卡）。兩條 WebVoyager 軌跡各有一句回饋：一條要比較 iPhone 14 Pro 與 15 Pro，回饋說 agent 沒用下拉選單選到 14 或 15；另一條要搜尋登山用品並依價格排序，回饋說搜尋做對了、但沒有依價格排序。第二句回饋拆成一正一負兩個面向。兩個「沒用對介面元素」的負面向，都成了 Element Interaction Accuracy 的壞行為例子；「搜尋字詞用對了」成了 Query and Search Strategy（查詢與搜尋策略）的好行為例子，另一條軌跡的「這種查詢不被支援」則成了它的壞行為例子。

用歸納出的指標評估 agent。LLM 評審（LLM-as-a-Judge），更廣地說是用模型評估，就是讓一個機器學習模型評估另一個模型的輸出。作者說它行不行，要看評估（或驗證）比生成、比行動容易多少；agent 任務裡這個差距通常很大：做事的模型要一步步做很多決策，評估的模型只要替軌跡分類，所以 agent 的基準常用它（作者引 WebArena、WebVoyager、Sotopia）。AutoLibra 把歸納出的指標放進評審的設定裡，替軌跡打分。

評審的做法（圖 8）：輸入歸納出的指標，LLM 替每條軌跡在每個指標上打 +1、−1 或 N/A，用的是 o3-mini medium，作者說它在這一步和 o3-mini high 的結果差不多。打 +1 的指標是這條軌跡的正特徵，打 −1 的是負特徵。算一個指標的分數時，用打正的軌跡數除以打正與打負的軌跡數，打 N/A 的不算，因為不是每個指標都適用每條軌跡；例如 valid-search-terms 只有任務需要搜尋時才適用。

後設評估。這是閉環的最後一段，評估的對象是 AutoLibra 歸納出的指標本身。它把評審偵測到的特徵，和人的回饋落地出的面向配對，要確認兩件事：歸納出的指標有沒有涵蓋標註者在意的行為，以及評審用這些指標能不能評得準。以第 3 章的例子說，如果 respond-promptly 被歸納成一個指標，評審的看法也和標註者一樣，這個面向就算成功涵蓋；如果沒有歸納出相近的指標，或評審給了不同的分數，就算沒涵蓋。

配對的做法（圖 9）：每一對軌跡與回饋，先把面向分成正負兩組，特徵也依打分分成正負兩組，正面向只和正特徵配，負面向只和負特徵配。作者把面向清單和特徵清單交給 GPT-4o，請它替每個面向找出最配的特徵，或判定沒有。整個資料集的覆蓋率，是所有例子的面向裡配得到特徵的比例；冗餘率是所有例子的特徵裡沒和任何面向配上的比例。

覆蓋率同時量兩件事：有沒有歸納出相近的指標，以及評審的判斷和人一不一致。任一件沒做到，這個面向就算沒涵蓋；所以覆蓋率低時，要分開看是指標缺了，還是評審判錯了，第 6 章的人工抽查就是單獨查評審這一步。冗餘率高，則不代表那些特徵判錯了：人每條軌跡只寫一句話，沒提到的行為不一定不存在。作者在選指標時壓低冗餘率，目的是讓指標組精簡、彼此少重疊（第 5 章）。這一段是整理者的讀法，論文沒有這樣拆。

思考題 · 01

你的評估清單裡，有幾條是使用者真的說過的？

找 20 則最近的使用者評語或客訴，每則拆成一到兩個「行為＋評價」的面向，再對到你現有的評估清單。

對不上任何一條的面向，是清單漏掉的東西，相當於覆蓋率的缺口；清單裡從來沒有人提過的項目，則是冗餘率的來源，值得問一句還要不要留。這個練習是整理者依第 2.3 節的兩個定義設計的，論文沒有提供門檻或建議值。

第 3 節開頭說，AutoLibra 設計成能透過評估流程自我驗證，所以可以去搜尋最能涵蓋人的意見的一組指標。這個最佳化也能在改進 agent 的過程中反覆做：agent 被改好之後，可以在既有的指標上再加新的；作者把它比作軟體開發時一直保留單元測試，避免新功能弄壞既有的功能。

第 3.1 節的目標是最大化覆蓋率、最小化冗餘率，兩者之中先顧覆蓋率：先讓評估完整涵蓋 agent 的行為，再減少指標之間的重疊，讓歸納出的指標最有用。做法是產生 20 組不同的指標，指標數 N 從 4 到 13，在人的回饋上算每一組的覆蓋率與冗餘率；留下覆蓋率至少是最高覆蓋率減 1% 的那幾組，再從中選冗餘率最低的一組。接著把 N 的範圍重設成選中的 N 加減 2，再做一次，直到選中那組的覆蓋率與冗餘率收斂，通常 3 輪以內。作者說這個方法很簡單，但他們試過遺傳演算法與迭代分群等其他最佳化策略，沒有一個比它好。

結果畫在圖 3。各種指標數的最高覆蓋率，在 N 等於 6 到 10 附近收斂，看資料集而定。Sotopia 的最佳覆蓋率是四個資料集裡最低的 60%，作者認為可能是任務太多樣；WebArena 與 WebVoyager 最高，都是 88%。保留下來沒用來歸納的軌跡，覆蓋率只比歸納用的軌跡差一點（不到 5%），作者說這在預期之內，因為指標裡的例子就是從歸納用的軌跡抽出來的。最後一個發現是好行為與壞行為的例子對指標很關鍵：把它們拿掉，CoGym 的覆蓋率最多掉 30%。

迭代歸納。第 3.2 節處理改進 agent 的情境：agent 變好之後會出現新的失敗模式或新的行為，所以可以一輪一輪歸納新的指標，這也方便追蹤 agent 在不同輪次的進展。做法是改行為分群那一步：把既有的指標與定義交給 LLM，要求它不改既有指標的定義，只把新的行為加進既有的指標，必要時才加新指標；然後用同樣的最佳化策略，確保新指標涵蓋新冒出來的行為，又不和既有的指標重疊。作者在註腳說，每一輪從頭重新歸納一組指標，實際上也不會損失覆蓋率，他們為了前後一致選了前一種。第 8 章的實驗用的就是這個做法。

思考題 · 02

你的評估指標該有幾個，又該多久加一次？

想一個你正在迭代的 agent：現在的評估項目有幾個，最近一次新增是因為什麼？

可以借第 3.1 節的順序：先確認現有項目能涵蓋最近收到的回饋，再刪掉彼此重疊、或從來沒人提到的項目；新版本上線後，只新增、不改舊項目的定義，分數才能跨版本比較。這些步驟是整理者依第 3.1、3.2 節整理的建議。

正文說 AutoLibra 另外歸納出四個 Sotopia-Eval 忽略的指標；表 2 在「沒對上的 AutoLibra 指標」一欄列出三個：Negotiation Tactics and Strategic Adaptability（談判策略與策略調整，14%）、Responsiveness and Conversational Termination（回應與結束對話，5%）、Adaptability and Flexibility in Dialogue（對話的適應與彈性，7%）。四與三兩個數字照錄。作者也說 Sotopia 另外五個維度仍是評估社交智能的重要維度：Financial and Material Benefits、Knowledge、Secret 捕捉到的行為，常常也被 Goal Completion 與 Believability 捕捉到，所以 AutoLibra 在壓低冗餘率時只留下單一的目標達成指標；Relationship 與 Social Rules 捕捉的是長尾的行為，AutoLibra 沒有抓到。

WebVoyager。網頁導航任務也一樣。AutoLibra 歸納出 Access Barrier Handling（處理阻擋，2%）、Error Recovery & Adjustment（錯誤恢復與調整，15%）、Step Efficiency & Action Redundancy（步驟效率與多餘動作，13%）、Navigation Accuracy（導航準確，11%）這類指標；作者說它們比先前研究的失敗分析類別更貼近 agent 的具體行為，那些研究常把這些情況一律歸成「卡住」（Navigation Stuck，44%）。另兩組對應是 Hallucination（幻覺，22%）對上 Information & Verification Accuracy（資訊與查證的準確，16%），Prompt Misalignment（和指示不符，9%）對上 Result Relevance Accuracy（結果的相關程度，9%）。AutoLibra 也找到失敗分析沒提的指標：Query and Search Strategy Efficiency（查詢與搜尋策略，7%）與 Final Output and Summarization Quality（最後輸出與摘要，18%），作者說它們都是常見的問題。反過來，AutoLibra 只觀察 agent 的行為，沒辦法解讀模型內部的表徵，所以抓不到 WebVoyager 論文提到的視覺定位問題（Visual Grounding Issue，25%）。

作者用這一節說明 AutoLibra 擅長抽出貼著行為的指標，特別是專家設計時抽不出來的細緻指標。

關鍵觀念 · 一

同樣是「卡住」，要修的地方不一樣

「卡住」是從結果回頭貼的標籤：任務沒做完，agent 停在某處。拆出來的四個指標說的是停住之前發生了什麼：出錯後沒有恢復、走了多餘的步驟、導航走錯地方、碰到阻擋不會處理。四種情況各有不同的改法，只看「卡住 44%」，不知道該先改哪一個。

這一段是整理者的讀法。論文只說這些指標更貼近具體行為，沒有比較四種各該怎麼修。

給初學者

Baba-Is-AI 的規則怎麼運作（附錄 D）

地圖是方格，上面有物件、規則方塊與障礙。規則由文字方塊排成「主詞、動詞、受詞」三格一列，橫排或直排連成三格才生效，例如 wall is stop；動詞有 is、has、can、not 四種。agent 只能上下左右移動一格去推方塊，也不會被告知這一步有沒有真的移動。把「baba is you」弄斷、又沒控制新的物件，任務會自動重置到隨機的起點。每回合上限 100 步，避免亂走碰巧解出。共有 40 個由易到難的任務，由 Goto-Win、Make-Win、Break-Stop、Change-You 四種子任務組合而成。

這個實驗從頭到尾用 Gemini 2.5 Flash，同時當 agent、AutoLibra 裡的 LLM，以及改 prompt 的模型。作者說投稿時它在 BALROG 的 Baba-is-AI 排行榜上排第 3，成功率 50.8% ± 4.6%，最好的結果是 56.7% ± 4.5%；選它是在成本與表現之間取捨。

改進分三個階段，只對 Baba-Is-AI 40 個任務裡的 6 個提供人的回饋；這樣才能看給訓練任務的回饋，能不能推廣到沒看過的任務。每個階段開始前，人看這 6 個任務各 3 條軌跡、寫回饋，再套用第 5 章的迭代歸納。正文說第 1、2 階段得到 5 個指標，第 3 階段再加 1 個；圖 4 的標註是先歸納 5 個、再歸納 5 個、再歸納 1 個。每個階段之內，反覆把這 6 個任務各一條 agent 軌跡，連同依這些指標的評分，交給 LLM 改進 agent 的 prompt。

圖 4 畫的是全部 40 個任務的統計，雖然整個最佳化只用了其中 6 個。作者說，指標的執行中最高分、指標的累積平均，以及遊戲的成功率都持續改善。檢視軌跡，可以看出 agent 學到的技能：第 1 階段，agent 學會依地圖的邊界決定要組哪些規則，作者認為這可能來自歸納出的指標 map-n-constraint-recognition；第 2、3 階段學到更進階的技能，包括組出勝利條件與自我指涉的規則，作者認為可能來自 rule-manipulation-proficiency 這個指標。圖 4 的圖說補了一句：成功率一路改善到第 3 階段，之後 agent 開始想太多。

作者的結論是，AutoLibra 歸納的指標是透過 prompt 最佳化改進 agent 的有效目標；在沒有對成功率最佳化的情況下，成功率提高了 20%（引言寫超過 20%）。他們強調 AutoLibra 是歸納指標的方法，和學習演算法互相獨立，prompt 最佳化、微調或強化學習都能搭配；換成其他學習演算法的效果，留給未來研究。

思考題 · 03

你寫給 agent 的指示，有哪幾句只在某個任務成立？

翻出你的 system prompt 或 skill 說明，把每一句指示標成「通用原則」或「某個任務的特例」。

像「只往東走」這種句子，在訓練用的任務上很有效，換一個任務就出錯。附錄 O.2 的做法是拿保留的任務檢查改動能不能推廣；你也可以替每個特例寫一個它會失效的反例任務。這個練習是整理者依附錄 O.2 設計的。

主題分析的方法，搬來評估 agent

作者說 AutoLibra 接起三條研究線：它借主題分析的方法，做出從自然語言來的評估指標，用來評估與獎勵 AI agent。和各線相比，它不預設失敗分類，歸納出的指標也能跨任務用。

評估 AI agent。這方面的研究多半圍繞基準，基準同時包含任務集與評估指標。除了這篇用到的資料集，作者舉了幾個例子：SWE-Bench 用人寫的單元測試當評估指標；Embodied Agent Interface 替以 LLM 為基礎的具身 agent 提供細緻的評估；τ-Bench 比對資料庫的狀態來評估；同時期的 AgentRewardBench 替網頁 agent 的獎勵模型建立基準。最近也有 Galileo、Vertex AI Gen AI、Docent 這類觀測工具，提供把 agent 失敗模式視覺化的介面。強化學習社群也研究過產生內在獎勵，鼓勵探索、完成子任務或發現技能。作者說相比之下，AutoLibra 是純資料驅動、不限任務的方法，不需要預先定義失敗分類，就能產生可解釋的指標。

從自然語言與人的回饋學習。已有研究用語言回饋替 agent 提供密集獎勵，做強化學習（作者引 Goyal 等 2019）。LLM agent 在稀疏獎勵下更難訓練，所以從自然語言回饋訓練 agent 很受關注：Chen 等 2024 提出從人的回饋模仿學習的方法；Text2Reward 用程式生成，從開放式回饋產生機器人的獎勵函式；作者自己的另一篇研究（Chen 等 2025）先用回饋透過提示改進策略，再讓沒有提示的策略向有提示的看齊；Shi 等 2024 提出把人的回饋納入策略學習的新模型架構。非開放式的回饋也用在訓練 agent 上，包括評分、偏好與示範。作者說和這些研究不同，AutoLibra 從所有標註過的例子歸納指標，產生能推廣到不同任務的指標，可以用在評估，也可以用在微調 agent。

主題分析。它是質性研究的工具，靠編碼與反覆歸納主題進行。已有研究提供輔助這個過程的計算工具，也有研究探索人與 AI 協作做主題分析；自動做概念歸納的 LLooM 和 AutoLibra 的做法最接近，也影響了它。作者說這篇把概念歸納的迴圈補完：用後設評估回頭最佳化歸納出的指標，再用在評估 agent 上。

1
以行為為中心的評估從端到端評估（像軟體開發的整合測試）轉向量具體行為的細指標（像單元測試）；未來可以研究更好的人與 AI 協作能不能改進這個流程。
2
子軌跡層級的回饋現在一條軌跡一句回饋，再落地到子軌跡的行為；未來可以讓使用者直接對一步或幾步給回饋，落地應該更準；也可以在互動當中收回饋，不必等任務做完，對使用者更友善。
3
更多改進 agent 的方法這篇只試了非參數的改進方法；未來可以用 AutoLibra 替每一步提供密集獎勵，再用強化學習訓練 agent。

第 8 節是作者的大圖像。人不只從自己的經驗學，更從社會互動傳下來的集體知識學；這種社會學習與教學的能力讓知識跨世代累積，讓人能在既有的技能與工具上往上蓋，而不必每次重新發明。作者問：怎麼利用這種社會智能，讓 AI agent 用類似的方式向人學習，甚至教人？

作者指出，目前訓練語言 agent 主要靠行為複製，或從自己產生的經驗做強化學習；行為複製在學技能上有先天的限制。第一，示範者要和學習的 agent 在同一個環境裡操作，知識傳遞的規模被綁住。第二，只從一兩次示範學的 agent，可能誤解什麼才是恰當的行為；這時老師明確的口頭回饋，對劃出可接受行為的邊界、講清楚示範裡看不出的原則，就很重要。

AutoLibra 提供的是一個計算上的做法：把人在日常互動裡自然交換的口頭回饋，拿來有系統地改進 agent 的行為。作者的願景是把 AI agent 部署到真實環境，從大規模、多樣的人類回饋裡學習，從所有使用者的集體經驗學到技能，在個人與組織的層級，同時形成一般的能力與專門的技能組，就像人類社群累積與分享知識的方式。再往前一步，這樣的 agent 可以當人與人之間傳遞技能與文化的中介：把熟練使用者的專業，提煉成可解釋的指標與可執行的回饋，用來引導新手，縮短學習曲線。
