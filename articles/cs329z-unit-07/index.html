CS 329Z UNIT 7 · 單元對照

記憶由誰管，存成什麼MemGPT、Generative Agents、Mem0 與 Letta 在三個問題上的證據

CS 329Z 第 4 週「Agent Memory Architectures」那一講配了四篇讀物：MemGPT 讓模型用函式呼叫管理多層記憶；Generative Agents 讓 25 個代理帶著記憶流、反思與計畫在小鎮裡過兩天；Mem0 每收到一對訊息就抽出事實、比對舊記憶後寫回；Letta 的部落格說記憶就是決定哪些 token 在視窗裡。這一頁把四篇並排，整理它們在三個問題上各拿出什麼證據、原文之間怎麼互相引用、同一件事各叫什麼名字；判斷題不附答案。每章開頭先放一張圖解卡講重點，往下是詳細說明；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

四篇讀物，都在管視窗放不下的東西

MemGPT 與 Mem0 各提出一套記憶系統並量了效果，Generative Agents 讓記憶架構在小鎮裡跑了兩天、請人評可信度，Letta 的部落格整理概念、沒有附數字。這一頁不重述四篇，而是把它們放在一起讀：哪裡各說各話、哪裡互相引用、證據各在什麼條件下量出來。

CS 329Z 第 4 週星期三的「Agent Memory Architectures」屬於「Memory & Multi-Agent Systems」分區。課程頁列的講題有五個：短期與長期記憶、把記憶當成工具動作、用檔案系統當外部記憶、結構化記憶，以及跨 agent 的記憶。這一講配了一篇必讀、三篇選讀，本站都整理過：

四篇的證據形式不一樣，後面每一章都要記得這件事。MemGPT 在兩個對話任務與兩個文件任務上，拿同一個模型比包進 MemGPT 與只靠固定視窗（開場白任務改和人寫的開場白比）；Mem0 是公司寫自家系統的論文，在 LOCOMO 長對話基準上和六類對手比，除了已發表的結果，對手都是作者自己跑的；Generative Agents 請 100 位評審排序可信度，再加上兩天模擬裡的湧現行為；Letta 的部落格是公司的概念文章，描述自家產品，沒有附量測數字。整理者補充一句背景：Letta 是 MemGPT 的作者們成立的公司，本站 MemGPT 與 Letta 兩頁也都註明了，原文沒有寫。四篇的正式篇名與原文連結列在頁尾。

這張表是整理者依四篇的章節對出來的，不是原文的分類。從表上看得出幾件事：

  • 「短期與長期記憶」四篇都有專章，切法各不相同。MemGPT 分成視窗裡的主脈絡與視窗外的外部脈絡；Generative Agents 把完整的經歷放在模型外的記憶流，每一步只撈幾筆進 prompt；Mem0 談的是跨 session 留下來的記憶；Letta 說只有訊息緩衝區算短期，其他都算長期。各篇怎麼稱呼，整理在最後的「同一件事的名字」。
  • 「記憶當成工具動作」：MemGPT 與 Letta 讓 agent 自己用函式或工具讀寫；Mem0 把 tool call 放在記憶層的更新步驟，由 LLM 從四種操作選一種；Generative Agents 的讀寫由架構在固定的時機觸發，模型不決定何時查記憶。誰來發動，是第 2 章的爭點。
  • 「結構化記憶」有三篇專章處理，結構各不相同：Generative Agents 的反思樹、Mem0g 的圖、Letta 的記憶區塊；MemGPT 的工作脈絡是一塊非結構化的文字。第 4 章把證據並排。
  • 「檔案系統」與「跨 agent」在單元內談得最少。四篇的外部記憶都放在資料庫（MemGPT 的 archival storage 用 PostgreSQL，Mem0 用向量資料庫與 Neo4j，Generative Agents 的記憶流也是資料庫），Letta 只提到回想記憶會自動存到磁碟。跨 agent 的只有兩處：Letta 說睡眠時間 agent 這類專門管記憶的 agent 也能改寫記憶區塊，Generative Agents 的消息靠對話在代理之間傳開。
跨單元的對照

檔案當記憶，寫在其他單元

單元 2 的〈Effective Context Engineering〉把 agent 寫在視窗外、之後再讀回來的筆記叫做結構化筆記，也叫 agentic memory，例子是一份 NOTES.md，並提到一套以檔案為基礎的 memory tool（Context Engineering 第 8 章）。單元 13 的〈Effective Harnesses for Long-Running Agents〉讓每個新的 session 先讀進度檔與 git 紀錄，弄清楚工作做到哪裡（第 2、6 章）。單元 14 的 OpenClaw 文件說模型只記得存到磁碟上的東西，記憶全寫成檔案（OpenClaw 第 4 章）。三篇都不在這個單元，這裡只並排原文寫的事。

課程講題沒有列、但三篇論文都花了大半篇幅的是怎麼評估記憶：MemGPT 設計了深度記憶檢索與開場白兩個對話任務，Mem0 用 LOCOMO 加上延遲與 token，Generative Agents 請 100 位評審排序可信度；Letta 的部落格沒有附量測數字。這些量尺不同，第 3、4 章會分開寫。

讓模型自己決定

MemGPT 的記憶編輯與檢索由模型主導：模型輸出函式呼叫，系統解析、驗證參數、執行，再把結果與錯誤送回給模型；工作脈絡的改寫、archival storage 的存取、舊對話的搜尋都走這條路（MemGPT 第 5 章）。系統自動做的有兩件：佇列管理器把每一則訊息寫進 recall storage；prompt 超過警告門檻（原文的例子是視窗的 70%）就插入記憶壓力警告，超過清空門檻就逐出一批訊息、重寫遞迴摘要（第 4 章）。事件叫醒模型，帶 request_heartbeat=true 的呼叫讓它連續查好幾次（第 6 章）。

這樣做的代價，MemGPT 自己的實驗裡看得到。多文件問答裡，MemGPT 理論上翻得夠多頁就找得到金牌文件，實際上常在翻完之前就停下來；配 GPT-3.5 的表現明顯變差，作者歸因於它有限的函式呼叫能力（第 10 章）。巢狀鍵值裡，MemGPT 配 GPT-4 不受層數影響，配 GPT-4 Turbo 與 GPT-3.5 則從第 2 層開始下滑，原因是沒有做足夠的查詢（第 11 章）。

Letta 的部落格也讓 agent 用工具改寫自己的記憶區塊、用工具查外部資料庫（Letta 第 4、5 章）。它另外介紹了睡眠時間 agent：作者說原始的 MemGPT 把記憶管理、對話和其他任務綁在同一個 agent 身上，記憶操作進行時回應可能變慢；改由另一個 agent 非同步處理、趁閒置時重新整理記憶，回應時間與記憶品質都改善了（第 7 章）。這一段是作者的說法，文章沒有附量測數字。

讓程式決定時機

Mem0 的記憶層跟在對話旁邊。每收到一對訊息，就帶著對話摘要與最近 10 則訊息抽出候選事實，再拿每條事實去比最像的 10 條舊記憶，由 LLM 透過 tool call 選新增、更新、刪除或不動（Mem0 第 2、3 章）。什麼時候寫，由這條流程決定；怎麼寫，由 LLM 判斷；回答問題時才把相關的記憶取回來。

Generative Agents 的讀寫全部由架構在固定的時機觸發：每一步都依近時、重要性、相關性三個分數檢索（Generative Agents 第 5 章）；最近事件的重要性加總超過 150 就反思一次，實際約一天兩三次（第 6 章）；一天的計畫先寫大綱，接近當下才拆細（第 7 章）。模型負責替記憶打重要性分數、寫反思與計畫，但不決定什麼時候查記憶。

整理者的讀法

四篇的證據，量的是不同的東西

  • MemGPT：實驗比的是「包進 MemGPT」與「只靠固定視窗」，整套系統一起換；讓模型自己決定的代價，要從它的失敗分析裡看：太早停、少查一層。
  • Mem0：延遲量的是回答時的搜尋與生成（Mem0 第 6 章的定義）；把對話寫成記憶花的時間不在這兩欄，第 12 章只給了建圖時間的觀察。
  • Generative Agents：消融拿掉的是記憶的種類，不是觸發的方式；成本是整套模擬的總花費。
  • Letta：睡眠時間 agent 的好處是作者的說法，這篇沒有數字。
  • 並排的比較：四篇都沒有在同一組任務上，並排「模型自己決定何時讀寫」與「程式在固定時機讀寫」。
跨單元的對照

單元 2 把兩種取回叫做推論前檢索與即時載入

單元 2 的〈Effective Context Engineering〉說，許多應用在推論前用 embedding 把可能相關的資料先檢索進來；越來越多團隊在這之外加上即時的策略：agent 手上只留輕量的識別碼，跑的時候再用工具把資料載入。原文說即時載入比較慢，常見的答案是兩者混合（Context Engineering 第 5 章）。這篇不在本單元，也沒有引用這四篇，這裡只並排它的說法。

還沒有答案的地方，三篇論文自己也點出來了。MemGPT 把進一步改進控制流程與記憶管理的策略列為後續方向（MemGPT 第 13 章）；Generative Agents 說檢索撈出的資訊還可以更相關，要針對情境微調三個分數的函式（Generative Agents 第 12 章）；Mem0 把最佳化圖的操作、降低 Mem0g 的延遲列為第一個後續方向（Mem0 第 13 章）。

整理者的讀法

兩篇比的對手不一樣

  • MemGPT 的 DMR：完整紀錄加搜尋，對上有損的摘要；題目考細節。
  • Mem0 的 LOCOMO：抽出的事實，對上原文片段（RAG）與整段原文（全脈絡）；題目分單跳、多跳、開放領域、時間四類。

  • 量尺：兩篇的評審都寬鬆，Mem0 的評審 prompt 還改寫自 MemGPT 的；但準確率與 J 仍是不同題目上的分數。

還沒有答案的地方，原文也點出了方向。MemGPT 想整合不同的記憶層技術，例如資料庫或快取（MemGPT 第 13 章）；Mem0 想探索兼顧效率與關係表示的階層式記憶架構（Mem0 第 13 章）；Generative Agents 說檢索撈出的資訊還可以更相關（Generative Agents 第 12 章）。

三種結構

Generative Agents 的反思以觀察與先前的反思為對象，所以長成一棵樹：葉是觀察，越往上越抽象，每筆反思都存著指回依據的指標（Generative Agents 第 6 章）。代理記得的地圖也是一棵樹，只記它看過的區域與當時的狀態（第 3 章）。

Mem0g 把記憶存成有向的標籤圖：節點是實體，邊是關係；新資訊和舊關係衝突時，舊關係標成失效、不刪除，作者說這是為了保留時間推理的能力（Mem0 第 4 章）。取回時可以沿著實體展開子圖，也可以拿整句查詢比對三元組（第 5 章）。

Letta 的記憶區塊有標籤、說明、值與字元上限四個欄位，固定釘在視窗裡；agent 用工具改寫它，其他 agent 也能改（Letta 第 4 章）。外部儲存可以是向量資料庫或圖資料庫，作者說圖讓 agent 能沿著概念之間的關係推理（第 5 章）。這篇沒有附數字。MemGPT 的工作脈絡是固定大小、只能用函式寫入的一塊非結構化文字（MemGPT 第 3 章），記憶要不要結構化，論文沒有討論（第 13 章，本站整理者的讀法）。

第 04 步除了答對率，也記每次放進視窗的 token、延遲與該查卻沒查的次數；第 05 步才把事實存成圖或加上反思，分題型看有沒有差。這五步是整理者把三題的證據接起來的順序，不是任何一篇讀物的建議。
注意：三題都不附答案；卡上的「還缺」是四篇都沒有報告的證據，不是整理者的結論。
判斷題 · 01

記憶什麼時候讀寫，該交給模型自己決定，還是寫進流程？

交給模型的一方：MemGPT 讓模型用函式呼叫自己搬，Letta 的 agent 用工具改寫區塊。寫進流程的一方：Generative Agents 每一步檢索、重要性累計到門檻才反思，Mem0 每一對訊息就抽取與更新，Letta 另派睡眠時間 agent 在閒置時整理（都在第 2 章）。

還缺的證據：同一組任務、同一個模型下，並排兩種做法，記準確率、呼叫次數、延遲，以及該查卻沒查的次數。四篇都沒有做；MemGPT 的證據來自它自己的失敗分析，Letta 的說法沒有附數字。

從自己的對話紀錄挑二十段多段對話，出幾題要回頭查的問題。一版給模型搜尋與寫入的工具、讓它自己決定；一版每一輪固定取回前幾筆、每一輪結束固定寫入。兩版用同一個模型，數答對幾題、各呼叫幾次、有幾次該查卻沒查。

判斷題 · 02

長期記憶該留原話、留摘要，還是只留抽出的事實？

留原話的一方：MemGPT 的 DMR 裡，能搜完整紀錄的版本比只有摘要的基線高很多；Mem0 的表 2 裡，讀整段原文的全脈絡 J 最高。只留事實的一方：Mem0 的分數高於它試過的每一種 RAG 設定；和全脈絡比，每次放進視窗的 token 與 p95 總延遲都少很多（都在第 3 章）。

還缺的證據：同一組題目上並排三種存法。MemGPT 沒有和抽出的事實比，Mem0 沒有和「完整紀錄加搜尋」比。

用同一批對話建三種記憶：原文加搜尋、滾動的摘要、抽出的事實（遇到矛盾就更新）。各出一組考細節的題（像 DMR 的「那次午餐吃哪一家」）和一組考偏好的題，看哪種存法在哪類題掉分，也記每次放進視窗的 token 數。

判斷題 · 03

記憶要不要加結構？加的話，加哪一種？

加分的例子：Mem0g 在時間題與開放領域的 J 高於 Mem0；Generative Agents 拿掉反思，可信度下降。掉分或代價：Mem0g 在單跳與多跳低於 Mem0，每次取回的 token 約多一倍；Generative Agents 的代理知道的地點越多，越會挑錯地方（都在第 4 章）。

可以拿來判斷的問題：你的問題裡，時間與關係的題占多少？結構帶來的額外延遲與 token，你的應用受不受得了？

把同一批事實存成兩份：一份清單，一份「實體、關係、實體」的三元組，舊關係標成失效而不刪。問幾題「他去年住哪裡」這類時間題，和幾題要串起兩條事實才答得出的題，分題型比兩份的答對率。

為什麼不附答案

證據在別人的任務上量出來

四篇的數字來自不同的任務、模型與評分方式；放到你自己的任務上會不會成立，要用你的任務量過才知道。這一頁只負責把證據排在一起，判斷留給讀者。

Reference · 用詞對照

同一件事，四篇各用不同的名字

四篇對記憶放在哪、怎麼寫、怎麼取回各有說法。每一條先寫這件事，再列各篇怎麼稱呼、在本站讀物頁的哪一章；沒有談到的篇就不列。

in-context memory
視窗裡的記憶
MemGPT：主脈絡，分系統指令、工作脈絡、FIFO 佇列三段（第 3 章）。Letta：訊息緩衝區與核心記憶（第 2 章）。Generative Agents：每次呼叫模型時 prompt 裡的那一段，包括代理摘要、當下的觀察與撈回的記憶（第 4、8 章）。Mem0：回答時放進 prompt 的取回記憶，每次約 1,764 token（第 11 章）。
external memory
視窗外的記憶
MemGPT：外部脈絡，包括 recall storage 與 archival storage（第 3 章）。Letta：回想記憶與歸檔記憶（第 2 章）。Generative Agents：記憶流（第 4 章）。Mem0：記憶庫，用向量資料庫；Mem0g 用 Neo4j 的圖（第 2、4 章）。
core memory
常駐視窗的事實
MemGPT：工作脈絡，附錄的提示詞稱它 core memory（第 3 章）。Letta：核心記憶，由記憶區塊組成（第 2、4 章）。Generative Agents：代理摘要，定期重新整理並快取（第 8 章）。
recall
完整的對話紀錄
MemGPT：recall storage，佇列管理器把每則訊息寫進去（第 3、4 章）。Letta：回想記憶，自動存到磁碟（第 2 章）。Generative Agents：記憶流裡的觀察（第 4 章）。Mem0 的記憶只存事實，抽取時參考對話摘要與最近 10 則訊息（第 2 章）。
summary
摘要
MemGPT：遞迴摘要，放在佇列第一格（第 4 章）。Letta：遞迴摘要，驅逐時連同舊摘要再摘要一次（第 3 章）。Mem0：對話摘要 S，由非同步模組定期更新（第 2 章）。Generative Agents：代理的摘要描述，由三次檢索加摘要產生（第 8 章）。
eviction
趕出視窗
MemGPT：警告門檻的例子是視窗的 70%，清空時逐出約半個視窗（第 4 章）。Letta：一次只驅逐一部分訊息，例子是 70%（第 3 章）。兩篇的 70% 指的不是同一件事。
memory write
寫入的動作
MemGPT：working_context.append、replace（第 5 章）。Letta：用工具改寫區塊，稱為 context 改寫（第 4 章）。Mem0：ADD、UPDATE、DELETE、NOOP 四種操作（第 3 章）。Generative Agents：觀察寫入記憶流，反思與計畫也寫回去（第 4 章）。
retrieval
取回
MemGPT：recall_storage.search 與 archival_storage.search，可以翻頁（第 5 章）。Letta：檢索是記憶的工具，不是記憶本身（第 5 章）。Mem0：向量搜尋最像的記憶；Mem0g 以實體為中心展開，或比對三元組（第 2、5 章）。Generative Agents：近時、重要性、相關性三個分數相加（第 5 章）。
consolidation
整理記憶
Letta：睡眠時間 agent 在閒置時整理區塊（第 7 章）。Generative Agents：反思，最近事件的重要性加總超過 150 時觸發（第 6 章）。Mem0：更新階段拿新事實比對最像的 10 條記憶（第 3 章）。單元 14 的 OpenClaw 把這一步叫做 dreaming。
conflict
過時與矛盾
Mem0：DELETE 會真的刪掉被矛盾的記憶；Mem0g 把過時的關係標成失效、不刪（第 3、4 章）。MemGPT：用 working_context.replace 改寫，例如「男友」改成「前男友」（第 5 章）。Generative Agents：環境樹記得的狀態可能過時，回去才更新（第 3 章）。
structure
記憶的結構
Letta：記憶區塊的標籤、說明、值與字元上限（第 4 章）。Mem0g：有向的標籤圖（第 4 章）。Generative Agents：反思樹與環境樹（第 3、6 章）。MemGPT：工作脈絡是非結構化文字（第 3 章）。
evaluation
怎麼量記憶
MemGPT：DMR 的準確率與 ROUGE-L，開場白與人設的相似度（第 8、9 章）。Mem0：LOCOMO 的 J、F1、BLEU-1，加上延遲與 token（第 6 章）。Generative Agents：TrueSkill 的可信度排名，以及兩天模擬的資訊擴散、關係與協調（第 9、11 章）。Letta 的部落格沒有量測。
