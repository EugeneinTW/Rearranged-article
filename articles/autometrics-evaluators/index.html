不到一百筆人評， 長出一組 對齊人的評估指標AutoMetrics：產生評審標準、 檢索現成指標、 用回歸配出權重

開放式的 AI 應用很難評：旅遊規劃、臨床紀錄、對話都沒有可以直接驗證的答案，手上常常只有使用者按的讚與倒讚。這篇論文的 AutoMetrics 從任務說明和不到 100 筆人評出發，讓 LLM 依好壞例子寫出候選評審，再從 48 個現成指標組成的 MetricBank 檢索，最後用回歸挑出幾個指標、配上權重。作者在五個任務上和 LLM 評審等基線比較與人評的相關，也把產生的指標拿去最佳化一個 τ-bench 的客服 agent。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

評審該看什麼，可以從少量人評裡學出來

Stanford CS 329Z 第 8 週「LLM-as-Judge & Evaluation Infrastructure」那一講（Evaluation for Agentic Systems 分區），談三種 grader、judge prompt 怎麼設計、已知的偏誤、pairwise 對 pointwise、非確定性的指標（pass@k 對 pass^k）、harness 設計，以及 Anthropic 的八步路線圖。這篇論文是這一講的必讀，它處理評審從哪裡來：人只給得出很少、又說不出原因的訊號時，怎麼做出一組會對齊人的指標。

同一講的另兩篇必讀是 Anthropic 的〈Demystifying evals for AI agents〉與 MT-Bench 論文（Zheng 等），選讀是 AutoLibra。MT-Bench 那一篇，正是這篇在相關工作裡替 LLM-as-a-Judge 引的出處。論文有六位作者，三位來自 Stanford、三位來自 American Express；整理者對照作者名單：第一作者 Michael J. Ryan 與最後作者 Diyi Yang 就是這門課的講師。

論文要解的問題是這樣。數學與寫程式有可以驗證對錯的答案，寫作、旅遊規劃、對話這類開放式任務沒有；人評仍是金標準，但又貴又慢。常見的替代是寫一份 rubric 請 LLM 當評審，前提是你已經知道該看什麼。作者說實務上多半只有讚與倒讚這種說不出原因的訊號，難處在找出背後的標準。AutoMetrics 的做法是讓標準從資料裡長出來：LLM 依好壞例子寫出候選評審，再和現成的指標一起交給回歸挑選、配權重。

先把幾個名詞對齊

  • Kendall τ：比較兩組排名一致的程度。把每一對輸出拿出來看，指標和人評排的先後相同就加分、相反就扣分；1 是完全一致，0 是和亂排差不多，負的是排反了。
  • z 分數：把一個量減掉平均、再除以標準差。BLEU 在 0 到 1、評審打 1 到 5 分，轉成 z 分數之後才能放在同一個回歸裡。
  • 偏最小平方回歸（PLS）：預測量很多、彼此又高度相關時用的回歸。它先找出一個最能預測目標的方向，把所有預測量投影上去，再沿著這個方向做回歸。
  • reward model：用大量人類偏好訓練出來、替回應打分的模型；MetricBank 也收了幾個現成的。

引言從一個落差講起。大型模型能拿去做幾乎任何任務，從旅遊規劃到程式補全，原型很快就做得出來，速度遠比社群替新任務設計專用指標快（作者引的是 BLEU、ROUGE、SARI 這幾篇指標論文）。數學與寫程式有容易驗證的獎勵，寫作這類主觀、開放的任務卻很難量；對這些任務，人評仍是金標準。

人評的問題是貴、慢，也沒辦法替每個原型、每群使用者都做一次。reward model 是一種替代，但通常要上千筆標籤。更常見的替代是 rubric 式的 LLM-as-a-Judge：把評分標準寫成 rubric，請 LLM 照著打。作者點出兩個問題：它假設系統該有的行為已經定義清楚，而且評審不保證嚴格照 rubric 打分（作者引 Tripathi 等人）。實務上，從業者手上往往只有說不出原因的訊號，例如使用者按的讚或倒讚；這時要做的不只是寫出 rubric，還得先找出真正重要的標準。引言這樣描述這件事：

"not only formulating the rubric, but also discovering the underlying criteria that matter" 「不只是寫出 rubric，還要找出真正重要的標準」：引言描述只有讚與倒讚時的難處。

作者由此主張評估本身要能適應：不只靠人評或固定的 rubric，而是依任務學出指標。已有的研究多半在讓 LLM 更會評特定標準，或拿 rubric 去最佳化模型；自動產生 rubric 與標準、並讓它們對齊人評的工作相對少，作者列了 RUBICON、VibeCheck，以及第一作者自己的 SynthesizeMe。作者說這種能適應的評估，不只讓新任務好評，也讓系統能依使用者的即時回饋最佳化。

AutoMetrics 就是在做這件事：把稀疏、說不出原因的人類回饋，變成能拿來行動、也看得懂的評估器。它從一份任務說明與不到 100 筆人類訊號出發，合成候選標準、檢索並改用現成的指標，再用回歸組成預測品質的量。作者強調它不只找出標準，還替標準找依據、配上權重，所以產出的指標既能預測人評，也看得出在量什麼。引言預告了三個結果：和人評的 Kendall 相關比 LLM 評審最多高 33.4%（第 8 章會拿表 2 核對這個數字）、大約 80 筆回饋就夠（第 11 章）、拿來最佳化下游系統時追得上可驗證獎勵（第 12 章）。工具開源在 GitHub 的 SALT-NLP/autometrics。

圖 1 用一個例子說明（第 02 卡）。資料是 EvalGen 的商品描述：LLM 依商品資料與顧客評論寫出描述，人只給讚或倒讚。AutoMetrics 產出五個指標，旁邊印著由回歸係數換算的相對重要性：避開禁用內容（不放連結、不用空泛的詞、不提商品缺點）26.3%、一個最佳化過的評審 prompt 23.6%、語氣與口吻的 rubric 19.9%、搜尋引擎最佳化 15.3%、一個附範例的評審 14.9%，五個加起來是 100%（整理者核對）。實驗裡拿來比較的 LLM 評審，用的是原本給標註者的說明；以 EvalGen 來說，那份說明只有一句「這個回應好（1）還是壞（0）？」（附錄 C.1）。

整理者的讀法

同一句說明，人和 LLM 讀到的東西不一樣

如果給人的說明只有「好還是壞」一句，真正的標準就留在標註者心裡，沒有寫下來；LLM 評審拿到的也只有那一句。AutoMetrics 產出的五個指標，可以看成把那些沒寫下來的標準攤開：禁用內容、語氣、搜尋引擎最佳化，各有一段說明與一個權重。這一段是整理者的讀法，論文沒有這樣說。

Chapter 02 · Related Work

組合指標與生成標準，以前是分開的兩條線

相關工作分兩條：一條整理現成指標，讓人好用或把它們組合起來，最接近的是用回歸組合指標的 MetaMetrics；另一條讓 LLM 當評審，最接近 AutoMetrics 評審步驟的是 DnA-Eval 與 EvalGen。作者主張，替新任務產生指標才是低資料、新任務情境的關鍵。

指標集合。先前的指標集合主要是為了讓從業者好用。已經在用 PyTorch 或 Hugging Face 的人，可以直接用 TorchMetrics 或 Hugging Face 的 lighteval；scikit-learn 的指標與 NLTK 的指標也是同樣的用意。作者說這些集合裡的文字生成指標，MetricBank 全部都有。另一種指標集合附在機器學習的觀測平台裡，例如 Evidently、Galileo、Scorecard.io、DeepEval；這些指標大多和平台綁在一起，只有 Evidently 與 DeepEval 有開源版。DeepEval 有推薦指標的功能，但它是一棵事先定好的問題樹，問的是「你的應用有沒有用檢索增強生成」「安全是不是優先考量」這類問題。

作者說最接近的是 MetaMetrics：它對多個任務專用的指標做回歸，替影像描述、摘要這類任務挑出最好的組合。作者在第 4 節把它當基線，並說比較的結果顯示，替新任務產生指標在低資料、新任務的情境裡是關鍵（第 8 章的表 2 裡，MetaMetrics 在 EvalGen 與 CoGym 是負的）。

LLM 評估。LLM 能力變強之後，LLM-as-a-Judge 越來越普遍。有一批研究替特定任務設計評審 prompt：說故事、摘要、對話、知識、翻譯等。另一批研究想讓 LLM 評審更可靠：G-Eval 把評估拆成一步步的思路鏈，再用產生各個分數的機率做加權；ChatEval 讓多個 agent 辯論，模擬多種觀點；SPADE 依標好的好壞例子，產生讓 LLM 驗證的斷言；VERDICT 把判斷拆成推理、驗證、辯論、彙整這些可以組合的單位，在評審時加算力。作者說 AutoMetrics 的 LLM 評審步驟借了這些做法，最接近的是 DnA-Eval 與 EvalGen：DnA-Eval 把評估拆成幾條 rubric 標準再彙整；EvalGen 向人收少量回饋，據此提出評估標準，再讓人與 LLM 一起反覆修改。

作者選 PLS 回歸，是因為這個情境有兩個限制：預測量（指標）的數量可能和資料筆數差不多、甚至更多；預測量之間又常常高度相關。直覺上，PLS 先把指標空間投影到最能預測人類標籤的方向，再沿著這條軸對標籤做回歸。

自然的延伸是：拿手上有限的資料學出一組有用的指標，再用它來最佳化系統；這時 AutoMetrics 的角色就像 reward model 或可驗證獎勵。作者選的測試環境是 τ-bench，一個讓使用工具的 agent 和模擬使用者互動、完成任務的測試平台。τ-airline 的 50 個任務切成兩半：25 個訓練、25 個評估。

模擬一個可驗證獎勵。作者把 25 個訓練任務各跑 8 次，溫度分別是 0.0、0.01、0.02、0.03、0.05、0.1、0.15、0.2，共 200 條軌跡（整理者算的），再取得每一條的真實獎勵。作者說實務上這一步可以換成主觀的人工標籤，不一定要可驗證獎勵。AutoMetrics 用「只用產生的」模式，並把資源多給產生的指標：單一標準的評審從 10 個加到 20 個、rubric 從 5 個加到 8 個；其他照預設（k＝30、n＝5）。

AutoMetrics 推薦了三個指標：兩個 rubric、一個單一標準（圖 5，附錄 G 有完整的 rubric）。會員權益的套用（rubric，係數 0.08，附錄 G 寫 0.0803），看的是依會員等級正確執行免費行李額度、保險資格與補償規則；該轉真人時才轉（rubric，0.0599），看的是遇到政策上限或需要例外處理時轉給真人客服；遵守航空公司規定（0.0567），例如沒有保險、又超過 24 小時，就不能取消基本經濟艙。附錄 G 印的整體 Kendall τ 是 0.2469。n＝5 原本推薦五個，最後的過濾刪掉兩個係數為負的。作者提醒，軌跡只來自 25 個任務，指標很可能開始學到資料本身的特徵；這說明了人的監督與指標過濾都重要。

沒有可驗證獎勵的最佳化。作者用 DSPy 寫了一個簡單的 ReAct agent 做 τ-airline 的任務，未最佳化時在 25 個測試任務上平均 60% 的正確率（五次試驗）。基準的最佳化用 DSPy 的 GEPA 最佳化器，在 25 個訓練任務上以可驗證獎勵最佳化；另一組改用 AutoMetrics 當 GEPA 的指標。2,000 次 rollout 後，用可驗證獎勵的 GEPA 在五次試驗平均是 0.680 ± 0.11，用 AutoMetrics 的是 0.720 ± 0.06。作者說 AutoMetrics 在統計上顯著高於 0.6 的基準（p < 0.05），並據此說它能追平、甚至超過可驗證獎勵當最佳化訊號。

思考題 · 03

如果拿學出來的指標當最佳化目標，你會怎麼防它被鑽漏洞？

想一個你想最佳化的 agent：客服、寫作、程式修改都可以。

指標庫
作者整理並實作的 48 個自然語言生成指標，29 個要參考答案、19 個不用（附錄 B、表 4）。
Metric Card
指標卡
仿照 Model Cards 寫的指標說明，七個部分；檢索時當成文件（附錄 B、D）。
Generate
產生
第一步：預設產生 10 個單一標準、5 個 rubric、1 個附範例、1 個 MIPROv2 最佳化過的評審（第 3.1 節）。
Retrieve
檢索
第二步：指標卡當文件、任務說明當查詢，ColBERT 先篩到 k′ 張，LLM 再挑出 k 個（預設 30）。
Regress
回歸
第三步：z 分數加 PLS，依權重取前 n 個（預設 5）再擬合，刪掉係數為負的產生指標。
Report
報告
第四步：寫出權重、和人評的相關與採用的細節；相關不顯著時加警告。
LLM-as-a-Judge
LLM 評審
讓 LLM 依一段說明替輸出打分；實驗的基線用原本給標註者的說明。
axis of variation
差異的軸
LLM 比較好壞例子後提出的評分面向；每條軸成為一個單一標準的評審（附錄 C.3、E.2）。
Single Criterion judge
單一標準的評審
只評一條軸、輸出 1 到 5 整數分的評審；附錄 F.2 裡被推薦最多的一類（67 個）。
rubric
評分說明
替一條軸寫出 1 到 5 分各長什麼樣；AutoMetrics 讓 LLM 依好壞例子產生。
Examples-based judge
附範例的評審
把人評例子分五等份抽樣放進 prompt，試 5 組、挑最接近人評的一組（附錄 E.2）。
MIPROv2
prompt 最佳化器
DSPy 內建的最佳化器，這裡拿來改寫評審 prompt、挑例子，當成一種昂貴的產生器。
ColBERT → LLMRec
兩段式檢索
ColBERT 先篩、再交給讀文件的 LLM 排序；附錄 E.1 在 16 種設定裡贏 14 種。
PLS regression
偏最小平方回歸
找出讓指標分數投影和人評共變異數最大的方向，再沿著它回歸；適合預測量多、又高度相關的情況。
Kendall's τ
Kendall 相關
兩組排名一致的程度；作者說它不假設分布，比 Spearman 與 Pearson 保守（第 3.2 節）。
criterion validity
判準效度
指標和參考標準的相關；這裡是和人評的 Kendall τ（表 2）。
construct validity
構念效度
指標有沒有抓到「品質」這個抽象概念；作者用敏感度與穩定度來量。
content validity
內容效度
指標有沒有代表它想量的東西；難以量化，作者用公開報告與評審的推理軌跡處理。
Sensitivity
敏感度
刻意改差的輸出拿到較低分的比例；AutoMetrics 在 81.0% 到 97.8% 之間（第 4.4 節）。
Stability
穩定度
1 減掉原本與等價改寫的分數差的平均；越接近 1 越不受無關變化影響。
in-distribution、out-of-distribution
分布內、分布外
MetricBank 裡有沒有專為這個任務設計的指標；五個任務裡三個是分布外。
high-p, low-n
高 p 低 n
預測量多、資料點少的回歸問題，容易出現假相關；少於 80 筆時只用產生的指標就是為了避開它。
verifiable reward
可驗證獎勵
可以用程式判定對錯的獎勵；第 5 節拿 τ-bench 的獎勵當標籤學指標，再和它比最佳化的效果。
τ-bench
工具型 agent 測試平台
agent 和模擬使用者互動、完成任務的測試平台；這篇用它的 50 個航空客服任務。
GEPA
反思式 prompt 最佳化器
DSPy 裡的 prompt 最佳化器；案例裡分別用可驗證獎勵與 AutoMetrics 當它的指標。
