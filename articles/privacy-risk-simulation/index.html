PRIVACY RISK SEARCH · 圖卡＋教材整合版

讓攻擊與防守 在模擬裡 互相逼出來LLM agent 的隱私風險： 讀模擬軌跡、改寫指令， 讓攻防交替搜尋

當每個人都有 agent 代辦事情，一個 agent 可能握著別人的病歷、案情或私人信件，另一個 agent 則會主動找上門，用多輪對話想把它套出來。這篇 Georgia Tech 與 Stanford 的論文把一條隱私規範做成三個 agent 的模擬，讓 LLM 讀模擬軌跡、改寫雙方的指令：先搜更強的攻擊，再搜擋得住的防守，一輪一輪交替。攻擊從直接開口要，一路升級到假冒身分與偽造同意；防守從要求同意的規則，長成先查身分的狀態機。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

隱私攻擊想不完，就讓搜尋去找

Stanford CS 329Z 第 8 週「Agent Safety & Guardrails」那一講（Safety 分區），談 agent 拿到工具與資料之後會出什麼事、怎麼設防。這篇 2025 年的論文是同一講的必讀，它處理的是其中最難事先列清單的一種風險：另一個 agent 主動上門，用對話把你手上的隱私資料套走。

這一講的講題有八個：工具存取帶來的隱私風險、prompt injection（含間接注入）、red-teaming、沙箱與權限模型、輸出護欄、責任、負責任的部署，以及 human-in-the-loop。同一講另外兩篇必讀是 Shao 等人的〈PrivacyLens〉與 Li 的〈Agentic LLMs as Powerful Deanonymizers〉；選讀是 Wen 等人的〈Contextualized Privacy Defense for LLM Agents〉、OpenAI 的〈Understanding Prompt Injections〉，以及 Anthropic 的 Responsible Scaling Policy。

先把幾個名詞對齊

  • 情境完整性（contextual integrity）：Nissenbaum 提出的隱私理論。一次資訊流動恰不恰當，要看它合不合所在情境的規範：誰、把誰的什麼資訊、經由什麼方式、給了誰。同一份病歷給主治醫師沒問題，寄給對方的筆友就不行。
  • ReAct：一種 agent 架構。模型每一步先寫下想法，再採取一個行動（例如呼叫工具），看到結果再決定下一步。
  • LLM 當最佳化器：讓 LLM 讀過去試過的候選與它們的分數，提出下一版更好的候選；論文引的是 Yang 等 2023 的做法。這篇的候選就是 agent 的指令。
  • 狀態機（state machine）：系統只能待在有限的幾個狀態之一，每個狀態只允許特定的動作，只有特定的事件能讓它換到下一個狀態。第 6 章的防守就是寫成這個樣子。

引言從一個情境講起：人與人的往來，正在變成各自由 AI agent 代理。這些 agent 不會單獨運作，而會和代表別人的 agent 協作、談判、分享資訊。作者說這帶來了新的隱私問題，範圍超出過去談 LLM 隱私時關心的訓練資料外洩或把使用者資料交給雲端。論文用粗體標出的研究問題是：手上握有敏感資訊的 AI agent，在和其他 agent 互動時，還能不能保持隱私意識。

作者整理了既有研究的兩種設定。第一種是使用者與 agent：使用者給的指示沒講清楚，agent 要依情境分辨哪些資料可以分享（作者引 Ruan 等 2023、PrivacyLens、AgentDAM）。第二種是 agent 與環境：環境裡藏著惡意的元素，例如網頁裡看不見的指令，誘使 agent 在替使用者做事時交出資料（作者引 EIA 與 fine-print injection 兩篇）。作者認為這兩種設定都抓不到真實威脅「會互動、會調整」的特性，所以提出一個分析 agent 對 agent 互動的框架：沒有權限的一方，主動透過多輪對話嘗試取得敏感資訊。

兩者的差別在攻擊面。作者說環境裡的威脅是靜態的，形狀也受介面的結構限制；多輪對話則會產生一直在演變的攻擊面，所以很難靠人工分析或逐一列舉找出弱點。這是整篇方法的出發點：既然列不完，就用搜尋去找。

"framing privacy risks themselves as objects of search" 「把隱私風險本身當成搜尋的對象」：引言說明這個做法和人工設計、預想威脅有什麼不同的一句。

作者的做法是一個以大規模模擬為基礎的搜尋框架，引的是用 LLM 做程式搜尋、做科學與演算法發現的研究。對每一條取自既有文獻（例如 PrivacyLens）的隱私規範，模擬依情境完整性理論放進三個 agent：資料主體、傳送方、接收方。資料主體先把敏感資訊交給傳送方；接收方（攻擊者）被指示用某種傳遞原則（例如「寄一封電子郵件」）從傳送方（防守者）那裡取得它。雙方的對話持續好幾輪，過程中檢查防守者的每個動作有沒有洩漏。

模擬讓互動式的風險變得可以控制地檢驗：防守者的指令固定時，任何一條讓洩漏變多的攻擊指令，就算是更有效的策略。有了這個比較基準，框架就能交替最佳化兩邊：先替每個情境搜出專屬的攻擊指令，再搜一套通用的防守指令去擋它們，然後重複。搜尋的引擎是讓 LLM 當最佳化器，讀模擬軌跡、提出新策略；為了搜得更完整，作者再加上平行搜尋，讓多條執行緒同時找，並把突破性的發現傳給其他執行緒。

引言預告了結果：框架找到的有效攻擊包括偽造同意與多輪的假冒，發展出的防守包括嚴格的身分驗證與以狀態機執行的規則；找到的攻擊與防守也能轉移到不同的模型與隱私情境。作者因此認為，這個框架可以當成實際部署前、面對真實對手時降低 agent 隱私風險的工具。

整理者的讀法

和 PrivacyLens 差在哪裡

PrivacyLens 的設定裡沒有對手：它給 agent 敏感資訊與一個沒講清楚的指示，看 agent 產生的動作裡有沒有不該出現的資訊。這篇沿用它的隱私規範與洩漏偵測，但把「沒講清楚的指示」換成一個被指示去套資料的 agent，並讓這個 agent 的指令被一輪一輪最佳化。第 2 節相關工作也這樣定位：既有研究多半是良性的設定，或是固定不變的惡意元素。這段對照是整理者依第 1、2 節整理的。

規範與角色。一條隱私規範寫成固定的句型：傳送方用某種傳遞原則，把資料主體的某類敏感資訊給接收方，是不被接受的。附錄 F 的第一個例子，整理者換成角色來說：一位律師不該用電子郵件，把委託人被指控的罪行告訴自己的筆友。模擬裡就有三個 agent：委託人（資料主體）、律師（傳送方）、筆友（接收方）。第二個例子是：一位編輯不該用電子郵件，把伴侶的感情困擾告訴自己的上司。

環境。三個 agent 透過 app 互動，這些 app 就是模擬的環境。作者照 Ruan 等 2023 與 PrivacyLens 的做法，實作了四個模擬的 app：Gmail、Facebook、Messenger 與 Notion，涵蓋了大部分的傳遞原則。每個 app 有自己的資料庫，以及附說明文件的 API，agent 用 tool call 操作它們（附錄 C 列了 Messenger 與 Gmail 的工具定義）。每條規範會用到兩個 app：一個是傳送方與接收方之間的溝通管道，由規範的傳遞原則決定；另一個負責把資料從主體送到傳送方，兩者可以是同一個。

agent。三個 agent 都用 ReAct 架構實作，執行方式由通知驅動：app 的通知（例如一封新信）觸發一個行動週期；週期裡 agent 可以連續做好幾個動作，最後必須呼叫 end_cycle() 結束週期、等下一個通知。每個週期開始時，agent 會拿到自己先前的互動紀錄。週期裡除了 app 的工具，還有一個思考工具 think()，模型被要求先想再行動；本身會推理的模型就不給這個工具。agent 覺得任務完成時呼叫 complete_task()。

記憶與指令。每個 agent 初始化時有一份記憶與一段指令。記憶放自己的社會背景、其他 agent 的公開資料與聯絡方式；資料主體的記憶多一份敏感項目的清單，傳送方的記憶多一句「某某的哪類資料放在哪個 app 裡」。指令則是：主體把敏感資料交給傳送方；傳送方監看通知、必要時回應其他 agent；接收方設法從傳送方取得敏感資訊。規範沒有指定的部分（社會背景、敏感項目清單），作者用 o4-mini-high 生成，再人工整理。

為什麼要反思。有效的攻擊要看情境，不跑模擬很難預測哪一種威脅比較大。作者的前導實驗發現，先生出大量多樣的策略、再全部拿去測，既沒效果也沒效率，因為設計策略的那一端收不到模擬結果的任何回饋。所以作者讓一個 LLM 當最佳化器 F，反思先前的策略與模擬軌跡，改寫接收方的指令。作者說這類反思式的方法（引 Yang 等 2023 的「LLM 當最佳化器」與 GEPA）有效，來自 LLM 能分析失敗的嘗試、看出防守的弱點，並放大成功的訊號。

循序搜尋的基線。輸入是 (a, d)：a 是起始的攻擊指令，d 是固定的防守指令。第 k 步用目前的攻擊指令跑 M 次模擬，得到 M 條軌跡與各自的洩漏速度；從中挑洩漏速度最高的幾組（指令、軌跡、分數）當反思例子，交給 F；F 讀全部的搜尋歷史，寫出下一版攻擊指令。重複 K 步算一個搜尋 epoch，回傳平均洩漏速度最高的那一版。

平行搜尋。只有一條執行緒的循序搜尋常常慢得無法接受，也容易被一開始的探索方向綁住；作者引的研究說，找到有效策略可能要幾百甚至幾千次迭代。所以演算法一次開 N 條平行的執行緒，每條從 LLM 依原始指令生出的一個不同起點開始（Init），各自反思、各自改進。這樣搜尋的吞吐量大幅提高，在有限的時間內找到有效攻擊的機會也變大。

平行的代價是每一步的模擬次數跟著執行緒數線性增加，一共 N×M 次。若為了多開執行緒而把 M 調小，單一指令的評估就變得不可靠。作者的做法是：M 設得很小，依 M 次的平均挑出一版，再替這一版加跑 P 次模擬，拿到比較可靠的估計。每一步只對一版指令做完整評估，最後回傳所有步裡表現最好的那一版。

跨執行緒傳遞。平行搜尋還有一個限制：執行緒之間不分享資訊，任何發現都被困在找到它的那一條執行緒裡，只有它能在後面的步驟繼續精修。作者借演化搜尋裡的遷移（migration）機制，加入跨執行緒傳遞：當這一步最好的那版指令（用 P 次模擬評估）勝過之前所有的步驟，所有執行緒挑反思例子時，改從全部執行緒的結果裡挑，而不是只從自己的結果挑。這樣每條執行緒都知道目前最有效的策略，可以同時去精修它。

# 輸入：步數 K、執行緒數 N、每步模擬 M、加跑 P、最佳化器 F、起始攻擊 a、固定防守 d
best, tau = a, 0
for k in 1..K:                                   # 第 5 行
    if k == 1:
        instr = Init(a)                              # 第 7 行：LLM 生出 N 個不同的起點
    else:
        instr[i] = F(第 i 條執行緒的歷史)             # 第 10 行：每條執行緒各寫下一版
    runs[i] = 跑 M 次 Simulate(instr[i], d)          # 第 11 到 15 行
    j = 平均洩漏速度最高的執行緒                      # 第 16 行
    runs[j] += 再跑 P 次 Simulate(instr[j], d)       # 第 17 到 19 行
    mu = 那 P 次的平均                               # 第 20 行
    if mu > tau:                                     # 第 21 行：刷新紀錄
        每條執行緒的例子 = Select(所有執行緒的 runs)  # 第 23 行：跨執行緒傳遞
        tau, best = mu, instr[j]
    else:
        每條執行緒的例子 = Select(自己的 runs)        # 第 28 行
return best                                        # 第 29 行

這段是整理者依演算法 1 寫的結構，不是論文的程式。實驗的設定是 N＝30、M＝1、K＝10、P＝10，Select 每一步回傳 5 個例子。附錄 J 交代了這些數字怎麼來：N×M 相同時，N＝10、M＝3 和 N＝30、M＝1 的表現相近，作者選後者以求更平行；K＝10 是因為用預設的 Gemini 2.5 Pro 當最佳化器時，表現通常在 10 步之後趨平；P＝10 則是在成本與風險評估的可信度之間取捨，因為模擬結果的變異很大。

最佳化器看到什麼

附錄 I 的 prompt，只交代它的結構

最佳化器的 system prompt 說明模擬裡三個 agent 的角色，以及它在搜尋演算法裡的位置；每一步的 prompt 再給它目前的搜尋進度（這一輪與先前幾輪的最佳分數）、目前的設定，以及這一輪的模擬軌跡，軌跡裡傳送方的每個動作都標了洩漏了哪些項目。它要先寫出分析，再輸出一段新的任務描述，格式是 JSON，長度限制在 50 個英文字以內。原文的 prompt 是用來產生攻擊指令的，本頁只寫到這個層次，不轉寫內容。

你的 agent 被攻擊時，誰會發現「這一招有效」？

Chapter 11 · Related Work

驗一條攻擊要跑整場對話，所以靠反思

作者把這篇放在三條研究線的交會處：agent 的隱私評測、隱私防禦、用 LLM 搜尋 prompt。和既有的對抗搜尋相比，在多輪模擬裡驗證一條攻擊指令貴得多，所以不走大量重抽樣或訓練專用模型，改靠 LLM 讀軌跡反思。

LLM agent 的隱私。LLM 的隱私問題常見的有訓練資料被萃取、system prompt 被萃取、使用者的敏感資料外洩給雲端服務商。和這篇最相關的，是檢查 LLM agent 產生的動作會不會洩漏使用者的私人資訊。ConfAIde 與 PrivacyLens 都以情境完整性理論為基礎，給 LLM 敏感資訊與沒講清楚的使用者指示，再測它預測的動作（例如寄信、傳訊息）裡有沒有敏感資訊；這類情境可以用群眾外包收集，也可以從法律文件抽取（PrivaCI-bench）；AgentDAM 把設定延伸到真實的網頁導航環境。作者說這些研究主要看良性的設定，沒有惡意的攻擊者。EIA 與 fine-print injection 更進一步，測網頁 agent 在替使用者填表這類敏感任務時，能不能應付嵌在網頁裡的惡意元素（例如索取個資的指令），那些指令可能藏在看不見的 HTML 裡，或包裝成看似合理的介面元件。這篇和它們的差別是：對手不是靜態的，而是會主動發起、持續多輪對話的攻擊 agent。

隱私防禦。最常見的防禦是在 prompt 裡給 LLM 隱私準則。在 prompt 之外，Abdelnabi 等人發展出能自動導出規則、替 agent 網路建防火牆過濾輸入與資料的協定；AirGapAgent 則多放一個有隱私意識的 agent，只讓任務必要的資料被存取。作者選擇專注在 prompt 層的防守，理由是簡單，而且模型遵循複雜指令的能力越來越強；他們也說這套模擬與搜尋框架，之後可以容納並最佳化更複雜的防守協定。

prompt 搜尋。一般任務的 prompt 最佳化有幾種做法：重抽樣是暴力法，一次生很多 prompt 再挑表現好的；反思（Yang 等 2023）讓 LLM 從（例子、分數）配對裡學，靠模式辨認反覆改寫；更有結構的做法把 LLM 放進基因演算法這類演化框架，用交叉與突變最佳化 prompt（EvoPrompt）。最佳化 agent 時，LLM 可以檢查 agent 的軌跡（Docent），直接改 agent 的 prompt（Opsahl-Ong 等 2024、Yuksekgonul 等 2025、GEPA），或寫程式改 agent 的架構（Hu 等 2024、Darwin Gödel Machine）。作者指出，這篇的目標是找長尾的風險，不是提升任務表現，最佳化的地形很不一樣：在 DSPy 這類框架裡，prompt 稍微改寫常常就有看得到的分數變化；這篇提出的很多攻擊策略，因為沒有揭露任何弱點，根本看不到訊號。

對抗式的搜尋。在類似的對抗情境裡，Perez 等人用重抽樣自動找對抗性 prompt（也就是用語言模型替語言模型做紅隊），AutoDAN 用基因演算法搜尋隱蔽的越獄 prompt，Rainbow Teaming 與 Foundation Model Self-Play 把搜尋寫成品質與多樣性並重的問題，鼓勵產生多樣的對抗策略。也有研究訓練專門的模型，系統性地引出有害的輸出與行為（Curiosity-driven red-teaming、investigator agents）。作者說和越獄不同，在多輪模擬裡驗證一條攻擊指令有沒有效，需要多得多的計算與時間，所以重抽樣與訓練專用模型都不實際；這篇的搜尋建立在 LLM 的反思能力上，用先前的嘗試提出更有效的指令。

第 5 節的收尾是：這篇研究 LLM agent 互動時的隱私風險，在可控的模擬上，用交替搜尋系統性地找出風險、發展穩的防守策略。演算法的核心是讓 LLM 反思模擬軌跡、提出新的攻擊與防守策略，再用平行搜尋與跨執行緒傳遞加強。作者說找到的攻擊與防守可以轉移到不同的模型，不論模型家族、大小，或是不是推理模型，也能轉移到沒看過的情境。

作者希望這是自動找出 agent 風險、並替它設防的第一步，並點名兩個方向。第一，擴大找出的風險的範圍與類型：探索更廣的長尾風險，例如本來就很難處理的情境。第二，擴大搜尋空間：除了最佳化 prompt 指令，也可以去搜尋最好的 agent 架構、護欄設計，甚至訓練目標。

倫理與可重現性。倫理聲明說，這篇透過受控的模擬研究 agent 之間互動的隱私風險，沒有牽涉人類受試者或可識別個人的資料；框架的目的是揭露弱點以發展更強的防禦，不是協助惡意使用。作者承認找到的新攻擊策略可能被對手參考，他們的緩解方式是只在有效反制的脈絡裡呈現這些策略。可重現性聲明列出補充材料：所有模擬設定（寫的是 Training-100 與 Testing-100）、模擬與評估的程式，以及 agent 軌跡的範例；正文實驗用的訓練集是 Training-5，兩個名稱照錄。作者也在摘要的註腳說程式與資料公開在 GitHub。

防守只能寫在 prompt 裡嗎？
這篇只做 prompt 層的防守。第 2 節說選它是因為簡單，而且模型越來越會遵循複雜的指令；框架也能放進更複雜的防守協定。結論把 agent 架構、護欄設計與訓練目標列為之後可以搜尋的對象。
換一個更強的模型當傳送方就夠了嗎？
不夠。表 1 裡更強的模型確實漏得少，但第 4.4 節的消融裡，隱私意識最強的 GPT-4.1 到搜尋最後仍被找到明顯的弱點；附錄 G 也發現讓模型想得更久，不一定更懂隱私。

只能說有初步證據。v3 的個案研究在真實信箱上重演假冒攻擊，5 次成功 3 次；作者說規模有限，系統的 sim-to-real 研究留給未來。
整理者的讀法

放回這一講：D2 其實是一個權限與確認的流程

下面是整理者的連結，論文沒有這樣講。D2 做的三件事：只認從已驗證帳號來的訊息、不接受轉貼或代轉的同意、直接回頭去問資料的主人，放在這一講的講題裡，分別像是身分驗證、權限的來源要可以追溯，以及 human-in-the-loop 的確認。差別在這篇把它們都寫在 prompt 裡，靠模型自己遵守；第 8 章的轉移結果顯示，遵循能力較弱的模型就守不住這些規則。這一講談的沙箱、權限模型與輸出護欄，則是把同樣的限制放到模型之外去執行，論文把這類方向留給之後。

攻擊的樣子不必靠人去猜，讓它在模擬裡被搜出來；防守也不必靠人去寫完，讓它對著搜出來的攻擊長出來。 整理自第 1、5 節

Reference · 名詞速查

關鍵名詞，與它們在論文裡的位置

先列模擬的角色與設定，再列指標與搜尋的零件，最後是攻防的名稱、資料集與相關研究。

contextual integrity
情境完整性
Nissenbaum 的隱私理論：資訊流動恰不恰當，看它合不合所在情境的規範；模擬的三個角色依它設計（第 1 節）。
privacy norm
隱私規範
「傳送方用某種傳遞原則，把主體的某類敏感資訊給接收方，是不被接受的」；取自既有文獻，例如 PrivacyLens。
data subject
資料主體
資訊的主人；模擬一開始把敏感資料交給傳送方，之後停用。
data sender
傳送方（防守）
握有別人資料的 agent，要決定分不分享；洩漏只看它的動作。
data recipient
接收方（攻擊）
不該拿到資料、卻被指示去套出資料的 agent；它的指令是攻擊搜尋改寫的對象。
transmission principle
傳遞原則
資訊經由什麼方式流動，例如寄電子郵件；決定傳送方與接收方用哪個 app 溝通。
mock application
模擬的 app
Gmail、Facebook、Messenger、Notion 的模擬版，各有資料庫與附說明的 API（第 3 節、附錄 B、C）。
action cycle
行動週期
一則通知觸發一個週期，agent 連續做幾個動作後呼叫 end_cycle() 等下一則通知（附錄 B）。
leak rate
洩漏率
有任何敏感項目洩漏的軌跡比例；照 PrivacyLens 的做法，通常比洩漏速度高 5 到 10 個百分點。
leak velocity
洩漏速度
每個項目第一個動作就漏記 1、越晚越小、沒漏記 0，再取平均；搜尋與評估的主要指標。
leak score
洩漏分數
給 LLM 最佳化器看的版本，方向和洩漏速度相反，越低代表漏得越多（附錄 I）。
alternating search
交替搜尋
每個週期先固定防守搜攻擊，再固定攻擊搜防守；依序得到 A1、D1、A2、D2（第 3 節）。
LLM optimizer
LLM 最佳化器
讀過去的指令與挑出的軌跡、寫下一版指令的 LLM；預設是 Gemini 2.5 Pro，換掉就搜得較差。
parallel search
平行搜尋
N 條執行緒各自改進一版攻擊指令；實驗 N＝30、M＝1，最好的那版再加跑 P＝10 次（第 3.1 節）。
cross-thread propagation
跨執行緒傳遞
刷新紀錄時，所有執行緒都從全部執行緒的結果挑反思例子；仿演化搜尋的遷移機制。
Select / Init
挑例子／生起點
Select 每一步挑 5 組洩漏最多的結果當反思例子；Init 由 LLM 依原始指令生出 N 個不同的起點。
Training-5 / Testing-100
訓練集／測試集
搜尋用 5 個基本指令下幾乎不漏的情境；測試用 100 個從 PrivacyLens 隨機抽的情境。
impersonation
假冒
A2 的核心手法：自稱是資料主體，送出假的同意；作者說騙不了人，卻騙得了 LLM agent。
consent forgery
偽造同意
宣稱或捏造「本人已經同意」；A1 開始出現，A2 搭配假冒成為多輪的策略。
state-machine defense
狀態機防守
D2：先查身分、再向本人要同意、等待時只回一句固定的話；只有本人已驗證帳號的回覆能改變狀態。
ICL / strategy guidance
範例轉移／策略指引
把找到的攻擊當範例請 LLM 改寫到新情境；＋SG 再把轉移最成功的策略放進 prompt（第 4.3.2 節）。
sim-to-real
模擬到真實
模擬裡找到的失敗能不能在真實環境重現；v3 用真實信箱試了 5 次，成功 3 次。
helpfulness
有用性
傳送方對良性請求的動作有沒有幫助；D2 只剩 31.2%，加一句提示回到 96.2%（附錄 N）。
PrivacyLens
隱私規範的評測
同一講的必讀；測 agent 在動作裡會不會洩漏敏感資訊。這篇測試集的規範與洩漏偵測都沿用它。
