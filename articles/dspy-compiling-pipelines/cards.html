第 3.3 節的例子：只給問答對與完全相符的 metric，teleprompter 會替 RAG 補上缺的標籤，也就是推理鏈與檢索脈絡。作者說 LM 本身不可靠，但在多階段設計的解空間裡搜尋很有效率：拆得好的程式，總找得到幾筆能通過的訓練例。
下一筆訓練例
三個讓標籤這麼省的前提
① 標籤最多只要最終輸出
訓練集可以只有幾筆，而且只有輸入也行；中間步驟的標籤不需要，除非 metric 要用到。作者通常最多只假設最終輸出有標籤。
新管線只要重新編譯、不用重標資料：作者說這種標籤效率是模組化的關鍵。
② metric 可以是一整個程式
EM、F1 之外可以自訂：例如答案要完全相符，而且要出現在某一段檢索結果裡。metric 也看得到那一次執行的 trace。
作者的建議：答案有沒有忠實依據來源，可以交給另一個 DSPy 程式判斷。
③ 示範是整條一起通過的
篩的是一整次執行，不是每一步各自打分；答案模組的示範裡，放的就是那次真的檢索到的脈絡與寫出的推理。
好壞例子怎麼取捨，作者說都讓使用者控制；一輪收集得不夠，還可以反覆 bootstrap。
注意：七格依附錄 E.1 的簡化虛擬碼畫，分格與順序是整理者排的；實作還會在高溫下多次取樣，trace 以執行緒安全的方式記錄。

BootstrapFinetune：示範變權重
示範不放進 prompt，改拿去更新每個 predictor 背後 LM 的權重；昂貴的程式可以當便宜小模型的老師。
例：Llama2-13b-chat 的 RAG 教 Flan-T5-large，問題不帶標籤。
代價：程式要跑幾千次
較貴的設定是 10 到 20 次試驗、每次跑 150 到 300 筆驗證例；通常幾分鐘到幾十分鐘，可以平行。
ensemble 推論時要把前幾名都跑一次（整理者補充）。
注意：四個候選是示意，實際次數依設定；「前 7 名」是第 6 節 ensemble 用的數字，不是固定規則。實線框表示候選的數量在編譯前就定了。

13 / 13結論：人寫程式與 metric
表現力在可組合的模組與最佳化器
第 8 節：三個新概念、兩個很不一樣的案例，都用相對小的 LM 快速做出有效的系統；作者維護開源版本將近一年，更多任務的受控實驗留給之後
01　把 prompt 當參數
手寫的字串，
就是手調的權重
指令、欄位前綴、示範都是參數；同一份程式換 LM、改管線，重新編譯就好，signature 不用動。就像深度學習不手調權重，而是交給最佳化器去找。
✗ 在程式庫裡替每個資料庫寫死一段 prompt
✓ 宣告做什麼，prompt 交給編譯器產生
02　讓 metric 決定留下什麼
示範是跑出來、
再用 metric 篩過的
標籤最多只要最終輸出；整條管線一起通過 metric 的那幾次，每一步都變成示範。metric 量什麼，編譯就往哪裡走：vanilla 把算式寫進答案欄就是例子。
✗ 為每個中間步驟另外標資料
✓ 把要求寫進 metric，連依據都能檢查
03　比的是程式加策略
「程式 P 用策略 S 編譯」
才是一次可重現的比較
同一個 LM，換成 reflection 或 multihop、換成 bootstrap 或 ensemble，就是另一個系統；Llama2-13b-chat 編譯之後能和 GPT-3.5 相比。
