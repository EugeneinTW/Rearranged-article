MEM0 · SCALABLE LONG-TERM MEMORY · 圖卡＋教材整合版

記憶不靠更長的脈絡， 靠抽出並更新的事實Mem0：每一對訊息先抽出事實， 再和舊記憶比對後寫回

聊天型的 agent 一換 session 就忘了使用者說過什麼；把脈絡視窗加長，只是讓遺忘晚一點發生。這篇 Mem0 團隊的論文提出一套記憶層：每收到一對訊息，先用 LLM 抽出值得記的事實，再和最像的舊記憶比對，由 LLM 決定新增、更新、刪除或不動；圖記憶版本 Mem0g 另把事實存成實體與關係。作者在 LOCOMO 長對話基準上和六類對手比較，說它的品質接近把整段對話塞進脈絡的做法，p95 延遲與 token 卻都少了九成以上。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

記憶也可以放在對話旁邊整理

Stanford CS 329Z 第 4 週「Agent Memory Architectures」那一講，談短期與長期記憶、記憶當成工具動作、檔案系統當外部記憶、結構化記憶，以及跨 agent 的記憶；必讀是 MemGPT。這篇 2025 年的 Mem0 論文是同一講的選讀。

依這篇論文附錄 C 的描述，MemGPT 把 LLM 當成作業系統來設計：脈絡視窗是容量有限的主脈絡（main context），像電腦的記憶體；視窗外還有不限大小的外部脈絡（external context），像硬碟。模型自己發出函式呼叫，去搜尋、取回或修改外部的資料，需要時把它們搬進視窗。記憶怎麼用，由 agent 在自己的迴圈裡決定。

Mem0 走的是另一條路。記憶層跟在對話旁邊運作：每收到一對新訊息，就用 LLM 抽出值得記的事實，再用一次 tool call 決定這條事實要新增、更新、刪除還是不動；回答問題時，再把相關的記憶取回來放進 prompt。它的圖記憶版本 Mem0g，把事實存成實體與關係組成的圖。放回這一講的講題（這是整理者的讀法）：兩篇都把記憶操作做成工具呼叫，差在 MemGPT 讓 agent 自己呼叫，Mem0 把呼叫放在記憶層的更新步驟；Mem0g 是結構化記憶的一個具體做法；兩篇處理的都是跨 session 的長期記憶。講題裡的「檔案系統當外部記憶」與「跨 agent 的記憶」，這篇論文沒有談到。

還有一件事要先說：這是公司寫自家系統的論文。五位作者都是 Mem0 的人，論文標頭只有 Mem0 的標誌與信箱，程式放在 Mem0 的網站上。比較的對手裡有同類的產品：Zep 的記憶平台、LangChain 的 LangMem、ChatGPT 的記憶功能。除了五個已發表的 LOCOMO 結果，其他對手都是作者自己跑的。所以這一頁把作者對自家系統的評價寫成「作者說」，第 7 章逐一交代每類對手怎麼跑，第 13 章把讀這些數字時要記得的條件收在一起。

先把幾個名詞對齊

  • 脈絡視窗（context window）：模型一次能讀進的 token 上限，超過的部分模型看不到。
  • session：一次對話。隔天重開一段對話就是新的 session，模型本身不會記得上一段。
  • 向量搜尋：把文字轉成 embedding 向量，用相似度找出最接近的幾筆。Mem0 找「最像的舊記憶」就靠它。
  • 知識圖（knowledge graph）：用節點表示實體、用帶標籤的邊表示關係；一條邊加上兩端的節點，就是一個三元組。
  • RAG：把文件切塊存起來，提問時取回最相關的幾塊放進 prompt。這篇把整段對話當成文件，拿 RAG 當對手。

Chapter 02 · Proposed Methods: Mem0

記憶存的不是原文，是抽出來的事實

Mem0 以一對訊息為單位增量處理。抽取階段帶著對話摘要與最近 10 則訊息，從新的這一對抽出候選事實；更新階段拿每條事實去比資料庫裡最像的 10 條記憶，再決定怎麼寫回。

第 2 節一開頭說有兩種架構。Mem0 用專門的抽取與更新模組，從對話裡抽出、評估、管理重要的資訊；Mem0g 在同樣的基礎上把記憶存成圖（第 4、5 章）。Mem0 處理的單位是一對訊息，可以是兩位使用者之間的，也可以是使用者與助理之間的。架構是增量的：對話進行到哪裡，記憶就跟到哪裡，不必等整段對話結束。

抽取階段在收到新的一對訊息 (mt−1, mt) 時開始，通常是使用者的一句話加上助理的回應，算是一個完整的互動單位。為了讓抽取有足夠的上下文，系統從兩個地方補脈絡：一是存在資料庫裡的對話摘要 S，涵蓋整段歷史的語意內容；二是最近的 m 則訊息，m 是控制時間窗大小的超參數。三樣東西組成一個 prompt P，交給用 LLM 實作的抽取函式 φ。φ 只從新的這一對訊息裡抽出一組值得記的記憶 Ω = {ω1, …, ωn}，這些是準備進知識庫的候選事實；摘要與最近的訊息只負責讓它看懂上下文。

摘要由一個非同步的摘要產生模組定期更新。它和主流程分開跑，抽取時拿得到較新的摘要，又不會因為重算摘要而卡住。作者這樣分工：S 提供整段對話的主題，最近的訊息補上還沒被整合進摘要、但可能相關的細節。

更新階段逐條處理候選事實，目的是讓知識庫保持一致、不重複。系統先用向量 embedding 從資料庫取出和這條事實語意最像的 s 條既有記憶，再把它們連同事實交給 LLM，由 LLM 決定要執行哪一種操作。四種操作與判斷的順序是下一章的主題。實驗裡的設定是 m = 10、s = 10：抽取時參考前 10 則訊息，更新時比對 10 條最像的記憶。所有 LLM 操作都用 GPT-4o-mini，向量資料庫用 dense embedding 做相似度搜尋。

提醒

Mem0 的刪除是真的刪

Mem0 的 DELETE 會把舊記憶從記憶庫移掉。Mem0g 處理衝突的方式不同：它把過時的關係標成失效、不實際刪除（第 4 章），作者說這樣才能做時間上的推理。第 9 章會看到，時間題是 Mem0g 勝過 Mem0 的一類；不過論文沒有單獨量「標成失效」這個設計的貢獻。

實作上，圖資料庫用 Neo4j；抽取器與更新模組用具備 function calling 的 GPT-4o-mini，從非結構化的文字抽出結構化的資訊。作者的說法是，圖的表示加上語意 embedding 與 LLM 抽取，讓 Mem0g 同時有複雜推理需要的結構，又保有理解自然語言需要的彈性。

Chapter 05 · Mem0g Memory Retrieval

查圖有兩條路：沿實體走，或比三元組

以實體為中心的做法先認出問題裡的實體，再沿著它們的關係展開子圖；語意三元組的做法把整個問題編成一個向量，和每條三元組比相似度。作者說兩條路並用，具體與概念性的問題都能處理。

取回的第一條路以實體為中心。系統先找出查詢裡的關鍵實體，用語意相似度在知識圖裡找到對應的節點，把它們當成錨點，展開進出兩個方向的關係，組成一個涵蓋相關脈絡的子圖。

第二條路是語意三元組，看得比較整體。整個查詢編成一個 dense embedding 向量，和圖裡每一條三元組的文字編碼比對，算出相似度分數，只回傳超過可調門檻的三元組，依相似度由高到低排列。

結論一節重申：Mem0 在單跳與多跳最好，Mem0g 在時間與開放領域有明顯進步，兩者的 p95 延遲都遠低於全脈絡。讀這些數字時，也要記得比較是作者自己設計、自己跑的。

摘要與結論的百分比怎麼對回表格

摘要說 Mem0 的 J 比 OpenAI 相對高 26%，對得上表 2 的整體 J：66.88 對 52.90，整理者算的比值約 1.26；說 Mem0g 比 Mem0 高約 2%，是 68.44 對 66.88。結論的 5%、11%、7% 沒有寫用哪個指標。整理者用表 1 的 J 核對：單跳 67.13 對 63.79 約 5.2%、多跳 51.15 對 47.92 約 6.7%，對得上；時間題 58.13 對 A-Mem* 的 49.91 約 16.5%，對不上 11%。這一頁照抄作者的說法，不替它選指標。

作者點名的後續方向有五個：最佳化圖的操作，降低 Mem0g 的延遲；探索兼顧效率與關係表示的階層式記憶架構；發展受人類認知啟發、更精細的記憶整合機制；把記憶框架延伸到對話以外，例如程序性的推理；以及多模態的互動。

Mem0 和 RAG 差在哪？
RAG 取回的是原文片段；Mem0 先用 LLM 從每一對訊息抽出事實、和舊記憶比對後才存，回答時取回的是這些事實。表 2 裡最好的 RAG 是 60.97，Mem0 是 66.88（第 2、10 章）。
該用 Mem0 還是 Mem0g？
作者說兩者互補：單跳與多跳 Mem0 較好，時間與開放領域 Mem0g 較好。Mem0g 的整體 J 高一些，但每次取回的 token 與延遲也較高（第 9 章）。
為什麼不直接用更長的脈絡視窗？
作者認為那只延後問題：對話終究會超過上限，關鍵資訊也會被無關內容埋住。全脈絡在 LOCOMO 上最準，但 p95 總延遲約 17 秒（第 1、11 章）。

Reference · 名詞速查

關鍵名詞與它們在論文裡的位置

先列兩個架構與它們的零件，再列評估用的資料集與指標，最後是比較的對手。

Mem0
記憶層
以一對訊息為單位，先抽出事實、再比對舊記憶決定寫法的長期記憶架構（第 2.1 節）。
Mem0g
圖記憶版本
在 Mem0 之上把記憶存成實體與關係的有向標籤圖；原文寫成 Mem0 加上標 g（第 2.2 節）。
extraction phase
抽取階段
用對話摘要、最近 m 則訊息與新的一對訊息組成 prompt，讓 LLM 抽出候選事實。
update phase
更新階段
每條候選事實取 s 條最像的記憶，交給 LLM 選一種操作寫回。實驗用 m＝10、s＝10。
conversation summary
對話摘要 S
涵蓋整段歷史的摘要，由非同步模組定期更新，抽取時當全局脈絡。
ADD／UPDATE／DELETE／NOOP
四種更新操作
新增、以資訊更多的版本取代、刪除被矛盾的記憶、不動（附錄 B 的 Algorithm 1）。
tool call
工具呼叫
原文對 function calling 介面的稱呼；更新階段靠它讓 LLM 選操作。
directed labeled graph
有向標籤圖
G＝(V, E, L)：節點是實體，邊是關係，標籤是實體的型別。
triplet
三元組
（來源實體, 關係, 目的實體），例如 (Alice, lives_in, San_Francisco)。
entity extractor／relationship generator
實體抽取器／關係產生器
Mem0g 兩段式抽取：先找實體與型別，再判斷實體兩兩之間的關係並貼標籤。
conflict detector／update resolver
衝突偵測／更新解析器
找出和新資訊衝突的舊關係，由 LLM 判斷哪些過時並標成失效，不刪除。
entity-centric retrieval
以實體為中心的取回
認出查詢裡的實體，對到節點後沿進出的邊展開子圖。
semantic triplet retrieval
語意三元組取回
整句查詢編成向量，和每條三元組的文字編碼比相似度，回傳超過門檻者。
LOCOMO
長對話記憶基準
10 段長對話、每段平均約 26,000 token；本篇用其中四類問題，排除對抗題。
single-hop／multi-hop／temporal／open-domain
四類問題
單一回合的事實、跨 session 的整合、事件的時間與順序、需要外部知識的開放題。
LLM-as-a-Judge（J）
LLM 評審
由另一個 LLM 判斷答案 CORRECT 或 WRONG；每個方法評 10 次，報平均與標準差。
F1／BLEU-1
詞彙重疊指標
數預測與標準答案重疊的詞；答錯細節時也可能拿高分，表中寫 F1、B1。
full-context
全脈絡
每次回答都把整段對話放進脈絡視窗；表 2 裡 J 最高，延遲也最高。
p50／p95
中位數／尾延遲
一半的請求比 p50 快，95% 的請求比 p95 快；表 2 對搜尋與總延遲各報一組。
chunk size／k
塊大小／取回塊數
RAG 對手的兩個設定：128 到 8192 token，k 為 1 或 2，共 14 組。
MemGPT
作業系統式記憶
同一講的必讀；依附錄 C，模型用函式呼叫在主脈絡與外部脈絡之間搬資訊。
A-Mem
筆記式 agent 記憶
把記憶做成彼此連結、會更新的筆記；本篇以溫度 0 重跑它得到 J（A-Mem*）。
Zep／LangMem
記憶平台／開源記憶庫
兩個對手：Zep 是商用的 agent 記憶平台，LangMem 是 LangChain 的開源方案（Hot Path 模式）。
