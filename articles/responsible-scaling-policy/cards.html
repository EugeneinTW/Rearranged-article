03 / 10部署風險與圍堵風險
部署管用它的風險，圍堵管持有它的風險
1.0 的框架把每一級要處理的風險分成兩類，各配一類措施：部署措施決定何時可以部署，圍堵措施決定何時可以訓練或繼續訓練
DEPLOYMENT RISKS
部署風險：來自使用模型
CONTAINMENT RISKS
圍堵風險：光是持有就有風險
外部使用者
透過 API 或其他公開介面造成傷害
內部使用者
帳號被入侵，或本身有惡意
部署措施
例：模型卡、使用政策、紅隊、自動偵測
決定：什麼時候可以部署
部署措施管的是模型的輸出：對外的 API 與對內的使用都算，
而且上一級的部署措施要一起做到。
權重被偷
落到惡意者手上，被用於大規模破壞
內部使用時自主逃脫
模型在內部使用期間脫離控制
圍堵措施
例：保護權重、內部分隔
決定：何時可以訓練或續訓
圍堵措施管的是權重在哪裡、誰拿得到：光是存放權重就要做，
所以要在訓練之前先到位。
災難的定義
由 AI 模型直接造成、沒有它就不會發生的
大規模破壞，例如數千人死亡，
或數千億美元的損失。
間接的社會影響重要，但不在這份文件的範圍。
兩個來源：濫用與自主
濫用：有人刻意拿模型造成大規模傷害。
自主與複製：模型自行擴散，
行為違背設計者的意圖。
政策說理解加深之後，會再修正這兩類。
不在範圍的事
錯誤資訊、偏見、毒性、社會影響、隱私、
可靠性由其他工作處理；
也不改變 Claude 當時的用法。
發布文：不影響現有產品的供應。
注意：兩類都要管，政策沒有偏好哪一邊，所以這張不用 ✗／✓；把兩類畫成左右並排、各配一個決定，是整理者依框架一節的說法排的。

10 / 10讀政策的三個問題
讀政策照三個問題走：誰承諾、何時觸發、誰查核
三條讀法與五步順序是整理者依前面九張卡歸納的；讀完 1.0，再讀政策頁上現行的 3.4 版
01　分清強度
承諾、應該、預期，
是三種不同的話
commit 是承諾，should 是標準，
expect 與 early guess 是預期和猜測；
ASL-4 那一節整段是猜測。
✗ 把猜測讀成承諾
✓ 每一句先標出強度
02　找條件句
每條承諾都是
「如果…就…」
評估碰到警訊，就啟用措施或暫停；
紅隊引得出來，就不部署。
再找例外：評估太保守、極端緊急。
✗ 只讀措施清單
✓ 先找什麼情況會啟動它
03　找查核的人
違反的時候，
誰會知道？
負責人每季報告、董事會核准、
LTBT 事先諮詢、部署後公開結果；
看得到的承諾才查得了。
✗ 只看寫了什麼
✓ 也看誰會發現沒做到
