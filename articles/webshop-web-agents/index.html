一家模擬的網路商店， 考語言代理 會不會照指令買東西WebShop：118 萬件真實商品、12,087 條人寫的指令，獎勵由程式自動算

要讓語言模型學會在網頁上做事，得先有一個夠大、語言夠真實、又不必請人逐次打分的練習場。這篇 Princeton 團隊的論文從 Amazon 爬下一百多萬件商品、請工人寫了一萬兩千多條購物指令，做成一個模擬的購物網站：代理照指令搜尋、點選、選好選項再買下，獎勵由程式比對算出。作者先讓模型模仿人類示範、再用強化學習微調，最好的模型成功率 29.1%，人類專家是 59.6%；模型不另外訓練，也能直接到 Amazon 與 eBay 上操作（sim-to-real）。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

先有能自動評分的考場，才練得出網頁代理

Stanford CS 329Z 第 11 週「Frontiers & Open Problems」那一講（Open Problems & Final Demos 分區，也是課程的最後一講），談多模態 agent、web agent 與電腦操作、科學 agent、長時間執行的 agent 架構、上線與可觀測性（tracing、監控、成本管理），以及可靠度、擴展性、可解釋性的開放問題。這一講沒有必讀，提出 WebShop 的這篇論文是兩篇選讀之一。

同一講的另一篇選讀是 Xie 等人的〈OSWorld: Benchmarking Multimodal Agents for Open-Ended Tasks in Real Computer Environments〉。本頁的論文全名是〈WebShop: Towards Scalable Real-World Web Interaction with Grounded Language Agents〉。

整理者對照了作者名單與課程頁：第三作者 John Yang 是這門課的講師；共同第一作者之一的 Shunyu Yao 是本站整理過的〈ReAct〉的第一作者，ReAct 就拿 WebShop 當評估環境之一；這個研究群後來也做了本站整理過的〈SWE-bench〉。

先把幾個名詞對齊

  • POMDP：部分可觀察的馬可夫決策過程。代理每一步看到一個觀察、選一個動作，環境換到下一個狀態，最後給一個獎勵；「部分可觀察」表示有些東西代理看不到，在這篇裡就是商品隱藏的屬性。
  • BM25：一種老牌的關鍵字檢索排序法，看查詢裡的詞在文件裡出現多少、有多罕見。
  • BERT、BART：兩種預訓練的 Transformer 語言模型。BERT 擅長把一段文字編碼成向量，這篇用它替按鈕打分；BART 能產生文字，這篇用它寫搜尋查詢。
  • beam search：產生文字時同時保留好幾個最有希望的候選，最後可以一次拿到前幾名。
  • policy gradient：一種強化學習的訓練法，拿到的獎勵高，就把當時選的動作的機率調高。

引言從兩類研究的落差講起。一類是會用語言做連續決策的代理，它們的任務語言概念有限，也很難放大；另一類是 GPT-3、BERT 這類大型語言模型，在文字分類、資訊擷取、問答這些傳統基準上表現很好，但那些基準是靜態、不互動的資料集，語言沒有對應到語言以外的東西。作者認為，要讓有 grounding 的語言模型再往前走，需要可以放大的互動環境，而且要同時具備兩個條件。第一，環境裡的語言反映真實世界的用法，也能大量收集。第二，任務回饋要定義清楚、能自動算，不必一直請人付出昂貴的評分。第二個條件，引言是這樣寫的：

"task feedback that is well-defined and automatically computable" 「定義清楚、能自動算出來的任務回饋」。第 1 節列出的第二個條件。

全球資訊網天生滿足第一個條件：它是一個巨大的開放領域互動環境，一頁頁互相連結，上面有自然的文字、圖片與可以操作的元素。作者特別點出網頁同時具備五個性質：可以放大、有語意、能互動、會變動、夠真實，這讓它和遊戲、3D 導航這類既有的代理環境很不一樣。網頁也是能直接部署代理的地方，買東西、預約這類繁瑣的事都可能交給代理做。

問題在於既有的網頁任務。作者說它們不是在狀態轉移與動作空間上不夠深，就是很難放大：有的只有一個分類任務，有的每回合只有少數幾個頁面（World of Bits）；有的回合比較長，卻只能沿著超連結走（WikiNav）；有的沒有自動算的獎勵，只好讓人在迴圈裡給回饋（WebGPT）。第 12 章會把這些工作放回相關研究裡再看一次。

WebShop 模擬的是在電商網站上購物：代理要讀懂一條人寫的文字指令，買到符合規格的商品。它要使用網站的搜尋引擎、從結果裡挑商品點進去、讀描述與細節，再選好必要的選項（例如 32 盎司、紅色）才按下購買；為了挑到最好的那件，可能要比較好幾件商品、在頁面之間來回，也可能要搜好幾次。環境裡有從 amazon.com 爬下的一百多萬件商品、一萬兩千多條群眾外包的指令，動作是「輸入搜尋文字」與「點文字按鈕」兩種；它包成 OpenAI Gym 的環境，可以用 HTML 或 simple 兩種模式呈現。獎勵由一組程式比對商品的屬性、類型、選項與價格算出，不需要人評分，互動學習因此可以放大。

引言也先預告了結果：作者用模仿學習與強化學習訓練代理，最好的代理平均 62.4 分、成功率 28.7%，規則基線是 45.6 分、9.6%，人類專家可以到 82.1 分、59.6%。一個註腳補充，這個任務需要耐心與一致性，部分群眾外包工人缺乏這兩點，分數因此較低；即使如此，人和模型的差距仍然明顯。這些結果放在第 8 章；把代理直接搬到 Amazon 與 eBay 的實驗放在第 11 章。

第 3 節先交代設計原則：網站怎麼換頁，和指令、獎勵這些跟任務有關的部分分開寫，所以要換成新任務或新領域很容易。第 3.1 節再把 WebShop 寫成一個部分可觀察的馬可夫決策過程，組成是狀態、動作、確定性的轉移函式、值在 0 到 1 之間的獎勵函式、指令空間與觀察空間。

一個狀態就是一個網頁，分四種：有搜尋框的搜尋頁、列出搜尋結果的結果頁、描述一件商品的商品頁，以及顯示更多資訊的商品細節頁（圖 1A 的 1 到 4）。每件商品有幾個欄位：標題、描述、概覽合成的文字、價格、一組購買選項、一組圖片（每張對應一個選項），以及一組代理看不到的屬性。屬性從標題與細節頁抽出來，只用來算獎勵（第 3 章）。

第 3.1 節用一條指令當例子：「能幫我找一雙黑藍色、下雨天也好穿的球鞋嗎？鞋底要蓬鬆，價格低於 90 美元。」（整理者的中文轉述）。它藏著的屬性是 waterproof 與 soft sole，選項是「顏色：黑藍」。指令的說法和屬性的寫法並不相同，「下雨天也好穿」要對到 waterproof，「鞋底要蓬鬆」要對到 soft sole；代理得自己把兩邊接起來。這條指令的分母是 2＋1＋1＝4（整理者算的），買到的商品每對上一格，獎勵就多四分之一，再乘上類型分。

為什麼要乘類型分？作者的例子是奶油與植物肉：兩者類型明顯不同，卻可能都標了「cruelty-free」「non-GMO」兩個屬性，也都有「size: pack of 2」這個選項。只看屬性與選項，買錯東西也能拿高分；類型分就是用來壓低這種情況。附錄 A.5 說類型分由三個元素決定：粗的類別有沒有對上（就是前面的 5 個大類，記為 c），細的類別有沒有對上（Amazon 網站上的類別鏈，例如眼膜貼會落在「美妝個人護理 > 護膚 > 眼部 > 除皺貼片」，記為 f），以及標題比對。式 6 照原文列出如下：

整理者的讀法

分數給部分分，成功率只看全對

同一個代理，分數可以很高、成功率卻很低：每次都買到類型對、價格對、屬性大多對，但選項沒選對的商品，就會落在這種情況。第 9 章把分數拆成四項，看的正是差距出在哪一格。

思考題 · 01

你的代理任務，「對了一半」要算幾分？

想一個你在做的代理任務：它的結果能不能拆成幾個可以各自比對的要求？哪一項錯了就該整題歸零，就像 WebShop 用類型分壓低買錯東西的情況？

可以先列出三到五個要求，再決定哪些是加分的格子、哪些是乘上去的閘；同時報一個「全對的比例」，才不會被部分分蓋掉問題。這是整理者的建議。

先看最簡單的對照。第 4.1 節的規則基線直接拿指令原文去搜，選結果頁的第一件商品就買，不選任何選項。字面比對的搜尋引擎幫了很多忙，所以它也是一個不需要學習的資訊檢索基線，屬性分數不會太低；但簡單的規則處理不了用自然語言寫的選項，不會探索，也學不會該搜什麼，所以總獎勵與成功率都應該很低。

學習的代理由兩個預訓練語言模型分工，分別從人類示範學「怎麼搜」與「怎麼選」。搜尋被當成一個序列到序列的文字生成問題：代理只看指令、不看任何其他脈絡（例如過去的搜尋、看過的商品），產生一個 search[…] 動作。作者從 1,012 條訓練用的人類軌跡取出 1,421 組「指令與搜尋」配對，微調一個 BART 模型，訓練目標是在指令之下產生人類那個查詢的機率越高越好。

選擇模型（圖 3）要在觀察 o 裡所有可點的動作中給出一個機率分布，訓練目標是讓人類實際點的那個按鈕機率最高。作者從訓練軌跡整理出 9,558 筆樣本。觀察先用一個 12 層的預訓練 BERT 編碼成一串詞的向量，每個動作的文字也用同一個 BERT 編碼；每個動作的表示和觀察的表示做交叉注意力，平均成一個向量，再乘一個矩陣得到一個分數，所有動作的分數取 softmax 就是策略。附錄 B.1 說交叉注意力的算法照 Seo 等人的做法：先算觀察每個詞和動作每個詞之間的注意力，得到「看過觀察的動作詞向量」，再平均成這個動作的分數。

def act(page, instruction):
    if page.kind == "search":                                 # 只有搜尋頁能搜
        queries = bart.beam_search(instruction, top=5)          # 只看指令

你的代理，會不會也太早下決定？

安全的做法

在真實網站上只讓代理導覽

附錄 E 說，初步的搬遷實驗裡，代理只能用兩種固定、安全的方式更新網址：搜尋結果、打開一件商品。會送出表單的動作（點選項、購買）都留在翻譯介面裡，等之後算獎勵用；真實網站上只發生導覽。作者也說，將來要在功能更多的真實網站上部署，先把模型可以做哪些事寫清楚，是避免有害行為的關鍵。

Chapter 12 · Related Work

既有的網頁任務，不是太淺就是要人評分

作者把 WebShop 放在三條研究線上：網頁上的強化學習、不互動的網頁任務、拿網頁做傳統 NLP。和它最接近的兩個工作是 Klarna 的商品頁資料集與 WebGPT：前者只做一次決定的監督式分類，後者要人在迴圈裡評分。

第一條線是網頁上的強化學習。Nogueira 與 Cho 的 WikiNav 讓代理在頁面之間導覽，但任務純粹是導覽，動作只有點一個超連結或停下。World of Bits 讓強化學習代理用像素與 DOM 觀察在網頁上完成任務；之後有好幾篇研究用各種技巧挑戰它的簡化版 MiniWoB，包括工作流程引導的探索、課程與元學習、DOM 樹表示、對抗式的環境生成，以及大規模的行為複製。作者說 MiniWoB 缺少跨多個頁面的長程決策，而且動作是低階的滑鼠點擊與按鍵，難度與規模都不容易放大。WebShop 則要走更長的路徑、依脈絡選動作、會回頭，動作是高階的搜尋與點選，比較能放大，也比較能搬到真實情境。AndroidEnv 與 MoTIF 不直接操作網頁，而是讓代理在手機平台上和 app 與服務互動。

第二條線是不互動的網頁任務：預測網頁元素、產生 API 呼叫、把指令剖析成概念層級的導覽動作等監督式分類任務。內容上最接近的是 Klarna 的商品頁資料集，5 萬多個商品頁標了不同的元素類別，用來做監督式分類。作者說這些工作都只考慮只做一次決定的監督式設定，而且可能要替每個領域定義網頁 API 或指令範本；WebShop 則把有真實文字與圖片的網頁，和一個豐富多樣、需要長程連續決策的互動空間結合起來。

第三條線是拿網頁做傳統的 NLP 任務：資訊擷取、檢索、問答、對話，以及用網頁文字訓練語言模型。這些做法主要把網頁搜尋引擎當成知識檢索器，替手上的任務收集更多證據。最接近 WebShop 的是 WebGPT，它用一個整合了搜尋引擎的網頁介面，訓練強化學習代理瀏覽網頁、回答問題；作者說 WebShop 的動作與觀察空間更多樣（包含圖片），而且不需要人在迴圈裡評估。

附錄 E 談社會影響與限制，分成四項：

Data

資料的代表性

選了 amazon.com 上五個常見的大類，爬遍所有子類別以減少偏差；但資料仍偏向網站所在的國家（美國）與語言（英文），也只代表使用者可能想買的商品的一部分。作者說商品資料可以替換，換成其他的代表性。

Labels

標註的偏誤

屬性目前靠人工標註，可能受標註者自己的經驗影響（例如比較懂運動用品、不懂彩妝）。自動的替代做法是用訓練好的 NLP 模型（例如關係擷取）抽屬性；獎勵的設計也可以改權重，偏重屬性、選項或價格。

Safety

網頁代理的安全

和直接把代理放上網路的 WebGPT 不同，WebShop 想提供一個可控、安全的模擬環境。真實網站的實驗只做導覽，表單動作都留在介面裡（第 11 章）。

Task

任務的語意

指令受限於用到的屬性與選項：屬性簡單、有時太泛（例如 easy to use），選項有時又太細（例如 d17(dedicated right, back)），代理可能拿一個特殊的選項當線索找商品，忽略指令的其他部分。

最後一項也點出作者的下一步：更充分地利用商品的圖片與文字（包括這篇沒有用到的使用者評論），寫出更有語意、更有挑戰的指令，是 WebShop 之後重要的方向。附錄 D.2 的最後一段也說，人和模型的差距，促使他們去擴充模型與環境目前的限制。

WebShop 的商品與指令是真的嗎？
商品是從 amazon.com 爬下的真實資料，指令是 Mechanical Turk 的工人看著一件真實商品寫的；網站本身是作者用 Flask 架的模擬環境，代理在裡面按下購買只會結束回合、算出獎勵（第 3 節、第 3.1 節）。
模型看得到商品圖片嗎？
看得到。選擇模型把 ResNet-50 的圖片特徵接在文字表示後面；但指令與獎勵只用文字，拿掉圖片分數只小降、變異變小（第 4.2 節、附錄 C.4）。
程式、資料與示範公開了嗎？
論文首頁的註腳列了專案網站，說程式、資料與示範都在那裡；Checklist 也說重現主要結果需要的程式、資料與說明附在補充材料裡。
思考題 · 03

如果要把你們的網站做成代理的練習場，哪些欄位適合藏起來當答案？

想想你們的商品頁、文件頁或後台：哪些資訊代理看不到，卻能拿來自動判斷它有沒有做對？指令又該由誰、看著什麼來寫？

可以照 WebShop 的做法先抽一個目標，再讓人看著它寫指令，答案就保證存在；也要先想好同義詞的問題，第 5 章看到完全比對會讓分數偏低。這是整理者的建議。

WebShop 把「會不會逛網頁」拆成可以自動打分的幾件事：搜得到、看得懂、選得對，也肯回頭。 整理自第 3、5 節

Reference · 名詞速查

關鍵名詞，和它們在論文裡的位置

先列環境與資料，再列獎勵與指標、模型，最後是分析與實驗用的名詞。

WebShop
模擬購物網站環境
1,181,436 件 Amazon 商品、12,087 條指令；代理要照指令搜尋、點選並買下商品（第 3 節）。
POMDP
部分可觀察的馬可夫決策過程
狀態、動作、轉移、獎勵、指令、觀察六個部分；屬性是代理看不到的那一塊（第 3.1 節）。
page types
四種頁面
搜尋頁、結果頁、商品頁、商品細節頁；每個狀態就是其中一種（第 3.1 節、圖 1）。
search[ ]、choose[ ]
兩種動作
搜尋只在搜尋頁能用，其他頁只能點文字按鈕；表 1 列出全部的按鈕與換頁（第 3.1 節）。
HTML mode、simple mode
兩種觀察模式
前者給人在瀏覽器裡操作，後者去掉中繼資料只留文字與按鈕，模型都用後者（第 3.1 節）。
attribute
屬性
描述商品性質的短語，用雙詞 TF-IDF 挖出再人工挑，共 670 個；藏起來，只給獎勵用（第 3.2 節、附錄 A.2）。
option
選項
購買時要選的欄位與值，例如顏色；全部商品有 842,849 個不同的選項（附錄 A.1）。
instruction
指令
工人看著一件目標商品寫的一句話，藏著一組屬性、一組選項與一個價格上限（第 3.1、3.2 節）。
reward（式 1）
獎勵
對上的屬性、選項與價格格數除以總格數，再乘類型分；按下購買時算一次（第 3.1 節）。
r_type、TextMatch
類型分
看粗類別、細類別與標題名詞的比對，取 0、0.1、0.5 或 1，壓低買錯東西的情況（附錄 A.5）。
Task Score、SR
分數、成功率
平均獎勵乘以 100；獎勵等於 1 的回合比例（第 3.1 節）。
reward verification
獎勵驗證
各抽 100 條軌跡由人重評、同義詞算對；自動分數偏低，像一個下界（附錄 A.7）。
human expert
人類專家
13 位合格工人中表現前 50% 的 7 位；測試集 82.1 分、成功率 59.6%（附錄 A.6、圖 4）。
rule baseline
規則基線
拿指令原文去搜、買第一件、不選選項；45.6 分、成功率 9.6%（第 4.1 節、圖 4）。
IL
模仿學習
BART 學人類的查詢（1,421 組），BERT 學人類點的按鈕（9,558 筆）；59.9 分、29.1%（第 4.2 節）。
IL+RL
模仿後再強化學習
凍住 BART、用前 10 個查詢當選項，只用 policy gradient 調選擇模型；62.4 分、28.7%（第 4.3 節）。
LP
語言預訓練
language pretraining；選擇模型不用預訓練權重時成功率掉了將近三分之二（第 5.2 節）。
attention fusion
交叉注意力融合
把按鈕的表示和觀察的表示做交叉注意力、平均，再算出一個分數（第 4.2 節、附錄 B.1）。
Pyserini、BM25
搜尋引擎
離線建好的 BM25 索引，結果固定；每次取前 50 件，分 5 頁（第 3.2 節、附錄 A.3）。
Choice oracle
選擇的對照組
看得到隱藏的屬性與獎勵，對每件結果試遍選項組合；v4 的成功率 84.2% 到 87.8%（第 5.3 節）。
sim-to-real
搬到真實網站
不再訓練，用一層翻譯到 Amazon 與 eBay 上操作；IL＋RL 在 Amazon 65.9 分、25%（第 5.4 節）。
trajectory
軌跡
一個回合裡依序做的動作；表 2 統計每回合經過的狀態、看過的商品與搜尋次數。
