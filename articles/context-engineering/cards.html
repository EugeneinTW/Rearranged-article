反覆的任務：每一輪都挑一次

03 / 10注意力是有限的預算
注意力是預算，context 越長分得越薄
n 個 token 之間有 n² 組兩兩關係；context 變長，模型掌握這些關係的能力就被拉薄，關鍵資訊越來越難準確找回

context rot
是漸層，不是懸崖：長 context 下模型仍然很能幹，但檢索與長距推理的精準度下降；每個模型都有，只是有的退得比較緩
成因 ① 架構
n² 組兩兩關係
transformer 讓每個 token 都注意整段 context 的每一個 token；n 個 token 就有 n² 組關係，越長越照顧不過來。
context 的大小和注意力的集中，天生互相拉扯。
成因 ② 訓練
短序列見得多，長依賴練得少
注意力模式從訓練資料學來，而資料裡短序列比長序列常見；跨整段 context 的依賴，模型經驗少、專門的參數也少。
注意力的樣子，是從資料分布學來的。
成因 ③ 延長手法
位置編碼內插的代價
把長序列調整到原本訓練時的較短長度來處理，讓模型撐得住更長的輸入；代價是對 token 位置的理解變差。
三者加起來：表現逐步下滑，不會突然失效。
注意：分段條是整理者的示意畫法，原文沒有畫圖也沒有給數字；原文的結論是把 context 當成邊際效益遞減的有限資源。

太空泛 · 高層的指引
一端 · 太具體
把 if-else 寫進 prompt，
想逼出精確的行為
若問退款且訂單 ≤ 30 天 → 直接退；
若 31 到 45 天 → 先問原因；其餘 → 拒絕……
把複雜又脆弱的判斷邏輯寫死在 prompt 裡，換一時的精確。規則越寫越多，系統越脆弱，維護也越來越複雜。
✗ 脆弱；時間一久，維護成本一直往上

確認不了，就說明還需要哪些資訊。

長任務的技巧，看任務的特性挑
長任務要連續工作數十分鐘到數小時，token 總數超過 context window；原文判斷任何大小的視窗都會遇到 context 污染
超過視窗的長任務
遷移、研究專案
這個任務
長什麼樣？
來回很多的對話
有里程碑的迭代
平行探索的研究
壓縮：摘要後，帶著摘要開新視窗
保住對話的連續；留下決策與未解的 bug，丟掉重複的工具輸出（第 08 卡）
結構化筆記：寫到視窗外，重置後讀回
追蹤進度與依賴；待辦清單、NOTES.md、memory tool（第 09 卡）
子 agent：各自在乾淨的視窗裡深挖
探索的細節留在子 agent，主 agent 只收精煉的摘要（第 10 卡）
共同目標
在 token 超過視窗的任務上，維持連貫、保住脈絡、持續朝目標行動
三個前提
等更大的視窗不是解法
可預見的未來，各種大小的視窗都會遇到 context 污染與資訊相關性的問題，至少在要求最好表現時是這樣。
所以技巧要直接對付污染本身。
長任務長什麼樣
連續數十分鐘到數小時的工作，例如大型程式庫遷移、完整的研究專案；整串動作的 token 數超過視窗。
動作一長串，目標要一路撐住。
模型變強也不會消失
在長時間的互動裡維持連貫，仍會是做出更有效 agent 的核心挑戰。選哪一種技巧，取決於任務的特性。
這是原文長任務一節的結語。
注意：三個出口是原文舉的例子，說明各技巧最擅長哪一類任務；原文沒有給更細的判準。

壓太兇

拿複雜的 agent trace 來調壓縮用的 prompt：先確定每一條相關資訊都留下了，再一輪一輪刪掉多餘的內容。
原文給實作壓縮系統的工程師的建議。
最輕的一刀：清掉工具結果
深埋在歷史裡的工具呼叫，agent 不需要再看一次原始結果。這是最安全、最輕量的壓縮之一，Claude Developer Platform 已做成功能。
先從這種明顯多餘的內容下手。
高保真地蒸餾
壓縮要把一個視窗的內容高保真地濃縮，讓 agent 在表現幾乎不下降的情況下接著工作；它通常是第一個拉的槓桿。
換到的是長時間的連貫。

三個例子
① 待辦清單與 NOTES.md
Claude Code 會建立待辦清單追蹤進度；自訂的 agent 可以維護一份 NOTES.md。幾十次工具呼叫之後，關鍵的脈絡與依賴還在。
最簡單的形式：一個檔案。
② 寶可夢 agent 的計數
在幾千步的遊戲裡記下「過去 1,234 步在 1 號道路練等，皮卡丘升了 8 級，目標 10 級」。沒人教它記憶該長什麼樣，它自己畫地圖、記成就、寫戰術。
context 重置後讀回筆記，接著跑好幾個小時。
③ memory tool
隨 Sonnet 4.5 推出，在 Claude Developer Platform 公開測試：用檔案在視窗外存取資訊，跨 session 維持專案狀態、累積知識庫。
參照過去的工作，不必全留在 context。
注意：原文沒有規定多久寫一次筆記、寫多少；六個步驟是整理者依原文的描述切的。

子 agent · 深入的技術工作

子 agent · 另一個聚焦任務
各自的探索脈絡互相隔離
交回：精煉摘要，常見 1,000–2,000 token
主 agent：綜合與分析
只讀每個子 agent 交回的摘要
關注點分離
詳細的搜尋脈絡隔離在子 agent 的視窗裡；主 agent 的 context 只放摘要，專心綜合。虛線框表示子任務由主 agent 依計畫派出。
數萬 token → 1,000–2,000
每個子 agent 可以大量探索，用掉數萬 token 甚至更多；交回主 agent 的，只有濃縮、精煉過的工作摘要。
主 agent 的 context 不會被搜尋過程塞滿。
