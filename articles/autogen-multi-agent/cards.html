03 / 13收到就回：自動回覆推動對話
收到就自動回覆，對話一路推進到終止條件
第 2.2 節與圖 2：代理收到訊息就自動呼叫 generate_reply，把回覆送回發訊者；回覆函式註冊好、開了頭，流程就由對話帶出來，不需要控制平面
Step 1　開頭
A.initiate_chat(任務, B)
開發者寫的最後一行
Step 2　B 收到
receive 觸發自動回覆；
先看終止條件成立沒有
Step 3　B 回覆
generate_reply：LLM 寫程式
內建的 LLM 回覆函式
Step 4　A 收到
同樣觸發自動回覆；
收到的是 B 寫的程式
Step 5　A 回覆
reply_func_A2B：先問人，
人沒輸入就執行程式碼
Step 6　終止了嗎？
TERMINATE 或次數上限
每次收到都檢查
結束
對話紀錄就是結果；
例如股價圖畫好了
是
開發者只寫了三件事：定義兩個代理、替 A 註冊一個回覆函式、用 initiate_chat 開頭。之後每一則訊息都由收到它的代理自動回覆，沒有另一個模組在排誰先誰後。
圖 2 的例子：B 寫出畫股價圖的程式 → A 執行，回報沒有安裝 yfinance → B 回覆先用 pip 安裝再執行 → A 再執行……
否：結果送回 B，下一輪
讓流程自己跑起來的三個前提
① 統一的介面
每個代理都用 send、receive 收發訊息，用 generate_reply 產生回覆；介面相同，任何代理都能和任何代理對話。
作者說這是去中心化、模組化、統一的定義流程方式。
② 回覆函式決定行為
內建的回覆函式有 LLM 推論、執行程式或函式、人的輸入；也能註冊自訂的，例如先和另一個代理聊過再回覆。
沒註冊時，用一組預設的回覆函式（圖 2 的註記）。
③ 停在哪裡要先寫好
流程靠收到就回推進；終止條件可以是 LLM 依指示回覆 TERMINATE，或 Python 設的條件，例如自動回覆的次數上限。
圖 13 的兩代理對話，一直道歉到次數上限才停。
注意：步驟依圖 2 的例子畫（A 是 UserProxyAgent、B 是 AssistantAgent）；終止檢查其實每次收到訊息都會做，這裡只畫一次。
04 / 13流程寫在 prompt，也寫在程式
流程可以寫在 prompt 裡，也可以寫在程式裡
第 2.2 節：自然語言與程式語言一起管控制流程，兩者之間還能互相轉手；附錄 C 的預設 system message（v0.1.1）就是用自然語言寫流程的例子
NATURAL-LANGUAGE CONTROL
自然語言：寫在 system message
PROGRAMMING-LANGUAGE CONTROL
程式語言：寫在設定與回覆函式
角色扮演
你是有幫助的 AI 助理，用寫程式與語言的能力解題
控制流程
需要資訊時、結果有錯時、找到答案時……各接一個該做的動作
限制輸出
程式放進標明語言的區塊；一次一個區塊；最後回 TERMINATE
協助自動化
使用者只能執行、不能改程式：給完整的程式，用 print 輸出
接地
用程式把資訊印出來；檢查執行結果；驗證答案、附上證據

human_input_mode

能不能執行程式、怎麼執行

LLM 設定
建構代理時指定用哪個模型與推論設定
第 2.2 節與附錄 B.1：這些在建構代理時用 Python 指定；圖 2 的 reply_func_A2B 就是註冊的回覆函式。
互相轉手
程式 → 自然語言：在自訂回覆函式裡，呼叫一次含控制邏輯的 LLM 推論　·　自然語言 → 程式：LLM 提議函式呼叫，交給程式執行
LLM 不會每條都照做

所以系統要有其他機制處理例外與錯誤。
Python 管得到的部分
終止條件、人類輸入模式、工具執行的邏輯都能用 Python 指定；註冊的回覆函式能用程式控制對話怎麼走。

03　自主程度可調
