文件開頭先替 Claude Code 定位：它是一個 agentic coding 的環境。聊天機器人回答完問題就停下來等你；Claude Code 會讀你的檔案、跑指令、改程式，自己把問題做完，你可以在旁邊看、中途改方向，或乾脆走開。工作方式也跟著變：不再是你自己寫、請 Claude 審，而是你描述想要什麼，由它探索、規劃、實作。文件也說這份自主有學習曲線，Claude 在一些限制裡工作，你得先懂這些限制。它說這份指南整理的，是在 Anthropic 內部團隊，以及在各種 codebase、語言、環境裡使用 Claude Code 的工程師身上證明有效的模式。

文件說多數做法都建立在一個限制上，就是 context window。它裝著整段對話：每一則訊息、Claude 讀過的每一個檔案、每一次指令的輸出。它滿得很快，一次除錯或一次探索 codebase，就可能產生並用掉數萬個 token。滿了之後表現會變差，Claude 可能開始「忘記」前面的指示，或犯更多錯。文件因此把 context window 當成最需要管理的資源，並建議用自訂的 status line 隨時看用量。

"Claude's context window fills up fast, and performance degrades as it fills." 「Claude 的 context window 滿得很快，而且越滿表現越差。」這是文件開頭點出核心限制的那一句。

給初學者

先把五個名詞對齊

  • Token：模型讀寫文字的單位；context 的長短用 token 數來算。
  • Context window：Claude 這一刻看得到的全部內容，包括你的訊息、它讀的檔、指令的輸出；有上限。
  • Session：一段和 Claude Code 的對話；可以清空、壓縮、倒回，也可以之後接著做。
  • Agentic coding：模型不只回答，還會自己讀檔、跑指令、改程式，直到把事情做完。
  • Slash 指令：在 Claude Code 裡以斜線開頭的指令，例如 /clear、/compact、/rewind。

讓 Claude 直接開始寫程式，寫出來的程式可能解的是錯的問題。文件建議用 plan mode 把探索和執行分開：在 plan mode 裡，Claude 讀檔、回答問題，但不做任何修改。它推薦的流程有四個階段。

1

2
規劃請它寫一份詳細的實作計畫。按 Ctrl+G 可以在你的文字編輯器裡直接改這份計畫，改完再讓 Claude 往下做。
3
實作核准計畫，或再按一次 Shift+Tab 離開 plan mode，讓 Claude 寫程式，並對照它的計畫驗證。
4
提交請它用描述清楚的訊息 commit，並開一個 PR。

# 3 實作（離開 plan mode）

提醒

plan mode 也有成本

文件提醒 plan mode 有用，但也多一道工。範圍清楚、改動很小的任務，例如改一個錯字、加一行 log、改一個變數名，直接請 Claude 做就好。規劃最有用的時候，是你不確定該怎麼做、改動會跨好幾個檔案，或你不熟要改的那段程式。文件的判準是：如果你能用一句話描述這次的 diff，就跳過計畫。

整理者的讀法：plan mode 在 Claude 動手之前多給你一個檢查點。探索階段它只讀不改；計畫是一份你可以直接編輯的文字；到了實作，計畫又成了它自己對照的標準。上一章的「能跑的檢查」管做完之後，這一章管動手之前。

第三組是把調查交給 subagent。文件說既然 context 是最根本的限制，就用 subagent 把研究留在外面：Claude 研究 codebase 時會讀很多檔案，每一個都吃掉你的 context；subagent 在各自的 context window 裡跑，只回報摘要。文件的例子是請 Claude 用 subagent 調查驗證系統怎麼處理 token refresh，以及有沒有現成的 OAuth 工具可以重用。實作完成後，也可以用 subagent 做驗證（第 8 章）。

第四組是 checkpoint。文件說你送出的每一個開始一輪的 prompt，都會建立一個 checkpoint；Claude 每次改檔之前都會先替檔案存一份快照。按兩次 Esc 或跑 /rewind 打開倒回選單，可以只還原對話、只還原程式碼、兩者都還原，或從選的那則訊息開始摘要。所以與其把每一步都規劃好，你可以請 Claude 試一個冒險的做法，不行就倒回、換一條路。checkpoint 跟著對話一起存，關掉 terminal、之後接續 session，還是能倒回。

提醒

checkpoint 不能取代 git

文件特別警告：checkpoint 只追蹤透過 Claude 的檔案編輯工具做的改動，Bash 指令或外部程序造成的改動都不在裡面。它不能取代 git。

第五組是接續對話。文件說 Claude Code 把對話存在本機，任務要分好幾次做時，不必重新解釋一遍 context。跑 claude --continue 接著上次的地方做，或用 claude --resume 從清單裡挑。文件建議用 /rename 替 session 取描述性的名字，例如 oauth-migration，把 session 當成分支：每一條工作線都有自己持續的 context。

文件把這些叫做常見的錯，說早點認出來能省下時間。五種各自的情境與修法如下：

Kitchen sink

什麼都丟的 session

一個任務做到一半，問了一件不相關的事，又回到原本的任務；context 塞滿無關的資訊。修法：不相關的任務之間 /clear。

Correcting

一改再改

做錯、糾正、還是錯、再糾正；context 被失敗的做法污染。修法：糾正兩次還沒好，就 /clear，把學到的寫進更好的起始 prompt。

Over-specified

規定過多的 CLAUDE.md

檔案太長，重要的規則淹沒在雜訊裡，Claude 忽略了一半。修法：大刀闊斧地刪；沒有這條指示它也做對的，刪掉或改成 hook。

Trust-then-verify

先信了才驗

Claude 交出一份看起來合理、卻沒處理邊界情況的實作。修法：一定要給驗證，測試、腳本、截圖都行；驗證不了，就不要上線。

Infinite exploration

沒有邊界的探索

請 Claude「調查」某件事卻沒限定範圍，它讀了幾百個檔，把 context 塞滿。修法：把調查範圍收窄，或交給 subagent，別讓探索吃掉主對話的 context。

整理者的讀法：五種裡有三種，文件的描述直接寫到 context 被塞滿或污染，就是什麼都丟的 session、一改再改、沒有邊界的探索；修法都是讓主對話變乾淨，清空，或把調查移到 subagent。規定過多的 CLAUDE.md 是規則被雜訊蓋過，修法回到第 4 章；先信了才驗是少了驗證，修法回到第 1 章。第 10 卡的分組就是照這個讀法畫的。

Chapter 10 · Develop your intuition

這些做法是起點，直覺要自己養

文件最後說，這些模式都不是定死的，而是一般情況下好用的起點；有時該讓 context 累積，有時該跳過規劃。後半的動手做清單不在文件裡，是整理者加的。

文件的最後一節說，這份指南裡的模式不是一成不變的。它們是一般情況下效果很好的起點，但不一定每個情境都最適合。

它舉了三種例外。有時你正深陷一個複雜的問題，歷史很有價值，這時就該讓 context 累積；有時任務是探索性的，該跳過規劃，讓 Claude 自己摸索；有時一個模糊的 prompt 剛剛好，因為你想先看 Claude 怎麼理解這個問題，再加上限制。

文件要你留意什麼有效。Claude 交出很好的結果時，注意你做了什麼：prompt 的結構、你給的 context、你當時在哪個模式。它表現吃力時，問為什麼：context 太吵？prompt 太模糊？還是任務太大，一次做不完？文件說時間久了，你會養出指南寫不出來的直覺：知道什麼時候該具體、什麼時候該開放，什麼時候該規劃、什麼時候該探索，什麼時候該清 context、什麼時候該讓它累積。

給它能跑的檢查、把意圖講清楚、讓 context 保持乾淨；剩下的，靠你看它做事時養出的判斷。 整理自全文

下面這份清單不在文件裡，是整理者把全文的建議排成的順序，讓你下一個任務就能照著試。

  1. 下一個任務先附上能跑的檢查測試、build、linter 或截圖比對都行；請 Claude 做完拿證據給你看，不要只說做完了。
  2. 範圍不清楚的改動，先進 plan mode探索、規劃、實作、提交；一句話講得完的 diff 就直接做。
  3. 用 /init 起一份 CLAUDE.md，再逐行刪每一行都問「刪掉會出錯嗎」；有時才用的搬去 skill，一定要發生的改成 hook。
  4. 設好權限與工具信任的指令加進允許清單、開沙箱；外部服務優先用 CLI，需要時再接 MCP。
  5. 換任務就 /clear，修正兩次還不對也 /clear帶著學到的東西重寫 prompt；還在同一件事上就用 /compact，並寫明要留什麼。
  6. 讀很多檔的調查，交給 subagent做完再用新的 subagent 對照計畫審 diff，只修影響正確性與需求的缺口。
  7. 大量重複的改動，先在 2 到 3 個檔上試用 claude -p 加 --allowedTools 跑迴圈；試順了再跑整份清單，或交給 /batch。

Reference · 名詞速查

二十四個名詞，看懂這份指南

依「限制、驗證與規劃、環境、session、自動化」的順序排，解釋是整理者依文件的用法寫的。

Context window
情境視窗
Claude 這一刻看得到的全部內容：每則訊息、讀過的檔、指令輸出；文件說它是最需要管理的資源。
Token
詞元
模型讀寫文字的單位；文件說一次除錯就可能用掉數萬個。
Agentic coding
代理式寫程式
模型自己讀檔、跑指令、改程式，把問題做完；你可以看著、改方向，或走開。
/goal
目標條件
把檢查設成條件；另一個評估者每一輪都重查，Claude 做到目標達成。
Stop hook
停止掛鉤
把檢查當腳本跑，沒通過就不讓這一輪結束；連續擋下的次數有上限。
Plan mode
規劃模式
Claude 只讀檔、回答問題，不做修改；用 Shift+Tab 切換，或以 --permission-mode plan 開始。
CLAUDE.md
專案說明檔
每段對話開頭都會讀的檔；只放廣泛適用、從程式碼推不出來的規則。
Skill
技能
.claude/skills/ 裡的 SKILL.md；相關時自動套用，或用 /skill-name 叫用。
Hook
掛鉤
在工作流程的特定時間點自動跑腳本；確定性，保證動作會發生。
Subagent
子代理
在自己的 context 裡、用自己被允許的工具做事，只把摘要交回來。
MCP server
MCP 伺服器
用 claude mcp add 接上的外部工具，例如 issue tracker、資料庫、Figma。
Plugin
外掛
把 skills、hooks、subagents、MCP servers 打包成一個可以安裝的單位；用 /plugin 找。
Auto mode
自動模式
分類器模型代替你審查動作，只擋看起來有風險的；文件說 v2.1.283 起是互動式 session 的預設。
Manual mode
手動模式
寫檔、跑 Bash、用 MCP 工具之前都先問你；安全，但批准多了容易變成照點。
Permission allowlist
允許清單
預先允許你知道安全的特定工具，例如 npm run lint、git commit。
Sandboxing
沙箱
作業系統層的隔離，限制檔案系統與網路存取，讓 Claude 在邊界內放手做。
/clear
清空
整個重設 context；換到不相關的任務，或同一件事修正超過兩次時用。
/compact
壓縮
摘要對話、空出 context；後面可以接指示，說這次要留下什麼。
Checkpoint
還原點
每個開始一輪的 prompt 都建立一個；只追蹤 Claude 檔案編輯工具的改動，不能取代 git。
/btw
順口一問
答案不進對話歷史，查個細節不會讓 context 變長。
Non-interactive mode
非互動模式
claude -p；用在 CI、pre-commit hook 與腳本，輸出可以是文字、JSON 或串流 JSON。
Worktree
工作樹
各自隔離的 git checkout；平行的 session 各用一個，改動不會互撞。
Fan-out
分派
把大型遷移拆給很多個平行的 Claude 呼叫：用 /batch，或用迴圈呼叫 claude -p。
Adversarial review
對抗式審查
新的 subagent 只看 diff 與標準，回報缺口；只修影響正確性與需求的。
