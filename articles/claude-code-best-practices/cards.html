先拿 2 到 3 個檔試，依出錯的地方修 prompt，再跑全部。沒人看著跑的時候，用 --allowedTools 限制它能做的事，文件說這一點很重要。

為什麼要換一個新的 context

直接可以拿去用的三條
① 只查正確性：跑內建的 /code-review skill，它在新的 subagent 裡審目前的 diff 有沒有 bug。
② 要對照計畫：自己寫審查 prompt，講清楚審哪份工作、對照哪份計畫、什麼算一個發現。
③ 被要求找缺口的審查者，就算工作沒問題也常回報一些；只修影響正確性與需求的，其餘當選項。
