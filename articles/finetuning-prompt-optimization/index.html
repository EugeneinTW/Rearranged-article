BETTERTOGETHER · FINE-TUNING × PROMPT OPTIMIZATION · 圖卡＋教材整合版

prompt 與權重， 輪流調比只調一邊好BetterTogether：先調 prompt、 再微調權重、 最後重挑一次示範， 讓同一個模型自己教自己

多模組的語言模型程式（例如先寫查詢、再檢索、再回答的多跳問答）通常只有最終答案的標籤，中間每一步寫得好不好沒有人標過，也沒有梯度可以傳回去。這篇 Stanford 的論文讓程式在訓練輸入上自己跑，只留下最終答案正確的軌跡：先用它們替每個模組挑 few-shot 示範，再用它們微調同一個模型的權重，最後在新權重上重挑一次示範。在三個任務、三個 7B 到 8B 的開放模型上，九組裡有七組的最高分同時用了兩種最佳化。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

調 prompt 還是調權重，這篇的答案是輪流調

Stanford CS 329Z 第 5 週「Optimization」那一講，從 prompt 一路講到微調：prompt 最佳化（GEPA、MIPROv2、OPRO、TextGrad）、test-time compute、LoRA 與 QLoRA、蒸餾、RLHF 與 DPO，最後問什麼時候該調 prompt、調權重，還是加推論算力。這篇 EMNLP 2024 的論文是這一講的選讀，對其中「調 prompt 還是調權重」給了明確的回答。

這一講的必讀是 GEPA 與 test-time compute，另一篇選讀是 MIPRO。它們多半處理其中一邊：把 prompt 寫得更好，或讓模型在推論時多花一點算力。這篇把 prompt 與權重放進同一個問題：一個由好幾次 LM 呼叫組成的程式，每一次呼叫背後都有一段 prompt 和一組模型權重，兩樣都能調。作者的回答是兩樣都調，而且照順序輪流調：先最佳化 prompt，用它跑出來的結果微調權重，再回頭最佳化一次 prompt。他們把這個做法叫 BetterTogether，並放進了 DSPy。

作者是 Stanford 的 Dilara Soylu、Christopher Potts 與 Omar Khattab。以下是整理者的補充：本站整理過的 DSPy 論文（2023 年貼上 arXiv，ICLR 2024），第一作者是 Omar Khattab、最後一位作者是 Christopher Potts，和這篇有兩位共同作者。這篇就建在 DSPy 上：程式用 DSPy 寫，兩個最佳化器是 DSPy 的 BootstrapFewShotRS 與 BootstrapFinetune；作者說 DSPy 那篇只在很窄的設定用過微調，這篇把它推廣成「同一個模型自己教自己」（第 2、3 章）。這篇引用的 Opsahl-Ong 等人（2024）〈Optimizing Instructions and Demonstrations for Multi-Stage Language Model Programs〉就是同一講的另一篇選讀 MIPRO，參考文獻列的作者也有 Potts 與 Khattab。

引言先講趨勢：越來越多系統不只用模型的單一能力，而是把 LM 的幾種技能接成管線，例如檢索增強生成、多跳推理、資訊擷取。作者稱這種系統為 LM 程式（LM Programs）：把問題拆成幾個比較好處理的子任務，各交給 LM 去做。如果能教會這些 LM 把自己的子任務做對，並在多階段的管線裡互相配合，能可靠運作的 NLP 系統範圍就會大很多。

DSPy 替這件事定了框架。一個程式是一個函式 Φ，由幾個階段組成，論文叫它們語言模組（language modules）。每個模組描述一個用自然語言定義、界線模糊的轉換，例如「替一份文件寫摘要」，這個轉換要靠學習得到：模組學一段 prompt 模板 π，拿它去呼叫權重為 θ 的 LM。最佳化問題就是更新每個模組的 π 與 θ，讓程式在一組輸入上的預期表現最高，表現用下游的 metric μ 衡量。

第 2 節把問題寫得更精確。程式 Φ 像一個黑箱，吃自然語言的輸入、吐自然語言的輸出，例如吃問題、吐答案；執行時會呼叫一個或多個模組。以多跳檢索問答為例，程式把問題拆成子問題，反覆去語料庫（例如維基百科）找相關段落，直到能忠實地回答。每個模組是一次宣告式的 LM 呼叫，用自然語言定義輸入的範圍（使用者的問題、一組檢索到的段落）與輸出的範圍（用來找更多段落的搜尋查詢）。要把一個模組實作出來，需要指定兩樣東西：把輸入塞進去、解碼出輸出的字串 prompt πi，以及這個模組呼叫 LM 時用的浮點權重 θi。

手上有的只是一個小訓練集：一些輸入 xi，加上選填的 metadata mi，例如最終輸出的標籤，或其他能判斷這次執行對不對的提示；以及一個 metric μ，拿程式的輸出和 metadata 算分。目標寫成文字是：在所有可能的權重組 Θ 與 prompt 組 Π 裡，找出讓 μ 在訓練集上的平均最高的那一組。作者說調管線的研究者實際上都在追這個目標，而它也是 DSPy 最佳化問題裡很大的一塊子空間。

問題是它不可解。第 1、2 節列出的原因可以整理成四條：

1
不可微分Φ 一般不可微分，沒有梯度可以從最終分數傳回每個模組。
2
沒有中間標籤模組通常沒有標好的輸出；第二個搜尋查詢寫得好不好，沒有人標過。
3
彼此依賴一個模組的輸出是下一個模組的輸入，模組之間的依賴很複雜，搜尋空間也很大。
4
資源少實際情況的訓練集通常很小，訓練與推論時能用的 LM 呼叫次數也不多。

所以作者找的是近似的最佳化策略：替所有模組 bootstrap 出訓練標籤，再在微調權重與最佳化 prompt 之間交替。前者是第 2 章，後者是第 3 章。

背景

概念上每個模組各有一組權重，實驗裡共用一個模型

第 2 節的寫法讓每個模組可以有自己的權重 θi，附錄 A 的程式說明也寫每個 LM 模組各用自己的 prompt 與權重。實驗的做法比較簡單：所有模組一開始共用同一個模型的權重，prompt 各不相同；微調時把所有模組的資料合成一份，訓練完所有模組都改用同一個微調後的模型（第 2、4 章）。

要讓第 3 章的交替演算法真的能跑，得替「最佳化 prompt」與「微調權重」各指定一種做法。作者選的是 DSPy 的 Bootstrap 家族：在輸入例子上執行程式的初始版本，當最終輸出「正確」時，記下每個模組看到的輸入與寫出的輸出。「正確」的定義是 metric 的分數達到某個門檻 λ，例如用二元準確度時 λ 是 1.0。作者特別強調這一點：兩種最佳化都不是在人工標註的資料上訓練，而是在程式自己產生的軌跡上訓練。第 1 章說中間步驟沒有標籤，這就是解法：由最終答案答對的那幾次，替中間步驟提供例子。

prompt 這邊用 BootstrapFewShotRS（簡稱 BFRS）。它替每個模組自己產生候選的 few-shot 例子，再用一種隨機搜尋（random search，RS）挑出真正要放進 prompt 的那幾個。Algorithm 2 的步驟是：先把訓練集切成訓練子集 T 與驗證子集 V；在 T 的輸入上執行程式，收集每個模組的輸入輸出，也就是軌跡；只留 metric 給高分的軌跡；接著抽出好幾組「少量軌跡」的子集，每一組都替每個模組提供一個候選示範，用它們組成 few-shot prompt，在 V 上算平均分，最後回傳分數最高的那一組 prompt。作者說這種簡單的搜尋已知能穩定地大幅提升 LM 程式的品質，常勝過手動或自動最佳化指令、或手寫例子。附錄 C 給了實際的設定：隨機搜尋 6 個候選程式，每個模組的 prompt 最多放 3 個 few-shot 例子。

換句話說，依第 3 節與 Algorithm 2 的描述，這篇說的 prompt 最佳化只挑 few-shot 示範，沒有改寫指令文字；指令一直是使用者給的簡單指令，也就是附錄 A 的 vanilla prompt 裡那一段。同一講的 MIPRO 依它的標題同時最佳化指令與示範，讀的時候要分清楚。

權重這邊擴充的是 DSPy 的 BootstrapFinetune（簡稱 BFT）。它替每個模組自己產生大量例子，合成一份資料集去微調 LM 的權重；作者說這等於一個隱含的多任務目標，子任務就是各模組的角色。第 4 節把 BFT 拆成七步，這裡併成五步：

1
跑全部訓練例把所有訓練例都當候選，在每一筆上執行程式。
2

# 三步都用同一個訓練集 X、同一個 metric，軌跡都由同一個模型產生
def better_together(program, X, metric):
    p1 = optimize_prompts(program, X, metric)                          # 第 1 步：權重不動
    w1 = finetune_weights(program.with_prompts(p1), X, metric)         # 第 2 步：用 p1 跑出的軌跡
    p2 = optimize_prompts(program.with_weights(w1), X, metric)         # 第 3 步：w1 配原本的 prompt
    return program.with_weights(w1).with_prompts(p2)

def optimize_prompts(program, X, metric):          # BootstrapFewShotRS
    T, V = split(X)
    traces = [t for t in run(program, T) if metric(t) >= LAMBDA]    # 只留答對的
    return best_on(V, sample_fewshot_subsets(traces))                   # 隨機搜尋，留 V 上最高分

def finetune_weights(program, X, metric):          # BootstrapFinetune
    traces = [t for t in run(program, X) if metric(t) >= LAMBDA]
    return train_lora(traces)                                           # 所有模組的配對合成一份

class HotPotQAProgram(dspy.Module):
    def __init__(self):
        self.retrieve = dspy.Retrieve(k=3)          # 凍結的 ColBERTv2，每跳取 3 段
        self.generate_query = [dspy.ChainOfThought("context, question -> search_query")
                               for _ in range(2)]    # 兩個模組，各有自己的 prompt
        self.generate_answer = dspy.ChainOfThought("context, question -> answer")

    def forward(self, question):
        context = []
        for hop in range(2):
            query = self.generate_query[hop](context=context, question=question).search_query
            context = dedupe(context + self.retrieve(query).passages)   # 去重後累積
        return self.generate_answer(context=context, question=question)

關鍵觀念 · 一

答對的軌跡，推理不一定對

表 A.1 那條 HotPotQA 軌跡問的是：受 Foster's rule 影響、北美最小的鹿是哪一種。第一個查詢模組的推理把 Foster's rule 說成一條用耳朵表面積估算大型哺乳類體重的公式（整理者注：Foster's rule 一般指島嶼法則，講島上動物體型的變化，和耳朵面積無關）。它寫出的查詢仍撈到了寫著「Key deer 是北美最小的鹿」的段落，最後的答案 Key deer 是對的。

整理者的讀法：metric 只看最終答案，這條軌跡會算成「答對」，可能被 BFRS 選成示範，也可能被 BFT 拿去訓練。論文沒有討論這種情況；它提醒讀者，bootstrap 留下的是結果對了的例子，不保證每一步的推理都對。

整理者的讀法

放回這一講：何時調 prompt、何時調權重

下面是整理者的連結，論文沒有這樣講。這篇的證據回答了這一講的一小塊：在只有最終答案標籤、模型是 7B 到 8B、訓練集 50 到 1,000 筆的設定下，prompt 最佳化不能省，只做微調常常不夠；兩者都做時，先調 prompt 讓微調有資料可學，微調後再重挑示範。它沒有碰 test-time compute，微調也只用了 LoRA，QLoRA、蒸餾、RLHF 與 DPO 都不在比較裡。同一講的 MIPRO 依標題同時最佳化指令與示範，這篇的 prompt 最佳化只挑示範；把別的 prompt 最佳化器換進 Algorithm 1 的 OptimizePrompts 會怎樣，論文沒有試。

需要準備多少標註資料？
只需要能判斷最終輸出對不對的 metadata，例如最終答案，中間步驟不用標。實驗的訓練集是 HotPotQA 與 GSM8K 各 1,000 筆、Iris 50 筆；prompt 最佳化只用其中的 100 與 250 筆當訓練與驗證（Iris 是 15 與 35 筆）。
三種順序哪一種最好？
第 5 節說三種 BetterTogether 策略之間沒有明確的贏家。九組裡有七組的最高分落在它們之中，但拿到最高分的順序隨任務與模型而變：Π → Θ → Π 與 Θ → Π 各三組，Π → Θ 一組。
要用大模型教小模型嗎？
這篇刻意讓同一個模型自己教自己。第 3 節說讓大模型替小模型 bootstrap 可能效果更好，但不在範圍內；DSPy 那篇用 Llama2-13b 程式的軌跡訓練 T5-Large，就是大教小的例子。

讓程式在訓練輸入上自己跑，把 metric 達到門檻 λ 的軌跡當成示範或訓練資料。
BootstrapFewShotRS（BFRS）
調 prompt 的最佳化器
切出訓練與驗證子集、收集答對的軌跡、隨機搜尋示範組合，回傳驗證分數最高的 prompt（Algorithm 2）。
BootstrapFinetune（BFT）
調權重的最佳化器
在全部訓練例上收集答對的軌跡，prompt 換回 vanilla，合成一份資料微調 LM（Algorithm 2、第 4 節）。
random search
隨機搜尋
BFRS 挑示範的方法；實驗裡搜尋 6 個候選程式，每個模組最多 3 個例子（附錄 C）。
BetterTogether
交替最佳化
先調 prompt、再微調權重、再調一次 prompt 的演算法（Algorithm 1）；也指表 1 裡同時用兩種最佳化的三種策略。
vanilla zero-shot
未最佳化的程式
只有使用者寫的簡單指令、沒有示範也沒有微調的程式；表 1 的第一列。
few-shot example
示範
放進 prompt 的輸入與輸出配對；BFRS 從答對的軌跡裡挑。
LoRA
低秩適應
這篇唯一試過的微調方法：訓練 query 與 key 注意力層，rank 32、alpha 64、5 個 epoch（附錄 C）。
multi-task objective
多任務目標
BFT 把所有模組的例子合成一份資料訓練一個模型，子任務就是各模組的角色。
Chain-of-Thought（CoT）
先推理再作答
三個程式的每個模組都先寫一段推理，再寫出查詢或答案。
HotPotQA
多跳問答
fullwiki 設定，從 500 萬篇維基百科摘要找兩篇來回答；程式有三個 LM 模組。
GSM8K
小學數學應用題
單一模組的 CoT 程式；取回應第一行的最後一個數字評分，測試 1,319 題。
Iris
鳶尾花分類
150 筆的經典分類資料，切成三等份；用來看以特徵為主的分類題會不會讓微調佔優勢。
ColBERTv2
檢索器
HotPotQA 程式裡凍結的檢索模型，每跳取回 3 段。
EM
完全相符
正規化大小寫、空白與標點後，答案和標準答案完全一樣才算對；HotPotQA 與 Iris 用它。
held-out test set
保留測試集
最佳化時不碰的測試資料；表 1 是它上面三個隨機種子的平均。
DSPy
LM 程式框架
定義與最佳化 LM 程式的框架；這篇的程式與最佳化器都是它的擴充，BetterTogether 也已放進去。
