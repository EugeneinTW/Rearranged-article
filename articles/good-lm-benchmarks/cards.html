03 / 07答案要能自動判對錯
同樣有很多種對法，程式有測試，摘要沒有
給一個模型寫的答案，benchmark 要判斷它對不對。作者拿兩個都很有用的任務對照：寫程式能用單元測試自動判，寫摘要很難評；有人提議讓 LM 來評，作者不贊成
✗ 寫摘要：找不到自動判對錯的方法
✓ 寫程式：單元測試自動判
任務：替這位病人的病歷寫 500 字摘要
正確的摘要，有很多種寫法
有人提議：讓 LM 來評分
同一個 LM 又解題、又評分
作者說：這樣會出問題
作者舉的例子是病歷摘要：對人很有用，但同一份病歷有很多種正確的摘要法，沒辦法拿一個標準答案來比對。
任務：寫一個函式、修一個 bug
程式也有很多種寫法
跑單元測試，自動驗證對不對
HumanEval、SWE-bench 都這樣判
SWE-bench 的兩組測試，見第 06 卡
單元測試不比對程式長什麼樣，而是實際執行、檢查輸出對不對；寫法再多，對了就過。這句解釋是整理者補的。
很有用，新 benchmark 卻很少
作者覺得摘要對人可能非常有用，例如病歷摘要；
但正確的摘要太多種、評分太難，新 benchmark 很少。
有人提議讓 LM 評 LM，作者認為這不是對的方向。
寫法再多，測試照樣判
同一個函式有很多種寫法，比對文字判不了；
HumanEval 與 SWE-bench 改用單元測試，自動驗證程式對不對。
原文說：看題目的類型，判對錯可能很簡單，也可能做不到。
注意：作者反對的是同一個 LM 同時當解題者與評分者；LM 只拿來解題，或只拿來評分，他沒有反對。

06 / 07一個 task 的四元組
評分器看的不是回答，是 agent 停下時的環境
原文最後一節：benchmark 是一組 task，每個 task 是要求、環境、停止條件、評分器組成的四元組。把一次執行由左往右畫開，評分器拿到的，是 agent 結束那一刻的環境
要事先決定
① 要求 request

② 環境 environment
能上網嗎？裝了哪些套件？
有沒有給 agent 特殊工具？
agent 在環境裡解題
不是四元組的一員；
它動手的地方就是 ② 的環境
③ 停止條件 stopping
送出 submit 就結束；不送呢？
回合、成本、時間上限，或組合
④ 評分器 scorer
拿 agent 停下那一刻的
環境來打分
評分的三種形式
二元：SWE-bench 的 fail2pass、pass2pass 兩組測試　·　連續分數：AlgoTune 比 agent 程式的總執行時間　·　ELO：CodeClash
中間那格虛線不是四元組的一員：agent 在 ② 的環境裡動手，停下之後，④ 拿同一個環境來打分。benchmark 就是很多個這樣的 task。
作者對其中三項的提醒
停止條件要先定
agent 可能自己送出 submit 結束，
但它一直不送時怎麼辦，要事先決定：
回合、成本、時間上限，或幾個一起用。
作者說每一種都行，重點是要決定。
環境要寫到完整
agent 解題時身處的環境要完整描述：
能不能上網、哪些套件有裝哪些沒裝、
有沒有給它特殊工具。
基線的 scaffolding 也從這裡開始（第 07 卡）。
評的是停下時的環境
評分器拿 agent 結束時的環境來打分：
SWE-bench 在那個環境裡跑兩組測試，
AlgoTune 量 agent 的程式跑了多久。
形式可以是二元、連續分數或 ELO。
注意：四元組與各項的問題是原文的；標題的「不是回答」、畫成由左往右的流程與中間那格 agent，是整理者的整理。AlgoTune、CodeClash 是作者團隊的 benchmark。
