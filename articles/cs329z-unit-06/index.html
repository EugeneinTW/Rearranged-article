Anthropic 的兩個定義

單元 2 的〈Building Effective Agents〉先畫一條線：workflow 是模型與工具照預先定義的程式路徑被安排的系統；agent 是模型動態指揮自己的流程與工具使用的系統（Building Effective Agents 第 1 章）。agent 那一章把實作講得很直接：模型在迴圈裡依環境回饋使用工具，每一步都要從環境拿到真實情況來判斷進度，常見的做法是加一個停止條件，例如最大迭代次數（第 7 章）。整篇的建議是先找最簡單的解，需要時才加複雜度。

ReAct 的迴圈：下一步由模型寫出來

ReAct 的策略就是被 prompt 過的語言模型：每一步看著到目前為止的 context，決定寫一句 thought、送出一個行動，或用 finish 交出答案；thought 不送進環境，行動的觀察接回 context（ReAct 第 2 章）。要不要寫 thought 也由模型決定：知識任務每一步都寫，ALFWorld 與 WebShop 只在關鍵處寫，何時出現交給模型（第 3 章）。放到 Anthropic 的定義上，這是 agent 那一側。

這個迴圈也有停止條件。HotpotQA 設 7 步、FEVER 設 5 步，作者說再多給步數，表現也不會更好；所有答對的軌跡裡，走到這麼多步的只佔 0.84% 與 1.33%（第 7 章）。

兩條後援規則：換不換方法，寫在程式裡

第 7 章的兩條規則是作者寫死的判斷。一條是 ReAct 在步數內沒有答出來，就退回 CoT-SC（抽 21 條 CoT 取多數）；另一條是 CoT-SC 抽出的 n 條裡，多數答案出現不到 n/2 次，就改跑 ReAct。換不換、往哪裡換，由程式看這兩個訊號決定，模型不參與。Anthropic 的路由工作流也是這個形狀：先依一個條件分類，再交給專門的流程，分類可以交給模型，也可以交給傳統的演算法（Building Effective Agents 第 4 章）。

表 1 兩題最好的 prompting 成績都來自這兩條規則：HotpotQA 是 ReAct → CoT-SC 的 35.1，FEVER 是 CoT-SC → ReAct 的 64.6；單獨的 ReAct 是 27.4 與 60.9（PaLM-540B，ReAct 第 7 章）。

同一張表上的一次並排

單元 5 的 DSPy 在 HotPotQA 上同時跑了兩種多跳程式。react 是內建的 ReAct 模組，每次檢索拿 1 段、最多走 5 輪，要查什麼、查幾次由模型決定；multihop 是作者寫的兩跳程式，每一跳由模型寫一個查詢、檢索 3 段，跳兩次就回答，步數寫在程式裡（DSPy 第 11 章）。GPT-3.5 在開發集上，編譯兩次的 react 是 39.0，編譯過的 multihop 是 48.7；換成 llama2-13b-chat 是 40.0 與 42.0。作者的結論是簡單的 multihop 表現最好（DSPy 第 12 章）。兩個程式每次檢索拿到的段數不同，DSPy 也沒有報告兩者的呼叫次數。

整理者的讀法

兩篇的「agent」不在同一個層次

  • Anthropic：agent 與 workflow 是整個系統的兩種架構，差別在路徑由誰決定。
  • ReAct：agent 是強化學習的用法，收到觀察、選一個行動；論文沒有 workflow 這個詞。
  • 對應：把迴圈放在 agent 那一側、後援規則放在 workflow 那一側，是整理者的讀法；Anthropic 的文章沒有提到 ReAct（整理者搜尋過）。
  • 透明：Anthropic 實作 agent 的第二條原則，是把規劃步驟明確地顯示出來（第 8 章）；ReAct 說 thought 讓人讀得懂、也改得動，附錄 A.3 裡人改掉兩句 thought 就救回一局遊戲（ReAct 第 11 章）。

還沒有答案的地方，兩篇自己也留著。Anthropic 說 workflow 適合定義明確的任務、agent 適合步數預測不了的開放問題，但沒有給判斷的門檻（第 1、7 章）。ReAct 的兩條規則是作者的啟發式，7 與 5 這兩個步數來自答對軌跡的分布；換一個任務要不要重訂，論文沒有討論。

ReAct：常識是一種 thought

ALFWorld 是文字版的家務遊戲，一個任務可能有超過 50 個地點，專家也要走 50 多步；遊戲裡有一個內建的難點：要判斷常見的家用品可能放在哪裡（ReAct 第 9 章）。ReAct 的示範裡有稀疏的 thought，做四件事：拆解目標、追蹤子目標完成了沒、決定下一個子目標，以及用常識推測東西在哪、拿到之後要做什麼。論文列 thought 的種類時，舉的常識例子是「胡椒罐比較可能在櫃子 1 到 6、流理台 1 到 3」（第 3 章）。

作者做了一個消融 ReAct-IM：同一批專家軌跡，改寫成只描述目前目標與子目標的 thought，少了三種：判斷子目標何時完成、決定下一個子目標、用預訓練的知識推測東西在哪。成功率從 71 掉到 53（6 組 prompt 各取最好），六類任務有五類下降，只有 Clean 例外；很多 ReAct-IM 的軌跡推不出東西可能放在哪裡（ReAct 第 11 章）。這些數字用的是 PaLM-540B，在 134 場沒看過的遊戲上評估。

附錄 C 把同一個清洗任務的兩份示範並排印出來（表 8、表 9），差別看得很清楚。兩份的第一句 thought 一樣：先找到並拿起萵苣，用水槽洗好，再放到餐桌上。接下來 ReAct 的示範寫的是萵苣比較可能在冰箱、餐桌、水槽、爐台或櫃子裡，從冰箱開始一個一個找；找到之後寫「找到了，下一步是拿起來」。ReAct-IM 的示範只重複「先要找到萵苣」，沒有說去哪裡找，也沒有一句判斷這一步完成了沒。

AutoGen：常識由另一個代理補

AutoGen 先做了一個兩代理系統：助理代理產生計畫、決定每一步的行動，executor 代理執行並回報結果。它整合了 ReAct 的 prompting，把 prompt 改成對話的形式，照 ReAct 用兩個示範，示範取自 ReAct 的程式庫（AutoGen 第 7 章）。它和 ReAct 的平均成功率都是 54%，也有同一個問題：偶爾用不上物理世界的基本常識，一再重複同一個錯誤。

作者檢查失敗的嘗試，把助理缺的常識交給新加的 grounding 代理。它只在兩個時機發言：任務開始時，以及助理連續三次送出同一個動作時，例如提醒「要先找到並拿起物品，才能檢查它」。三代理的平均成功率是 69%，3 次取最好是 77%（同一章）。

條件要分開看。AutoGen 表上的 ReAct 數字，是跑 ReAct 的官方程式、用預設設定得到的，那份程式的後端是 text-davinci-003；AutoGen 的兩個版本用 GPT-3.5-turbo；每個任務試 3 次（AutoGen 第 11 章）。兩代理與三代理之間用的是同一個模型。

整理者的讀法

兩篇補的是相似的缺口，量法不同

  • ReAct 論文：同一個模型、同一批軌跡，比「示範裡有沒有常識與子目標型的 thought」：71 對 53。
  • AutoGen：同一個模型，比「有沒有一個在卡住時補常識的代理」：54 對 69。
  • 相似的失敗：ReAct-IM 常判斷錯子目標是否完成，AutoGen 的助理常把「找到」和「拿起」混為一談。這是整理者並排時看到的相似，兩篇沒有互相比較。
  • 沒有的比較：同一個模型下，「把常識寫進示範」和「另外加一個代理」直接並排的結果，本站的讀物裡沒有。

單元 1 的 Ng 把「多個 agent 分工」列為四種模式之一，說它能讓 agent 做更多事，但比 reflection 與 tool use 不成熟、比較難預測（Agentic Design Patterns 第 3 章）；他在多代理那封信舉的第一個理由，就是 AutoGen 的消融（第 7 章）。AutoGen 自己在討論裡說，哪類任務最適合多代理，還是開放問題（AutoGen 第 13 章）。

示範：誰寫、寫幾條

ReAct 的示範是人寫的完整軌跡：HotpotQA 6 條、FEVER 3 條，ALFWorld 每類任務從 3 條裡取 2 條、排出 6 組 prompt，WebShop 1 條（ReAct 第 4 章、第 9 章）。thought 怎麼寫也寫在示範裡：換成只複述目標的寫法，ALFWorld 從 71 掉到 53（第 3 章）。

單元 5 的 DSPy 把示範交給編譯器：teleprompter 依一個 metric，從訓練資料 bootstrap 出示範（DSPy 第 5 章）。HotPotQA 的 react 程式，不給示範是 20.3，用 ReAct 論文的專家推理改寫成的示範是 33.0，編譯兩次是 39.0（GPT-3.5，開發集；第 12 章）。

指令與格式：怎麼描述任務

ReAct 說它的 prompt 很直覺：寫示範的人只要在自己做過的每個行動上面，打出當時的想法，沒有特別挑格式、設計 thought 或挑選示範（ReAct 第 3 章）。

單元 9 的 GEPA 改的是指令：一個負責反思的語言模型讀執行軌跡與評分時的文字，找出失敗的原因，把教訓寫進某個模組的指令，示範不動（GEPA 第 1 章）。單元 11 的 AutoMetrics 拿一個用 DSPy 寫的 ReAct agent 做 τ-bench 的航空客服任務，未最佳化時 25 個測試任務平均 60%；用 GEPA 最佳化 2,000 次 rollout 之後，拿可驗證獎勵當 GEPA 的指標是 0.680，改用 AutoMetrics 產生的指標是 0.720，都是五次試驗的平均（AutoMetrics 第 12 章）。兩組的區間重疊，論文沒有檢定這兩組的差。

工具與回饋：能做什麼、看到什麼

ReAct 的 Wikipedia API 只有 search、lookup、finish 三個動作，作者說它比當時的檢索器弱得多，是刻意的：要逼模型用推理決定查什麼（ReAct 第 4 章）。代價也在失敗分析裡：人工標註的 ReAct 答錯軌跡裡，有 23% 是搜尋沒有帶回有用的資訊（第 6 章）。

單元 13 的 SWE-agent 保留 ReAct 的一輪，改的是介面：替語言模型設計少量好懂的指令、每一輪精簡的回饋，加上擋下語法錯誤的護欄（SWE-agent 第 2 章）。同一個 GPT-4 Turbo 在 SWE-bench Lite 上，預設是 18.0%；拿掉 edit 是 10.3%，換成一筆一筆看的搜尋是 12.0%，比完全不給搜尋工具的 15.7% 還低（第 8 章）。單元 2 的 Anthropic 也說，做 SWE-bench 的 agent 時，花在工具上的時間比花在 prompt 上多，把工具改成一律要絕對路徑之後，模型就沒再用錯（Building Effective Agents 附錄 2）。

停止與流程：何時停、失敗退回哪裡

ReAct 在 HotpotQA 與 FEVER 設 7 步與 5 步的上限，沒答出來就退回 CoT-SC（第 2 章）。Anthropic 建議 agent 加停止條件，例如最大迭代次數，也可以在檢查點暫停、等人回饋（第 7 章）。SWE-agent 的上下文管理只保留最近 5 個觀察，改成保留完整歷史是 15.0%（第 8 章）。單元 12 的 CDI 把防禦插在迴圈裡：它說依照 ReAct 與 MCP，標準的 agent 迴圈在提出工具呼叫與拿到結果之間反覆，CDI 在工具結果回來之後，由一個小模型寫出這一步該給什麼、不該給什麼（CDI 第 1 章）。

整理者的讀法

各篇只改一個零件，量的條件各不相同

DSPy 改示範，在 HotPotQA 上用 GPT-3.5 與 llama2-13b-chat；AutoMetrics 改指令，在 25 個航空客服任務上；SWE-agent 改介面，在 SWE-bench Lite 上用 GPT-4 Turbo。哪一個零件對你的任務影響最大，這幾個數字不能互比，要在同一個任務上各改一次才知道。四個零件的拆法與歸類是整理者的。

判斷題 · 01

多步的任務，下一步該交給模型選，還是先把路徑寫死？

交給模型的一方：ReAct 的迴圈遇到查不到的條目，會自己改查相似的條目（ReAct 第 3 章）；Ng 的研究 agent 在網頁搜尋被限流時，自己改用 Wikipedia 工具完成任務（Agentic Design Patterns 第 6 章）；Anthropic 說步數預測不了的開放問題適合 agent。寫死路徑的一方：ReAct 兩題最好的成績來自寫死的後援規則；DSPy 的表上，固定兩跳的 multihop 是 48.7、react 是 39.0；Anthropic 建議先找最簡單的解（都在第 2 章）。

還缺的證據：同一個任務、同樣的工具與呼叫預算下，固定流程和模型自己選路並排的結果。DSPy 那一次並排，react 每次檢索拿 1 段、multihop 拿 3 段，也沒有報告呼叫次數。

挑一個要查兩三次資料的任務，寫一個固定的「查、再查、回答」流程，和一個有步數上限的 ReAct 迴圈；兩邊用同一個檢索工具、每次拿同樣段數，各跑二三十題，記正確率與呼叫次數，再照 ReAct 表 2 的類型分失敗。

判斷題 · 02

卡住時缺的常識或檢查，該寫進 thought，還是另外加一個代理或一輪反思？

寫進 thought 的一方：ReAct 論文拿掉常識與子目標型的 thought，ALFWorld 從 71 掉到 53（第 3 章）。另外加的一方：AutoGen 加 grounding 代理，從 54 到 69（同一章）；DyLAN 的 WebShop 表上，Reflexion、BOLAA、DyLAN 的 reward 都高於 ReAct 的 53.8，每題的呼叫次數也從 8.40 次變成 24 到 33 次，LATS 超過 400 次（第 4 章）。

還缺的證據：同一個模型、同樣的呼叫預算下，「把常識寫進示範」和「另外加一個代理」直接並排的結果。AutoGen 表上的 ReAct 和它自己的系統，用的是不同的模型。

拿一個 ReAct 式的 agent 做兩版：A 版在示範裡補兩三句常識型的 thought，B 版加一個只在同一個動作連續出現三次時發言的檢查代理（AutoGen 的觸發條件）；兩版用同一個模型，記成功率與每題的呼叫次數。

判斷題 · 03

要改善一個 ReAct 式的 agent，先動哪一個零件？

四個零件都有讀物量過（第 5 章）：示範，DSPy 編譯出來的 39.0 對人寫推理的 33.0；指令，AutoMetrics 的 ReAct agent 經 GEPA 從 60% 到 0.680 或 0.720；介面，SWE-agent 拿掉 edit 從 18.0 掉到 10.3；流程，ReAct 的後援規則給出兩題最好的 35.1 與 64.6。

還缺的證據：四個數字來自四個任務、四種模型，各篇只改了一個零件；同一個任務上四個零件各改一次的比較，本站的讀物裡沒有。

固定模型與二三十題，一次只改一個零件：換一組示範、改寫指令、改工具回傳的格式、調步數上限與失敗時的退路；每一版記成功率與呼叫次數，看哪一個零件讓數字動得最多。

Reference · 用詞對照

同一件事，各篇用不同的名字

ReAct 的每個零件，在其他單元的讀物裡各有叫法；也有同一個詞在兩篇裡指不同的東西。每一條先寫這件事，再列各篇怎麼稱呼、在本站讀物頁的哪一章；沒有談到的篇就不列。

thought
想法、推理
ReAct：thought 或 reasoning trace，語言空間裡的行動，不送進環境（第 2 章）；ALFWorld 寫成 think:、WebShop 寫成 think[…]（第 9 章）。SWE-agent：每一輪的想法（第 3 章）。隱私風險模擬：思考工具 think()（第 2 章）。MemGPT：邊想邊說（第 6 章）。Anthropic：要明確顯示的規劃步驟（第 8 章）。
action
行動、工具呼叫
ReAct：action，例如 search[…]、lookup[…]、finish[…]（第 4 章）。Ng：一段呼叫工具的字串，由程式掃描、執行、回填（第 5 章）。SWE-agent：指令，例如 edit、search_file（第 3 章）。Anthropic：回應裡的 tool use 區塊（附錄 2）。
observation
觀察、回饋
ReAct：observation，接回 context（第 2 章）。SWE-agent：環境回饋，預設只保留最近 5 個（第 3、8 章）。Anthropic：每一步從環境拿到的真實情況，例如工具呼叫的結果（第 7 章）。
workflow
同一個詞，兩種範圍
Anthropic：路徑由程式預先寫好的 agentic 系統，和 agent 相對（第 1 章）。Ng：agentic workflow，讓模型多次處理、逐步改進，和零樣本一次寫完相對（第 1 章）。ReAct 沒有用這個詞。
agent
代理
Anthropic：模型依環境回饋自己決定流程與工具（第 1、7 章）。ReAct：強化學習的用法，收到觀察、選一個行動（第 2 章）。AutoGen：可對話的代理，能接上 LLM、人或工具（第 2 章）。
scaffold
腳手架、介面
講題：scaffold 是設計決策。GEPA：ReAct 這類腳手架（第 1 章）。SWE-agent：agent-computer interface，ACI（第 2 章）；Anthropic 也用 ACI 這個詞（附錄 2）。ReAct 沒有用這個詞，本站把它的幾個選擇讀成設計決策（第 13 章）。
demonstration
示範
ReAct：人寫的完整軌跡，每個任務 1 到 6 條（第 4、9 章）。DSPy：編譯器 bootstrap 出來的示範（第 5、6 章）。SWE-agent：一條成功解題的軌跡，拿掉是 16.3%（第 8 章）。GEPA：只改指令、不改示範（序章）。
planning
計畫
ReAct：thought 裡的拆目標、訂計畫、追蹤進度、調整計畫（第 3 章）。Ng：Planning，模型先輸出一段計畫，軟體照著執行（第 6 章）。AutoGen：ALFWorld 裡助理代理規劃、executor 執行（第 7 章）。講題的 plan-and-execute，本站讀物都沒有用這個詞。
reflection
反思
Ng：生成、批評、重寫（第 4 章）。Anthropic：評估者與優化者，整理者對上的（第 6 章）。DyLAN：Reflexion 當 WebShop 的對照，4 次嘗試（第 7 章）。ReAct 沒有這個詞。
self-consistency
多抽幾次取多數
ReAct：CoT-SC，溫度 0.7 抽 21 條 CoT 取多數（第 5 章）。DyLAN：ReAct-SC，每個回應抽三次（第 7 章）。
stopping condition
停止條件
ReAct：HotpotQA 7 步、FEVER 5 步，沒答就退回 CoT-SC（第 7 章）。Anthropic：最大迭代次數，或在檢查點暫停等人回饋（第 7 章）。
baseline
對照組
ReAct：Standard、CoT、Act 都是刪減 ReAct 軌跡做出來的（第 5 章）。AutoGen：跑 ReAct 的官方程式（第 7 章）。DyLAN：ReAct 與 ReAct-SC（第 7 章）。OpenHands：ReAct（0-shot）（第 8 章）。DSPy：react 程式加上人寫推理（第 12 章）。
grounding
同一個詞，兩種用法
ReAct：作者說它的解題過程靠外部知識，比 CoT 有依據、以事實為本（第 6 章）。AutoGen：grounding 代理，在卡住時補一句物理世界的常識（第 7 章）。
