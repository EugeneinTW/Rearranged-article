三個元件：LLM、prompt、動作空間
只有語言模型做不成 agent。prompt 可以是
system prompt，也可以是從環境拉進來的資訊；
動作空間是讓它在世界裡動手的工具。
原文說，談多代理時，至少有一個元件在變。
CodeR 換的是後兩個
五個角色的 LLM 一樣；prompt 規定每個角色
只做修 issue 的一段，動作空間只給它那一段
用得到的工具；後面的角色讀前面角色的結果。
五段依序是計畫、重現、定位、修改、驗證。
直覺，但不好做
照工作階段拆成角色，每個角色只管自己那一段，
是非常直覺的系統結構。作者接著說，這樣的系統
要做好，有好幾個困難：結構、脈絡、維護。
三個麻煩畫在第 03 卡。
注意：五個角色的 prompt 與動作空間照原文逐條整理；原文沒有描述五個角色之間的完整流程，中文角色名與五段的名稱是整理者加的。

直覺的分工，換來三個麻煩
作者列的三個難處，都能在 CodeR 的分工上找到位置：Verifier 拿不到定位工具、交接只傳摘要、每個角色各自一份 prompt 或 code base

② 只傳摘要
① Verifier 想自己做檔案定位來確認答案，但定位的工具在 Fault Localizer 手上，它拿不到
③ 維護
每個角色通常各是一個 code base，至少各是一份 prompt：五個角色疊起來，系統的程式碼更大、更複雜
三個麻煩，各自對應一種團隊的毛病
01　結構 · STRUCTURE
結構對不上題目
多代理靠事先定好的結構解題：題目剛好符合時
很好，不符合就卡住。Verifier 想自己定位檔案，
但 agent 彼此完全分開，它拿不到那組工具。
團隊的類比：組織得很鬆散。
02　脈絡 · CONTEXT
脈絡在交接中流失
資訊要在 agent 之間傳遞，傳遞本身就會流失
資訊。Fault Localizer 若只把工作的摘要往下傳，
下游常常就少了本來用得上的脈絡。
團隊的類比：彼此溝通不良。
03　維護 · MAINTAINABILITY
程式更大、更難維護
每個 agent 通常是自己的一份 code base，
至少也是自己的一份 prompt，整個系統的程式碼
因此更大、更複雜。
團隊的類比：有人離開，需要的技能就接不上。
注意：兩個例子（Verifier、只傳摘要）是原文的；Reproducer 與 Fault Localizer 上下並列，是因為原文沒說兩者的先後；三種團隊毛病一對一對上三個麻煩，是整理者排的。

為什麼夠用
寫程式、跑程式、瀏覽網頁，讓 agent 能用上原本為人類開發者做好的軟體工具；作者說這非常多用途，涵蓋了其他多代理系統能做的大部分事。
單一 LLM：相對容易
通用的 LLM 已經很好：閉源的有 Claude、GPT-4o，
開源的有 llama-3.1、Qwen-2.5。它們不是什麼都會，
但能做的事範圍很廣。
缺哪種能力，作者說可以用持續訓練補上，其他能力不會大幅下降。
單一動作空間：也不太難
給相對通用、能解決問題的工具，或把各 agent 的
工具箱直接串起來。OpenHands 給的是寫程式、
跑程式、瀏覽網頁三種，用的是為人類開發者做好的工具。
作者說這涵蓋了其他多代理系統能做的大部分事。
單一 prompt：最棘手
agent 要拿到怎麼解題的指示，也要拿到環境裡的
資訊。原本各 agent 各自一份的 prompt，例如十份，
要怎麼合成一份，是第 05 卡的題目。
作者說最好的方法仍是進行中的研究問題，但他相信能解決。
注意：上排拿第 02 卡的 CodeR 工具當例子是整理者的畫法，原文這一段沒有指名 CodeR；三件事的難易是作者自己的評估，他說 OpenHands 的 CodeActAgent 已經是這種單一代理的原型。

作者說這篇不是在說多代理沒用：一個 agent

多代理當然是對的做法。
原文用「例如」帶出這兩種情況，不是完整的清單。
對一直加複雜度多想一步
這篇的目的，是讓人批判地看待「系統越做越複雜」
的潮流。每多一個 agent，就多一份要維護的 prompt，
也多一道可能掉脈絡的交接。
「每多一個 agent」那兩句是整理者依第 03 卡補的。
三個條件已經在路上
作者說有時候簡單的最好；有了強大的模型、
強大的工具、多用途的 prompt，
單一代理這條路已經走了一大段。
三者正好對上第 02 卡的三個元件：LLM、動作空間、prompt。
