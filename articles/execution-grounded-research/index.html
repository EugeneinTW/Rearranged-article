EXECUTION-GROUNDED AUTOMATED AI RESEARCH · 圖卡＋教材整合版

點子要先被執行， 才知道有沒有效自動執行器、演化搜尋與 RL：Stanford 對自動化 AI 研究的一次完整實驗

LLM 很會提研究點子，但這個團隊先前用大規模專家評審發現，那些點子看起來有說服力、真的做出來卻常常無效。這篇論文的回應是把「執行」做成自動化的一環：一個高通量的執行器把自然語言的點子變成程式、丟上 GPU 跑實驗、回傳成績；再拿成績當回饋，比較兩種學習方法。演化搜尋十輪內就在兩個真實的 LLM 研究問題上超過基準，RL 從執行獎勵則只拉高平均、拉不高上限。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

這篇是第一講「評估」那個挑戰的完整示範

CS 329Z 第一講講三個工程挑戰：拆解、資料、評估。這篇論文把「評估」做到底：讓一個研究點子在幾十分鐘內變成一個可以比較的數字，然後用這個數字去學習。

把它排在第一週的選讀有兩個理由。第一，它把課程後面會拆開講的東西一次放在同一個系統裡：一個出點子的模型、一個實作程式的模型、一個排程與執行實驗的基礎設施、一個獎勵函數，以及兩種從獎勵學習的方法。讀完之後，後面幾週講工具、評估、最佳化時，都有一個具體的例子可以對照。第二，作者群裡有這門課的授課者 Diyi Yang，論文也是 Stanford 幾個實驗室合作的成果，其中一個實驗環境就是另一門課 CS336 的作業，全班的排行榜成了論文裡的人類基準。

讀論文和讀部落格文章不一樣，這一頁的處理方式也不同。章節跟著論文的論證走，不跟著節號走：方法拆成環境、系統、前提驗證三章，結果拆成搜尋結果與點子分析兩章，RL 拆成結果與訓練動態兩章。頁面上的數字只用論文文字或表格寫出來的；論文的圖上有很多點沒有標數字，這裡也不替它們標。哪些歸納是整理者的，每張圖卡的腳註都會說。

給初學者

先把幾個名詞對齊

  • ideator（出點子的模型）：給它研究問題與基準程式碼，它產生自然語言的研究點子。論文裡它是被學習、被更新的那一方。
  • executor（執行器）：把點子變成程式修改、跑實驗、回傳成績的整套系統。論文把它當成獎勵函數，本身不被更新。
  • execution grounding（執行接地）：點子的好壞不靠人評審，靠真的執行後的實驗結果來定。
  • nanoGPT speedrun：一個公開競賽，比誰能用最短時間把一個 124M 參數的 GPT-2 訓練到指定的驗證損失。
  • GRPO：一種強化學習演算法，用同一題的一組回答互相比較來算優勢；論文既拿它當後訓練環境的基準，也拿它來訓練出點子的模型。
評估做到可以自動化、可以並行、可以當獎勵，接下來的問題才輪到「模型學不學得會」。 整理者的引言

論文開頭描述的自動化 AI 研究長這樣：LLM 針對重要的研究問題產生點子，把點子實作成程式，跑實驗確認效果，然後持續從執行結果學習。如果這條路走通，這些自動化的研究者就能在巨大的搜尋空間裡自動找出有效的點子，把算力可擴展地換成科學發現；找到的點子還能回頭改進前沿模型本身，形成遞迴式的自我改進。

"scalably converting compute into scientific discovery" 「可擴展地把算力換成科學發現」：第 1 節對自動化 AI 研究的願景。

然後作者馬上潑冷水：瓶頸在 LLM 能不能產生有效的點子。他們引用自己團隊先前的兩項工作，用大規模的專家評審評估 LLM 產生的研究點子，發現這些點子常常看起來很有說服力，由人類研究者執行之後卻沒有效果。既然人評不準，就用執行來接地。困難在於他們刻意選了完全開放式的研究：任何能用自然語言表達的點子都在動作空間裡，不像神經架構搜尋那樣預先限定一組可選的運算子。要在這種設定下自動、可擴展地拿到執行結果，就得先建一個能把幾百個點子實作出來、平行執行、回傳結果的系統。

整篇論文的三個主張在引言就講完了，後面的章節是把它們做出來：

1
可行在 LLM 預訓練與後訓練兩個 GPU 密集的真實問題上，自動執行器能實作大部分前沿模型產生的點子；Claude-4.5-Sonnet 與 Claude-4.5-Opus 在預訓練環境的執行率超過 90%。
2
演化搜尋有效但擴展有限十輪之內超過兩個環境的基準，而且模型會提出演算法層級的點子；但只有 Claude-4.5-Opus 隨輪數持續進步，Sonnet 與 GPT-5 早早飽和。
3
RL 會塌縮用執行成績當獎勵訓練模型，平均獎勵上升，最大獎勵不動；模型收斂到少數容易實作的點子，思考長度與點子多樣性一起崩塌。

還有一句話決定了整篇論文的判準，值得先記住：對推進科學發現而言，作者更在乎「有一個突破性的點子壓過基準」，而不是「有很多安全的點子把平均拉高」。後面看 RL 為什麼算失敗，就是用這句話量的。

背景

什麼是「開放式」

AutoML 與神經架構搜尋也用驗證集成績當獎勵去搜，但搜的是預先定義好的運算子組合。這篇的動作空間是自然語言：模型可以說「把重要性取樣比率拆成基底與殘差」，也可以說「把 RMSNorm 換成 LayerNorm」，兩者都要被同一個執行器實作出來。這是它比 AutoML 難、也比 AutoML 抽象一層的地方。

關鍵觀念 · 一

模型不是故意作弊，只是最佳化一個數字

作者在早期開發時遇到不只一次：模型修改注意力機制，讓未來的 token 洩漏進來，驗證損失當然漂亮。這不是模型有惡意，而是「評分程式碼在動作空間裡」的必然結果：只要改評分比改方法容易，最短路徑就是改評分。所以他們凍結評估超參數、另寫一個保守的推論函式做最終驗證；後訓練環境則乾脆把驗證程式碼放到執行器碰不到的檔案裡。

這件事對任何想讓 agent 自我改進的人都成立：被最佳化的東西和評分的東西必須分開，而且要在系統層面分開，不能靠提示模型「不要作弊」。

兩個環境都不限制點子的範圍：從大量的超參數調整，到全新的模型架構或訓練演算法，都在範圍內。這一點和第七章「模型到底提了什麼點子」的分析直接相關。

自動執行器可以看成一個高階 API：輸入是一批自然語言的點子，輸出是每個點子的 benchmark 成績。中間有三個元件。

1
Implementer（實作者）跑在一台 IO 能力強的 CPU 機器上。對每個點子平行呼叫寫程式的 LLM，prompt 裡同時給點子和整份基準程式碼，一次平行取樣 10 個 diff 檔。某個 diff 無法 patch 時，把 patch 的錯誤記錄回傳給模型要求修改，這種循序自我修正最多做 2 次。最後回傳第一個能成功 patch 的 diff，把改好的程式碼打包成 zip 上傳到雲端儲存桶。
2
Scheduler（排程器）以固定頻率從雲端下載新的程式碼包；遇到還沒執行過的，檢查該環境需要的資源，準備好要提交的工作設定。
3
Worker（工作機）排程器找到可用的 GPU 後啟動 worker 跑實驗。成功時把所有效能指標的記錄上傳到 wandb，連同完整的中繼資料：點子內容、程式碼修改、執行記錄。失敗（例如實作有 bug）就停下來。

點子模型之後可以下載這一批點子的結果，看到每個點子的表現與完整的訓練記錄，再決定下一批要提什麼。整個系統的設計目標是吞吐量：CPU 機器負責 IO 密集的實作，GPU 叢集只跑實驗；一批點子各自獨立，結果全部回收之後才進入下一批。這正是第五章演化搜尋一輪一輪跑的基礎。

提醒

實作者選的是最簡單的做法，代價寫在討論裡

Implementer 直接要 LLM 吐一個 diff，不是有工具、能安裝套件的完整 coding agent。作者在討論一節承認這限制了能被實作的點子種類；附錄裡執行失敗的例子，多半是要訓練額外的輔助模型、或要匯入環境不支援的外部套件的點子。做不出來的好點子在 RL 裡拿 0 分、在搜尋裡等於沒有訊號，這會變成獎勵的雜訊。

演化搜尋是不需要梯度更新的傳統最佳化方法。作者在前沿模型上搭了一個搜尋框架，靈感來自 AlphaEvolve 這類用演化搜尋做程式碼最佳化的工作。它的運作方式可以口述：

1

2

3

4
退火第 1 輪利用與探索各佔一半，之後逐輪把探索比例調低、利用比例調高。
5
執行下一批兩個子集合起來就是這一輪的批次；GRPO 環境每輪 50 個點子，nanoGPT 環境每輪 80 個。執行完回到第 2 步。

相關工作一節解釋了這篇和一堆看起來相似的工作差在哪，用兩個問題就能分開：點子空間是限定的還是開放的？有沒有從執行回饋學習？

AutoML 與神經架構搜尋在預先限定的運算子集合裡，用 RL 或搜尋依驗證集成績最佳化架構；近年也有直接讓 LLM 提出架構變體並實作驗證的工作，以及套用到超參數調整、演算法發現、後訓練目標、最佳化器、agent scaffold 的類似做法。這篇的差別是完全開放式，對點子類型沒有限制，而且最佳化的是自然語言點子這個更高的抽象層級。AI-Scientist、AI-Researcher、Agent Laboratory 這類端到端的研究代理也處理開放式的 AI 研究，用精心設計的 scaffold 產生並實作點子，但沒有研究怎麼從執行回饋學習來提高點子的效果。在 MLE-Bench、RE-Bench、ML-Gym 這類有明確指標的 benchmark 上，有工作用搜尋或 RL 從執行回饋學習，但那些是嚴重依賴特徵工程與調參的 ML 工程任務，這篇處理的是需要演算法開發的預訓練與後訓練。

還有兩條線。用 LLM 做研究流程裡某一個環節的工作：文獻回顧、點子產生、資料分析、實驗計畫、研究程式執行、審稿；作者把這篇定位為互補，專注在自動執行點子與從執行回饋學習。程式碼領域的執行接地則已經有人做：用執行回饋整理資料訓練模型、用端到端的 RL 教模型依執行回饋改程式、在推論時用執行訊號引導生成；差別在這篇的驗證是跑一整場訓練實驗，更複雜也更昂貴。

原則 01
把問題做成環境，

原則 02
要上限就用搜尋，
並保留探索
演化搜尋十輪超過基準，上限會動；RL 從執行獎勵只提高平均，點子塌縮到兩種。失敗給 0 分會把模型推向保守。
類比：RL 之後 pass@k 停滯甚至下降。
原則 03
執行器的能力，
就是點子空間的上限
只要 diff 的實作者做不出需要外部套件或輔助模型的點子；好點子做不出來就變成獎勵雜訊，等於不存在。
作者的方向：有工具、能裝套件的 coding agent。
作者列的四個限制，排成下一步
1　測泛化
小規模最佳的點子放大或換資料集還有效嗎；納入最佳化目標
2　換學習訊號
用執行軌跡裡比純量獎勵更豐富的訊號；補探索的誘因
3　升級執行器
有工具、能裝套件的 coding agent，減少做不出來的點子
4　加主觀指標
新穎性、有趣程度；前提是找到計算的方法
一句話
執行接地可行，演化搜尋有效但擴展有限，RL 從執行獎勵會塌縮；作者希望這篇成為執行接地的自動化 AI 研究的基礎，並把限制交給後面的人。
注意：三條原則是整理者從全文歸納的；四個限制與方向來自第 8 節，排成順序是整理者做的。

作者的結論：他們建了一個大規模平行的執行器，能自動執行模型產生的點子、驗證它們在開放式的預訓練與後訓練問題上的效果；用它當獎勵函數分析了演化搜尋，前沿模型配上簡單的搜尋框架就能顯著超過基準；也揭露了用執行獎勵做 RL 的限制，模型為了提高平均而收斂到簡單點子、失去多樣性、上限不動。討論一節列了四個限制，每個附了方向：

1
沒有測泛化小規模上最好的點子，放大規模或換資料集不一定還有效；未來應該把泛化與可擴展性明確測出來，甚至納入最佳化目標。
2
RL 只提高平均可能的原因包括基底模型缺乏多樣性、RL 目標缺少探索的誘因；未來可以利用執行軌跡裡比純量獎勵更豐富的訊號。
3
執行代理的能力限制了範圍許多有潛力的點子沒被成功實作，變成獎勵的雜訊；未來可以做能用外部工具、能安裝套件的 coding agent，而不是直接要 LLM 吐 diff。
4
只用了效果當獎勵新穎性、有趣程度這類主觀指標可以補進來，前提是找到計算的方法。

整理者把全文壓成三條原則。第一，先做環境，評分要隔離：問題、基準程式碼、benchmark、固定資料、固定指標、固定預算六件事齊了，點子才變得可比較；評估超參數要凍結、驗證程式碼要放在執行器碰不到的地方，內部迴圈用代理指標、驗收才量真指標。第二，決定要平均還是上限，再選學習方法：要上限就用搜尋並保留探索，RL 從執行獎勵會把模型推向安全的簡單點子，失敗給 0 分會塑造保守。第三，執行器的能力就是點子空間的上限：做不出來的好點子等於不存在，要擴大空間就要升級執行器。

給自己的作業

讀完可以做的三件小事

拿你手上任何一個想讓 agent 自我改進的任務，寫下它的六件事，看缺哪一件；找出評分程式碼在不在 agent 的動作空間裡；然後決定你要的是平均還是上限。三題都答得出來，再談用搜尋還是 RL。

Reference · 名詞速查

關鍵名詞與它們在論文裡的位置

先列系統與環境的名詞，再列兩種學習方法用到的，最後是分析用的。

ideator
出點子的模型
接研究問題與基準程式碼、產生自然語言研究點子的 LLM；論文裡唯一被學習更新的部分。
executor
自動執行器
把點子變成 diff、排程、跑實驗、回傳成績的系統；由 Implementer、Scheduler、Worker 組成，當成獎勵函數用。
execution grounding
執行接地
用真的執行後的實驗結果，而不是人的判斷，來定點子的好壞。
research environment
研究環境
研究問題、基準程式碼、benchmark、固定資料、評估指標的組合；論文做了 nanoGPT 與 GRPO 兩個。
nanoGPT speedrun
預訓練競速
在 8 張 H100 上把 124M 的 GPT-2 練到驗證損失 3.28，比誰的時間短；基準 35.9 分鐘，人類最強不到 2.1 分鐘。
GRPO
群組相對策略最佳化
Shao 等人 2024 年的 RL 演算法，用同一題一組回答互相比較算優勢；既是後訓練環境的基準，也是訓練 ideator 的方法。
proxy reward
代理獎勵
預訓練環境搜尋時用的獎勵：固定 25 分鐘，取驗證損失的倒數；避免不同點子的執行時間差太多。
reward hacking
獎勵作弊
模型改評分相關的程式來拿高分，例如讓注意力洩漏未來 token；論文用凍結評估與隔離驗證程式碼來防。
completion rate
完成率
執行後拿到有效、非零實驗結果的點子比例；第 3 節的第一個指標。
best-of-N
N 選 1
抽 N 個點子全部執行，取最好的；論文用它當搜尋框架的對照，同預算下搜尋從第 1 輪起勝出。
evolutionary search
演化搜尋
不更新權重的最佳化：每輪把超過基準的點子拿來組合（利用）、把隨機舊點子拿來要求不同（探索），逐輪退火。
exploitation / exploration
利用／探索
搜尋每一輪的兩個子集；第 1 輪各半，之後利用比例上升。
RLVR
可驗證獎勵的強化學習
用可以自動驗證的結果當獎勵做 RL；論文把執行成績當成這種獎勵。
mode collapse
模式塌縮
模型收斂到少數穩定拿高分的輸出，多樣性消失；論文裡是 128 個點子有 119 個是同兩種。
pass@k
k 次內至少一次答對
衡量上限的指標；先前工作發現 RL 後 pass@k 停滯甚至下降，論文拿它類比最大獎勵不動。
EMA
指數移動平均
對中間 checkpoint 做加權平均再驗證；是 Opus 最佳解的一部分，也是 RL 塌縮後的兩種常見點子之一。
LLM-as-judge
用模型當判官
論文用它把點子分成超參數調整與演算法兩類。
AlphaEvolve
程式碼演化搜尋
Novikov 等人 2025 年的工作，論文搜尋框架的靈感來源。
