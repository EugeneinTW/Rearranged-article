04 / 12執行器：三段式管線
執行器是三段式的管線，目標是吞吐量
輸入一批自然語言的點子，輸出每個點子的 benchmark 成績；Implementer 在 CPU 機器上做 IO 密集的實作，GPU 叢集只跑實驗
一批點子
自然語言，50 到 80 個；
ideator 送進來
Implementer
點子＋基準程式碼 → 抽 10 個 diff
patch 失敗最多修 2 次
雲端儲存桶
第一個能 patch 的 diff 套上去，
整份程式碼打包成 zip
Scheduler
固定頻率輪詢；沒跑過的就
查資源需求、準備工作設定
Worker
接上 GPU 跑實驗；成功就上傳
失敗就停
回傳什麼
每個點子的效能指標上傳到 wandb，連同完整的中繼資料：點子內容、程式碼修改、執行記錄。ideator 下載這一批的結果與完整訓練記錄，再決定下一批要提什麼。
三個設計取捨
① 實作者只要一個 diff
不是有工具、能安裝套件的 coding agent。需要外部套件或額外訓練輔助模型的點子多半做不出來，作者列為未來方向。
最簡單的做法，先把迴路跑起來。
② 一批獨立平行，結果回收才下一批
幾十到上百個點子各自實作、各自排程、各自跑；全部回來才進入下一輪。這是演化搜尋一輪一輪跑的基礎。
RL 時一批 rollout 要同時用 256 或 1024 張 GPU。
③ 做不出來的點子變成雜訊
執行失敗在 RL 裡拿 0 分，在搜尋裡等於沒有訊號；好點子做不出來，獎勵就低估了它。
討論一節明說這是限制。
注意：三個元件與 10 個 diff、修 2 次的數字來自原文第 2.2 節；「三個取捨」是整理者的歸納，①與③來自原文的討論一節。

06 / 12演化搜尋：利用、探索、退火
演化搜尋靠利用、探索、退火三件事，不更新權重
每一輪的 prompt 都帶著前幾輪的執行結果：超過基準的點子拿來組合，隨機抽的舊點子拿來要求「完全不同」；模型的權重從頭到尾沒動
Step 1　第 0 輪
取樣一整批全新的點子
（GRPO 50 個、nanoGPT 80 個）
Step 2　執行
整批丟進執行器，拿到成績
執行器就是獎勵
Step 3　利用
超過基準的點子進 prompt，
要模型組合它們的優點
Step 4　探索
隨機舊點子塞滿 context，
要模型提完全不同的
Step 5　下一批
兩個子集合起來，
回到執行
每輪退火：第 1 輪利用與探索各半，之後利用比例逐輪上升、探索下降
固定條件
每個環境各用 Claude-4.5-Opus、Claude-4.5-Sonnet、GPT-5 跑，出點子與寫程式是同一個模型。靈感來自 AlphaEvolve 這類程式碼最佳化的演化搜尋。搜尋是序列化的：第 t 輪要等第 t-1 輪的實驗全部跑完。
三個零件各自的作用
① 為什麼算學習
權重沒動，但每輪 prompt 帶著前幾輪的執行結果，模型在 context 裡學到什麼有效。同樣的取樣預算，第 1 輪起就贏過 best-of-N。
best-of-N 沒有記憶，只能加大 N。
② 利用的門檻是「超過基準」
不是排名前幾，是絕對超過基準的點子才進 prompt；模型看到的都是有效的方向。代價是可能太早鎖定一個方向。
Sonnet 在 GRPO 環境就是這樣狂榨一個發現。
③ 探索用的是負向範例
把舊點子塞進 prompt 要求「完全不同」，避開已經試過的區域；退火讓前期廣、後期深。這是多樣性不會消失的原因。
RL 沒有這個機制，第 9、10 卡看後果。

09 / 12RL：平均上升，上限不動
RL 拉高了平均，卻拉不高上限
用執行成績當獎勵、標準 GRPO 微調 Qwen3-30B：平均獎勵像數學題那樣穩定上升，最大獎勵整個訓練都在震盪；科學發現要的是後者
✗ RL 從執行獎勵：更新權重
✓ 演化搜尋：不更新權重

平均變好是訓練成功，不是失敗
目標函數要的是平均，模型就交出平均。這是第一次在開放式研究環境看到平均獎勵隨 RL 上升，曲線和數學題的 one-shot RLVR 類似。
失敗給 0 分，就是在教模型保守。
科學發現看的是那一個突破

12 / 12先做環境，再選學習方法
先做環境，再選學習方法，並記得執行器是上限
整篇讀完可以帶走的三條原則，以及作者在討論一節列的四個限制排成的下一步
原則 01
把問題做成環境，
評分要隔離
問題、基準程式碼、benchmark、固定資料、固定指標、固定預算；評估超參數凍結、驗證程式碼放在執行器碰不到的地方。作者是被模型洩漏未來 token 教會的。
內部迴圈用代理指標，驗收才量真指標。
原則 02
要上限就用搜尋，
並保留探索
演化搜尋十輪超過基準，上限會動；RL 從執行獎勵只提高平均，點子塌縮到兩種。失敗給 0 分會把模型推向保守。
類比：RL 之後 pass@k 停滯甚至下降。
原則 03
執行器的能力，
就是點子空間的上限
只要 diff 的實作者做不出需要外部套件或輔助模型的點子；好點子做不出來就變成獎勵雜訊，等於不存在。
作者的方向：有工具、能裝套件的 coding agent。
作者列的四個限制，排成下一步
1　測泛化
小規模最佳的點子放大或換資料集還有效嗎；納入最佳化目標
2　換學習訊號
用執行軌跡裡比純量獎勵更豐富的訊號；補探索的誘因
3　升級執行器
有工具、能裝套件的 coding agent，減少做不出來的點子
4　加主觀指標
新穎性、有趣程度；前提是找到計算的方法
一句話
執行接地可行，演化搜尋有效但擴展有限，RL 從執行獎勵會塌縮；作者希望這篇成為執行接地的自動化 AI 研究的基礎，並把限制交給後面的人。
