GEPA · REFLECTIVE PROMPT EVOLUTION · 圖卡＋教材整合版

從執行軌跡裡 讀出教訓， 演化出來的 prompt 贏過強化學習GEPA：反思突變改寫指令， Pareto 前緣留下 每一題的贏家

用強化學習調整一個 LLM 系統，常要跑上萬次 rollout，因為每跑一次只拿回一個分數。這篇論文提出 GEPA：讓一個負責反思的 LLM 讀執行軌跡與評分時吐出的文字，找出失敗的原因，把教訓寫進某一個模組的指令；候選版本用 Pareto 前緣保留「在某一題最好」的每一個，互補的版本還能逐模組合併。作者在六個任務、Qwen3 8B 與 GPT-4.1 Mini 上，讓它和跑滿 24,000 次 rollout 的 GRPO、以及 MIPROv2、TextGrad 等 prompt 最佳化器比較。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

調 prompt 對上調權重，這篇把兩條路正面比了一次

Stanford CS 329Z 第 5 週「Optimization」那一講，從 prompt 一路講到微調：prompt 最佳化（GEPA、MIPROv2、OPRO、TextGrad）、test-time compute、LoRA 與 QLoRA、蒸餾、RLHF 與 DPO，最後問什麼時候該調 prompt、調權重、還是加推論算力。這篇就是講題裡 GEPA 的出處，排在這一講的必讀。

同一講的另一篇必讀是 Snell 等人談 test-time compute 的論文，選讀是 MIPRO 與 BetterTogether。這篇 GEPA 論文剛好把講題裡的前兩條路放在同一張表上比：一邊只改 prompt（GEPA、MIPROv2、TextGrad、Trace），一邊用強化學習改權重（GRPO，實驗用 LoRA）。第 5.1 節又把 GEPA 拿去做推論時的搜尋，碰到了第三條路。論文沒有引用 Snell 等人那一篇，兩者的關係是整理者的連結；蒸餾、RLHF 與 DPO、QLoRA 這幾個講題，論文也沒有碰。

論文有 17 位作者，來自 UC Berkeley、Stanford、BespokeLabs.ai、Notre Dame、Databricks 與 MIT，第一作者是 UC Berkeley 的 Lakshya A Agrawal。v1 在 2025 年 7 月貼上 arXiv，主表只有 HotpotQA、IFBench、HoVer、PUPA 四個任務，摘要寫平均贏 GRPO 10%；2026 年 2 月的 v2 加進 AIME-2025 與 LiveBench-Math 兩個數學任務，摘要改成六個任務、平均 6%，PDF 頁首標 ICLR 2026 Oral。v2 的表 3 與附錄幾張圖還是四個任務的版本，讀數字時要分清楚（v1 與 v2 的對照是整理者做的）。下面是整理者照作者名單與參考文獻對出來的補充：本站整理過的 DSPy 論文，作者裡的 Omar Khattab、Arnav Singhvi、Matei Zaharia、Christopher Potts 也在這篇的名單上；選讀 MIPRO（參考文獻裡的 Opsahl-Ong 等人 2024）的 Krista Opsahl-Ong 與 Michael J Ryan，以及選讀 BetterTogether（Soylu 等人 2024）的 Dilara Soylu，也都是這篇的作者。這篇第 2 節的形式化定義就是沿用 DSPy、MIPRO、BetterTogether 等幾篇；實驗裡被最佳化的系統是 DSPy 程式，比較用的 MIPROv2 也內建在 DSPy 裡。作者把程式碼公開在 GitHub 的 gepa-ai/gepa。

這一頁怎麼處理論文，也先說清楚。章節跟著論證走，不跟著節號走：第 1 章是問題，第 2 到 6 章是方法（迴圈、反思突變、回饋函式、Pareto 選擇、合併），第 7 到 11 章是評估，第 12 章是相關工作，第 13 章是結論與代價。有兩處合併：第 3.1 節的 Pareto 選擇和觀察 3 的消融實驗併成第 5 章；附錄 D.1 的 Merge 和觀察 5 的結果併成第 6 章。數字只用正文、表 1 到表 4，以及圖上印出來的值，全部依 arXiv v2。附錄裡最佳化出來的 prompt 很長，這一頁只挑三個當例子，改寫成中文說明。

給初學者

先把幾個名詞對齊

  • GRPO（Group Relative Policy Optimization）：一種強化學習演算法。同一題讓模型產生一組回答，用組內分數的相對高低估計每個回答好不好，再更新權重。
  • LoRA：微調時不動原本的權重，只訓練插在旁邊的小矩陣，便宜很多。這篇的 GRPO 就是用 LoRA 做的。
  • few-shot 示範：在 prompt 裡放幾組「輸入與正確輸出」的例子。MIPROv2 同時最佳化指令與示範，GEPA 只最佳化指令。
  • 支配（dominate）：候選 A 在每一題都不比 B 差、至少一題比 B 好，就說 A 支配 B。被支配的候選沒有任何一題值得留它。

論文從調整 LLM 系統的主流做法講起。帶可驗證獎勵的強化學習（RLVR），例如 GRPO，把「成功與否」當成 rollout 結束時的一個純量獎勵，拿來估計 policy gradient。作者承認這類方法有效，但實務上常要數萬次 rollout 才能學會一個新任務，近期用 GRPO 的工作甚至用到數十萬次。這在很多應用裡是瓶頸：下游系統會呼叫昂貴的工具、從 LLM 取樣的推論預算有限，或者最大、最好的那些模型根本不能微調。

作者的觀察是，就算是很複雜的 LLM 系統，一次 rollout 也能序列化成一段自然語言軌跡：裡面只有各模組的指令、模型產生的推理鏈、工具呼叫，有時還有獎勵函式內部的訊息，例如在被壓成一個分數之前的編譯錯誤。現在的 LLM 讀得懂這種軌跡，所以作者主張，刻意用自然語言、靠反思這些軌跡來學習的演算法，比標準的強化學習更能用上 LLM 本來就有的語言先驗。摘要裡有一句話把這個主張說得最直接：

"the interpretable nature of language often provides a much richer learning medium for LLMs" 「語言的可解釋性，常常是 LLM 更豐富的學習媒介」：摘要拿來對照「從稀疏純量獎勵導出的 policy gradient」的一句。

第 2 節把問題寫成形式化的樣子。一個複合式 AI 系統是由一次以上的 LLM 呼叫組成、中間可能穿插外部工具、由任意控制流程編排的模組化系統；agent、多 agent 系統、ReAct 這類腳手架都算。作者沿用 DSPy 一系列論文的寫法，把系統記成 Φ，把每個模組拆成 prompt 與權重兩種參數。這個寫法同時容納「改 prompt」與「改權重」，就能把在不同參數空間裡工作的方法放在一起比，例如 GEPA 對 GRPO。

提醒

GEPA 只動 prompt，權重完全不動

第 3 節明說 GEPA 只演化 prompt 的集合 Π，模型權重 Θ 固定。所以標題裡的「勝過強化學習」，比的是兩個不同參數空間的方法：在同一個系統、同一批任務上，各自花多少 rollout、最後的測試分數多少。表 1 裡也有 GRPO 贏的任務（第 8 章）。

第 3 節說 GEPA（Genetic-Pareto 的縮寫）有三個核心原則：遺傳式的 prompt 演化、用自然語言回饋做反思、以 Pareto 為基礎挑候選。它的輸入有五樣：一個用簡單 prompt 起始的系統 Φ、訓練集 Dtrain、任務本來的評分函式 μ、會回傳文字的回饋函式 μf（第 4 章），以及 rollout 總預算 B。

遺傳的部分是這樣運作的。候選池一開始只有原本的系統，每一個候選都是「所有模組各配一段 prompt、權重固定」的具體版本。之後進入迴圈，不斷提出新候選，直到預算用完。新候選由既有的候選衍生，方法有兩種：反思突變（第 3 章）或交叉（第 6 章的 Merge）。每個新候選都繼承父代的學習訊號，加上自己這次 rollout 的訊號，所以知識會沿著這棵遺傳樹一路累積。預算用完之後，GEPA 回傳在 Dpareto 上平均表現最好的那一個候選。

這樣的設計有一個代價，作者在觀察 1 自己點出來：GEPA 大部分的 rollout 花在驗證上，也就是新候選入池時在 Dpareto 每一題評分，而這些分數只用來挑候選，不產生學習訊號。第 8 章會看到，只算訓練集上的 rollout，GEPA 用的次數少很多。

第 3.1 節先說明挑候選這一步為什麼重要。GEPA 的設計很模組化，挑候選的策略可以換，而策略決定了探索與利用之間的取捨。最直覺的做法是永遠挑表現最好的那一個，但這常讓最佳化器卡在局部最優：一旦找到一個主導的策略，就很難超越它，最佳化器把預算耗在這個候選上，學不到新的、可能更好的策略。

GEPA 的做法借自 Mouret 與 Clune（2015）的「illumination」策略，寫在演算法 2。對每一個訓練例，GEPA 記下所有候選在這一題的最高分，這些最高分構成一個 Pareto 前緣。至少在一題拿到最高分的候選留下來，被嚴格支配的剪掉。最後從剪完的集合裡隨機抽一個，機率和它「領先的題數」成正比。作者說這讓 GEPA 能跳出局部最優，又不讓搜尋範圍膨脹，把資源集中在帶著「贏的策略」的候選上。

給初學者

為什麼是「每一題」而不是「每一個目標」

一般說 Pareto 前緣，常見的是兩三個目標，例如準確度與成本。GEPA 把驗證集的每一題都當成一個目標：一個候選只要在某一題上是最好的，就代表它帶著某種別人沒有的做法。這樣一來，前緣上的候選數量由資料決定，不需要事先指定要保留幾個。

背景

MIPROv2 怎麼最佳化

附錄 E.4 的描述：MIPROv2 已經整合進 DSPy 與 llama-prompt-ops。它對每個模組先 bootstrap 出一批指令與示範的候選，給它們均勻的先驗，用 Tree-Structured Parzen Estimator（TPE）提出組合，再依評分更新貝氏模型，偏向高分的候選，最後挑最可能好的指令與示範組合、驗證後定案。和 GEPA 相比，它是靠全域的分數，在一批事先產生的候選裡挑組合；GEPA 則是讀回饋、直接改寫指令。相關工作一節也把 MIPROv2 歸在「主要依賴全域獎勵」的方法。

思考題 · 03

換模型的時候，你會重做最佳化，還是先把舊的 prompt 搬過去？

假設你在小模型上調好了一組 prompt，下個月要換成更大的商用模型。

GEPA-Qwen-Opt 的結果說，至少在這六個任務上，搬過去的指令已經贏過在新模型上重新最佳化的 MIPROv2。可以先搬、先量，再決定要不要在新模型上重跑；GEPA 的成本（第 7 章）也讓重跑不算太貴。

第 5.1 節先說明，這篇論文的主軸是讓 AI 系統用少量樣本適應新任務，但初步的發現顯示 GEPA 也可能是一種推論時的搜尋技術。做法是把要解的題目清單（例如一批要轉成 CUDA 的 PyTorch 模組）當成訓練集交給 GEPA，並讓 Dtrain 與 Dpareto 都包含完整的題目。這樣 GEPA 會刻意「過擬合」這組題目，對每一題反覆提出更好的解，而且能把從某一題的 rollout 學到的教訓用到其他題上。

第 5.2 節把 GEPA 反過來用，做對抗式的 prompt 搜尋。獎勵被反轉：最佳化器提議在 prompt 裡加入冷知識之類的額外資訊，目標是讓 pass@1 變低；同時要求 prompt 不能和任務矛盾，而且仍要包含解題需要的所有資訊。演化用的題庫是 AIME 2022 到 2024 年的題目，學到的 prompt 在 AIME-2025 的 30 題上評估，模型是 GPT-5 Mini，每題跑 5 次、共 150 次生成。作者從一段乾淨的指令出發，演化出一段加在每一題前面、通用的對抗指令。

結果是 pass@1 從 76%（乾淨的 prompt）掉到 10%，而題目描述與規定的答案格式都還在。乾淨的 prompt 只是說「你是助理，回答問題，最後用『### <final answer>』的格式給答案」。演化出來的版本在同樣的內容之間，插進了幾句冷知識：蜂蜜不會壞、尼羅河是世界最長的河、海豚之類的哺乳類睡覺時會睜一隻眼。人工檢查發現，GPT-5 Mini 多半在回答結尾照字面寫出佔位用的「### <final answer>」，把格式規則誤讀了。作者認為大幅掉分來自無關細節和嚴格、字面的格式限制之間的交互作用，不是格式要求本身造成的。

作者提的用途

找出最壞情況，而不只是看平均

作者說，對抗式 prompt 搜尋能系統化地找出讓表現大幅下降的指令層級擾動，是一種有原則、自動化的方式，去探測平均指標之外的最壞情況。找到通用、又保留任務內容的干擾（例如冷知識加上嚴格的格式）之後，可以把它們變成可重用的壓力測試與回歸測試，也可以當成微調或安全訓練的資料，做大規模的紅隊測試，追蹤不同模型、版本與領域之間的穩健度變化。

feedback function μf
回饋函式
把評分函式 μ 擴充成除了分數、還回傳 feedback_text 的版本；可以是模組專屬的。
execution trace
執行軌跡
LLM 產生的文字：各模組的輸入、輸出、推理與工具呼叫。
evaluation trace
評估軌跡
環境為了算分數而產生的文字，例如給 0 分之前的編譯錯誤、沒通過的 rubric。
Dfeedback／Dpareto
學習用／挑選用的資料
訓練集切出的兩份：前者抽小批次產生學習訊號，後者只給分數、用來挑候選；實驗裡分別是訓練集與驗證集。
minibatch
小批次
每一輪從 Dfeedback 抽的幾筆例子，實驗裡是 3 筆；新候選要先在這裡分數變高才入池。
Pareto frontier
Pareto 前緣
對驗證集每一題記下的最高分，以及拿到這些最高分的候選；GEPA 從這裡依領先題數抽樣（演算法 2）。
dominated
被支配
某候選在每一題都不比另一個好、至少一題比較差；GEPA 從前緣上剪掉這種候選。
SelectBestCandidate
只挑最好的
消融用的策略：每一輪都從分數最高的候選往下改，類似 TextGrad；表 3 的提升是 +6.05。
BeamSearch
束搜尋
保留前 N 名候選（N＝4），APO 用的做法；表 3 的提升是 +5.11。
System Aware Merge
系統感知的合併
把有共同祖先、各自改了不同模組的兩個候選，逐模組拼成一個；GEPA+Merge 用它，最多 5 次（附錄 D.1）。
GRPO
群組相對策略最佳化
用一組 rollout 的相對分數估計優勢的強化學習演算法；實驗用 LoRA、固定 24,000 次 rollout。
LoRA
低秩適配
只訓練插在旁邊的小矩陣的微調法；GRPO 的設定是 rank 16、α 64。
MIPROv2
指令與示範的貝氏最佳化
同時最佳化指令與 few-shot 示範的 prompt 最佳化器，已整合進 DSPy；No-Demos 版只調指令。
TextGrad
文字梯度
把文字回饋當梯度反向傳播的最佳化器；實驗在 Trace 框架裡實作。
Trace（OptoPrime）
Trace 框架的最佳化器
用豐富回饋與執行軌跡做生成式最佳化的框架，OptoPrime 是它的最佳化器；表 2 的對手之一。
Aggregate
總分
各任務分數的平均；表 1、表 2 是六個任務，表 3 與圖 10、17、18 是四個任務。
generalization gap
泛化差距
最佳化後的 prompt 在測試集與最佳驗證分數之間的差；圖 16 照 Wan 等人（2024）的方法畫。
inference-time search
推論時搜尋
把要解的題目同時當訓練集與驗證集，讓 GEPA 直接替這批題目找更好的解（第 5.1 節）。
adversarial prompt search
對抗式 prompt 搜尋
把獎勵反過來，找出保留任務資訊、卻讓模型大幅答錯的指令（第 5.2 節）。
fastp
加速比例
KernelBench 的指標：產生的 kernel 比 PyTorch eager 快 p 倍以上的題目比例。
PUPA
隱私意識的委派
用可信與不可信的模型回答真實查詢、又不洩漏個人資料的任務；系統是 PAPILLON，回饋拆成品質分與洩漏分。
HotpotQA／HoVer
多跳問答／多跳驗證
都要跨多篇維基百科文件；回饋告訴每一跳還缺哪些文件。
IFBench
遵守輸出限制
測模型能否精確遵守「只回答是或否」這類限制；測試集有 58 種新的、分佈外的限制。
