DYLAN · DYNAMIC LLM-POWERED AGENT NETWORK · 圖卡＋教材整合版

隊伍與溝通結構， 都依任務動態決定DyLAN：先用同儕評分選出隊伍， 解題時中途刷人、夠一致就停

多個 LLM agent 一起解題的系統，成員與溝通方式多半事先寫死：幾個角色、辯論幾輪、每一輪誰都發言。這篇論文提出 DyLAN，把多輪協作寫成一張時間展開的前饋網路，再分兩階段讓網路依任務變形：先讓候選 agent 試跑，把同儕評分從最後一層往回傳，算出每個 agent 的貢獻分數來選人；解題時再由一個 LLM Ranker 中途刷掉排名在後的 agent，多數一致就提早停止。在程式生成、網頁購物、MMLU 與 MATH 四類任務上，它的分數都高於對照方法，API 呼叫次數維持中等。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

隊伍成員與溝通結構，也可以交給系統決定

Stanford CS 329Z 第 5 週「Multi-Agent Systems」那一講（Memory & Multi-Agent Systems 分區），談單 agent 與多 agent 的差別、編排模式、handoff 與狀態轉移、委派與協作，以及協調與錯誤傳播的難處。同一講的必讀是 AutoGen，這篇 DyLAN 是選讀。

依課程的安排，AutoGen 在這一講代表固定的對話式編排：有哪些 agent、誰對誰說話、對話怎麼接下去，由開發者事先寫好。DyLAN 問的是另一件事：如果隊伍裡放誰、這一輪誰還要繼續發言，都讓系統依任務與當下的回答決定，協作會不會更好？論文在引言第一段把 AutoGen 列在多 agent 協作的前作裡，全文只提到這一次；兩篇沒有直接比較，這裡的對照是整理者依課程的安排加的。

放回這一講的講題，下面是整理者的讀法。單 agent 對多 agent：論文的出發點是一個 agent 很難有效率地包辦各種任務，所以轉向多個 agent 協作。編排模式：DyLAN 把多輪協作一律畫成分層的網路，論文的表 1 也把辯論、合併多個回答、反思這些既有的系統畫成節點與邊（第 11 章）。handoff 與狀態轉移：每一步交給下一步的只有上一層的回答，實驗裡每個 agent 的記憶只保留最新一層前人的回覆。委派與協作：程式題分成寫程式與審查兩種角色，由一個 LLM Ranker 決定誰繼續往下。協調與錯誤傳播：作者主張一條線串到底的流程，中間錯了容易一路影響到最後的輸出；分層網路讓好幾個解法同時往前走，由後面的節點評分與挑選，多數一致就停。

給初學者

先把幾個名詞對齊

  • 多 agent 協作：讓幾個帶不同角色提示的 LLM 互相看對方的回答、修正自己的答案，最後合成一個答案。
  • LLM 辯論（LLM Debate）：幾個 LLM 各自作答，再看彼此的答案重答，固定跑幾輪。這篇拿它當主要對手之一。
  • 角色提示（role prompt）：放在 system prompt 的一段描述，例如「你是一位數學家，擅長算術與長期規劃」。
  • 同儕評分（peer rating）：讓 agent 替別人的回答打分數；DyLAN 用它來估每個 agent 的貢獻。
  • 反向傳播（back-propagation）：訓練神經網路時，把誤差從輸出層一層層往回分配的算法。DyLAN 借它的形狀來分配貢獻，但沒有訓練任何權重。

引言先說 LLM agent 已經能推理、寫程式，也被用在電玩與自動駕駛這類具身任務上，但一個 agent 很難有效率地包辦這些任務，所以研究轉向讓多個 agent 協作。作者接著拿人的團隊當參照：已有研究發現，從人類社會借來的溝通結構也能幫助 agent 協作；人的團隊還有另一個特點，會依任務調整成員。

醫院會診是作者的例子。同一場會診裡，討論越深入，有些醫生的專長越不相關，就「離開」了，溝通的結構跟著改變，這是協作中的動態結構。不同疾病的會診，一開始請來的醫生組成也不同，取決於相關的醫學領域與每位醫生能貢獻多少，這是團隊最佳化。這兩個觀察引出論文的核心問題：

"Does a dynamically changing team of agents benefit LLM-powered agent collaborations similarly?" 「會動態改變的 agent 團隊，是否也同樣有益於 LLM agent 的協作？」：第 1 節提出的研究問題。

作者說這個問題還沒有好好回答。現有研究替不同任務設計了不同的溝通結構，例如推理題用辯論、寫程式用自我協作，但這些結構都不更換團隊成員，從頭到尾固定。組隊的方式也有問題：多數研究依人的經驗手寫 agent，或請 LLM 生成 agent，兩種都是事先定好，沒有驗證它們在協作裡是否真的派得上用場；結果不是隊伍一成不變，就是重組隊伍時沒有有根據的檢查。

DyLAN 是作者的回答。它把多 agent 協作寫成時間前饋網路（T-FFN）：每一輪溝通對應網路的一層，節點是那一輪參與的 agent，邊是 agent 之間的溝通。系統分兩個階段運作。第一階段是團隊最佳化：讓候選 agent 先協作一次，用一種仿照反向傳播與神經元重要性分數的前向、反向訊息傳遞算法，替每個 agent 算出貢獻分數（Agent Importance Score），過程不需要標準答案，再選出貢獻最大的幾個。第二階段是解題：由選出的小隊協作，途中一個 LLM Ranker 會停用表現差的 agent，網路因此在解題時長成不同的形狀。作者預告，選人這一步讓 MMLU 某些科目的準確率最多高出 25.0 個百分點（大學數學從 40.0 到 65.0）。

作者列的貢獻有三項：提出兩階段、帶選人機制的 DyLAN；用時間前饋網路加上團隊重組來描述 agent 協作，減少對人的先入之見的依賴；在多種任務上展現準確度、效率與穩定性。

第 3 節先給全貌。DyLAN 分兩個階段：第一階段「團隊最佳化」試跑一次，建出最佳化過的隊伍；第二階段「解題」由這個隊伍協作。兩個階段共用同一個核心元件，就是時間前饋網路 T-FFN。作者說它既是溝通結構的抽象，也是計算圖：解題時沿著它往前傳訊息，選人時沿著它往回傳分數。因為選人要用到解題的元件，論文的講法是先定義網路，再講解題，最後講選人，這一頁也照這個順序。

定義本身很精簡，用文字說就是四件事：

定義 1 · agent

參與協作的 N 個成員

可以是帶工具的 LLM agent，也可以是獨立的工具，例如一段腳本或程式直譯器。

定義 2 · 節點

第 t 層有 N 個節點

每個節點對應一個 agent，也就是這個 agent 在第 t 步的那一次回答。

定義 3 · 邊

只連相鄰兩層

邊是節點之間的溝通管道，從第 t−1 層連到第 t 層，形成 agent 之間的溝通結構。

定義 4 · T-FFN

T 層節點加上層間的邊

作者只考慮相鄰層之間的邊；邊也可以加在任兩個節點之間，表示更複雜的結構。

在網路上傳東西，論文叫訊息傳遞：一個節點從相鄰的節點收到一組訊息，用一個聚合函式把它們合成自己的新訊息。收的是上一步的節點，叫前向訊息傳遞；收的是下一步的節點，叫反向訊息傳遞。解題用的是前向。聚合函式依節點的類型分兩種做法：LLM agent 把收到的回答和題目一起填進 prompt 模板，取模型生成或呼叫工具之後的回覆；工具節點只挑出自己能處理的輸入，例如程式碼或結構化的文字。

推論從第 1 層開始：題目送進第 1 層的每個 agent，之後每一層都看得到上一層所有節點的回答，可以批評、給建議、修正，或做品質審查，看 agent 的設計而定。最後一層的回答裡出現最多次的那個，經過後處理就是輸出。附錄 D 的通識題模板大致如下：

團隊重組的目的是在解題途中找出貢獻較大的 agent，並依此改變溝通結構。做法是多用一個 LLM，論文稱為 LLM Ranker：它讀這一步參與者的回答，依附錄 D 的 Ranker 模板給出排名，排名在前的 agent 才能參加下一步。換成網路的語言，就是只有前幾名的節點和下一層連邊，下一層的邊等於「這一步留下的節點」與「下一步的節點」兩兩相連。這個過程一直重複到符合停止條件，得到專屬於這一題的一張網路。

Algorithm 1 把整個解題寫成一個迴圈。每一步先看是不是重組步：如果是，Ranker 從上一層挑出前 k 個回答，被淘汰的 agent 之後的邊全部拿掉，留下的節點直接沿用自己上一步的回答；如果不是，就照前一章的前向訊息傳遞作答。每一步結束都檢查一次能不能提早停止。跳出迴圈後，最後一層出現最多次的答案經過後處理，就是輸出。

def solve(query, agents, T, reform_steps, k=2):
    layer = [a.answer(query) for a in agents]          # 第 1 層：每個 agent 各自作答
    for t in range(2, T + 1):
        if t in reform_steps:                              # 重組步
            keep = ranker.top(layer, k)                    # LLM Ranker 挑前 k 個回答
            agents = [a for a in agents if a in keep]      # 其他 agent 從此停用
            layer = [r for r in layer if r.agent in keep]  # 留下的沿用上一步的回答
        else:
            prev = shuffle(layer)                          # 打亂順序，避免位置偏誤
            layer = [a.answer(query, prev) for a in agents]
        if agree_ratio(layer) > 2 / 3:                    # 提早停止
            break
    return majority(layer)                                 # 取最多次的答案，再做後處理

提早停止的依據來自拜占庭共識理論：在一輪溝通裡，要容忍 p 個出錯的成員，至少需要 3p＋1 個成員。依這個理論，只要同一層超過三分之二的 agent 答案一致，推論就終止；實務上走到最大步數也會停。作者特別說明，先前研究用的一致性判斷都不適用於多輪、多 agent 的互動，因為那些理論假設的是同一個 LLM 跑很多次，或是要求所有 agent 答案完全相同。

附錄 B.1 把幾個數字定了下來。選人之後，網路每一層固定 4 個節點（程式題是 4 個寫程式、4 個審查，輪流上場），因為提早停止至少要 4 個成員，才能在某一步容忍一個不同的回答：超過三分之二一致，代表 4 個裡至少 3 個相同，剩下 1 個可以不同。Ranker 每次留下 2 個（k＝2），作者說這是協作的最少人數，實驗上也在效果與效率之間取得好的平衡。判斷一致的方式依任務而定：選擇題與決策題要答案完全相同；程式這類開放式的生成，用 BLEU 分數超過門檻來判斷（第 4.3 節寫的門檻是 0.9）。

思考題 · 01

你的多 agent 系統，憑什麼決定「可以停了」？

想一個你正在做或用過的多 agent 流程：它是跑滿固定輪數，還是有某個條件讓它提早結束？答案是選項、數字，還是一段程式或文字？

答案能直接比對的任務（選擇題、分類、行動），可以照 DyLAN 用「超過三分之二一致」當停止條件，隊伍至少 4 個才容得下一個異議。答案是程式或長文時，字面相似度很難判斷一致，程式題的早停在論文裡只省了 11.3%；可以考慮改用能執行的檢查，例如單元測試。

團隊最佳化的目標，是依候選 agent 在一次試跑裡的貢獻選出一個子集合，讓新隊伍解題更有效、也更有效率。試跑用的就是前一章的解題流程，得到一張網路；團隊最佳化再以這張網路、候選名單與題目為輸入，輸出選出來的 agent。作者把這個函式實作成三個步驟，合稱 agent selection：

1
傳播（Propagation）每個節點替前一步各節點的解答打分，是一次前向訊息傳遞。節點收到的訊息就是上一步各 agent 的回答；聚合函式換成評分函式，輸入是這個節點的 prompt、題目與收到的回答，輸出是它給每個前一步節點的分數。
2
聚合（Aggregation）每個節點把後繼節點給自己的評分收回來，算出自己在這一步的貢獻，是一次反向訊息傳遞。算法是加權和：一個節點的貢獻，等於每個後繼節點的貢獻乘上該後繼節點給它的評分，再全部相加。
3
選擇（Selection）把同一個 agent 在所有步的貢獻加起來，就是它的 Agent Importance Score；依分數取前 k 名，組成最佳化後的隊伍。

實作上先把貢獻放在最後一層，再一層層往回做聚合（Algorithm 2）。起點怎麼放，附錄 B.2 寫得很具體：推理與決策任務，把貢獻平均分給最後一層答案一致的 agent；程式任務，平均分給最後一輪答案沒有語法錯誤的節點。作者指出，這個定義保證每一層的貢獻加起來都是 1，不同層、不同 agent 的分數才能公平比較。整理者補一句為什麼：每個評分者給出的權重加起來是 1，往回分的時候，總量既不會多也不會少。

評分怎麼拿到，只多一句話。附錄 B.2 在每個節點的 prompt 最後加上一個要求：作答之外，替其他 agent 的每個解答打 1 到 5 分，寫成像 [[1, 5, 2, ...]] 這樣的清單，清單長度等於前一步的節點數。這些分數和要往下傳的回答，從同一段回覆裡一起取出；每個評分者的分數再除以總和，變成加起來為 1 的權重。評分前一樣先打亂前人回答的順序，避免位置偏誤。

def importance_scores(layers, final_answer):
    I = {}                                          # I[(t, agent)]：這個 agent 在第 t 步的貢獻
    T = len(layers)
    good = [n for n in layers[T - 1] if n.answer == final_answer]
    for n in good:                                  # 程式題改成「沒有語法錯誤」
        I[(T, n.agent)] = 1 / len(good)             # 起點：一致的節點平分 1
    for t in range(T, 1, -1):                       # 從最後一層往回
        for rater in layers[t - 1]:
            w = normalize(rater.scores)             # 1 到 5 分 → 加起來為 1 的權重
            for prev, weight in w.items():
                gain = I.get((t, rater.agent), 0) * weight
                I[(t - 1, prev)] = I.get((t - 1, prev), 0) + gain
    total = {}
    for (t, agent), v in I.items():
        total[agent] = total.get(agent, 0) + v      # 跨層加總 = Agent Importance Score
    return total                                    # 取前 k 名組成隊伍

這個設計的靈感有兩個來源。一個是訓練神經網路用的反向傳播，把誤差從輸出一層層往回分配。另一個是神經元重要性分數（Yu 等人 2018），用來衡量網路裡每個神經元對輸出有多重要。相關工作一節也提到，人的團隊研究早就用技能貢獻與同儕評分來挑選、管理工作者（第 11 章）。DyLAN 把兩邊接起來：評分來自同儕，分配的方式借自反向傳播。

整理者的提醒

起點是共識，不是正確答案

醫生第 1 步沒有作答，只拿到 0.03，但它在第 2 步跟著多數答 (D)，又分到 0.33，總分反而高過經濟學家。原因在起點的規則：最後一層的貢獻只看答案是否一致，不看答案對不對，也不看是誰先想出來的。這一題的共識剛好是對的；如果多數一起答錯，分數就會流向那個錯的共識。這是整理者依附錄 B.2 的定義推出來的，論文沒有分析這種情況；第 10 章的領域外實驗和這一點有關。

圖 5 是一題程式：寫一個函式，回傳 2 的 n 次方除以 p 的餘數。第 1 步幾個寫程式的 agent 各寫一版，其中有的版本是錯的，有一版用了 numpy 卻沒有匯入。第 2 步輪到審查：Unit Tester 實際跑測試，四版裡兩版通過；Syntax Checker 是純工具，抓到那一版的 NameError；Code Reflector 指出有一版沒處理 p 等於 1 的情況，另一版忘了匯入套件。第 3 步寫程式的 agent 依審查修改。第 4 步重組：Ranker 認為雖然有一版顧到了邊界情況，另外兩版在效率與可讀性上更好，只留下這兩版；兩者都寫成 Python 內建的 pow(2, n, p)，答案一致，在第 4 步提早停止。

圖 7 是失敗的例子。題目要在格子上找長度為 k 的最小路徑，第 1 步 Algorithm Developer 用 heap 寫的解法其實是對的；第 2 步的 Code Reflector 卻說這段程式「不夠精簡」，把修改帶往錯的方向；第 3 步停下來的答案改用深度優先搜尋，結果逾時失敗。這個例子說明，審查者給的意見本身也可能是錯的，而後面的節點會照著改。

思考題 · 02

如果讓你的 agent 互相打分，你會拿什麼當起點？

DyLAN 的貢獻從最後一層往回分，起點在推理題是「答案一致」，在程式題是「沒有語法錯誤」。想一想你的任務裡，有沒有比共識更可靠、又不需要人工標註的訊號。

能執行的檢查通常比共識可靠：程式有單元測試，資料處理有 schema 驗證，網頁操作有最後的頁面狀態。把起點換成這類訊號，分數才會流向真的做對事的 agent；沒有這類訊號時，至少讓候選裡有對題的角色，避免多數一起錯。

你的任務裡，哪些角色其實不該進隊伍？

列出你會放進多 agent 系統的角色，再想一想：對某一類題目，有幾個角色是真的相關的？如果答案是「一兩個」，其他角色在協作裡是在幫忙，還是在干擾？

論文的限制放在附錄 A，再加上散在正文的代價，整理如下：

1
開放式答案難判一致程式題用 BLEU 判斷一致只是權宜之計，CodeBLEU、CodeT 這類針對程式的方法可能更好；程式題的提早停止只省了 11.3%（第 9 章）。
2
候選裡要有對題的人多數 agent 的設計和任務要求相反時（例如寫程式的 agent 去答臨床問題），表現會差；作者建議複製高分的 agent，而不是補進低分的，必要時從更強的模型引進 agent 並加以驗證。公共關係的提升最小、領域外的分數不比平均分配好（第 8、10 章），指的是同一件事。
3
選人與刷人還是分開的作者說這篇只是把協作外的選人和協作中的重組簡單接起來，怎麼更細地結合還有待研究；資料少的時候，貢獻評估也可以搭配人工標註。
4
第一階段的成本另計主結果主要回報解題階段的呼叫次數，團隊最佳化那次試跑的成本不在裡面（第 6 章）；附錄 C.1 顯示只用 10% 的資料選人，分數也接近。
5
模型與對手數字的來源實驗用 2023 年的 gpt-3.5-turbo；GPT-4 的比較沿用對手論文的數字，呼叫次數是估計的（第 7 章）。

倫理聲明從應用談起：DyLAN 可以用在軟體開發、虛擬聊天室、電玩這類開放環境，使用者只要粗略交代團隊要有哪些 agent，它就能自動最佳化出更有效率的多 agent 系統，減少人設計 agent 的工夫。作者也說，DyLAN 的整體架構呼應了線上工作者的最佳協作組織，也許能反過來用 LLM agent 模擬並最佳化人的協作。風險方面，論文用的 GPT-3.5、GPT-4 可能給出不當的回應；手寫或 LLM 生成的 agent，也可能在協作中做出不符社會原則的行為或回應，作者認為團隊最佳化或許能減輕這個問題。

整理者的讀法

放回這一講：兩個可以調的旋鈕

下面是整理者的連結，論文沒有用這一講的詞。課程講的編排與委派，在 DyLAN 變成兩個可以調的旋鈕：一是隊伍組成（第一階段，靠試跑與同儕評分），二是溝通結構（第二階段，靠 Ranker 與一致性門檻）。handoff 的內容刻意很少，每一步只交出上一層的回答。錯誤傳播的處理方式，是讓多條解法並行、由後面的節點評分與挑選，並用「超過三分之二一致」當共識門檻。和 AutoGen 那種由開發者寫好對話流程的編排對照，DyLAN 把一部分編排的決定交給執行時的回答，代價是多一次試跑與一個額外的 Ranker。

DyLAN 需要訓練模型嗎？
不需要。所有 agent 都是透過 API 呼叫的現成 LLM（主要是 gpt-3.5-turbo），選人靠的是一次試跑裡的同儕評分，不更新任何權重。
貢獻分數需要標準答案嗎？
不需要。起點是最後一層答案一致的節點（程式題是沒有語法錯誤的節點），再依同儕評分往回分配；作者用需要標準答案的 Shapley value 當對照，驗證它在領域內接近。
選出來的隊伍一定比較好嗎？
在論文的實驗裡，選人後三類任務都變好（表 5）；但提升依科目差很多，大學數學 +25.0、公共關係只有 +4.5，候選人都不對題時，貢獻分數和平均分配差不多（表 15）。
先讓候選人真的一起做一次，再決定誰留下；解題時也一樣，看回答決定誰繼續說話。 整理自第 1、3.3、3.4 節

每個節點替上一步的解答打 1 到 5 分，再正規化成加起來為 1 的權重（附錄 B.2）。
Shapley value
Shapley 值
需要標準答案的貢獻指標：成員加入各種組合後平均多出的表現；附錄 C.6 用它驗證貢獻分數。
in-domain／off-domain
領域內／領域外
隊伍裡至少一個 agent 的角色對應題目的大類，就是領域內；一個都沒有就是領域外。
#API calls
API 呼叫次數
每題平均呼叫模型的次數，論文拿它當成本的代理指標。
Pass@1
一次通過率
程式題第一次交出的程式就通過單元測試的比例。
HumanEval
程式生成基準
164 題函式層級的程式補全，每題附單元測試。
WebShop
購物網站環境
照顧客描述找商品；reward 衡量相符程度，等於 1.0 才算成功。論文用測試集的 50 個環境。
MMLU
通識題基準
57 科的四選一題目；論文從測試集抽五分之一。
MATH
數學題基準
7 個子領域、5,000 題測試題。
LLM Debate
LLM 辯論
多個 LLM 固定輪數互看答案再重答；MMLU 與 MATH 的主要對手。
LLM-Blender
回答合併
一輪呼叫多個 LLM，用成對排名合併最好的回答。
