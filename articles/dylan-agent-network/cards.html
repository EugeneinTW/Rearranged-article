02 / 13固定的團隊與結構
人的團隊會換人，多數 agent 團隊不會
第 1 節：會診時討論越深，有些醫生不再相關就離開；不同的病，一開始請的醫生也不同。現有的多 agent 系統兩件事都沒做，DyLAN 兩件都做
✗ 固定的團隊與結構
✓ DyLAN：選人、刷人、提早停止
事先寫好的角色：人寫或 LLM 生成
固定人數、固定輪數
第 1 輪
全員各自作答
第 2 輪
全員看彼此的答案再答
第 3 輪
跑滿輪數才取答案
成員從頭到尾不變
角色沒經過驗證
推理題的辯論、寫程式的自我協作都是這樣：幾個角色事先寫好，每一輪全員發言，跑滿輪數才取答案。組隊時也不檢查這些角色在協作裡是否真的派得上用場。
候選 agent：7 到 12 個角色
第一階段 · 團隊最佳化
全員試跑、互相打分，選前幾名
不需要標準答案
第二階段 · 解題
Ranker 中途刷人，超過 2/3 一致就停
每一題的網路都不同
選出的小隊交給第二階段；誰留到最後、走到第幾步，看這一題的回答。
這一題的答案
第一階段對應會診的「不同疾病請不同醫生」，第二階段的刷人對應「討論越深，有人離開」。兩個階段都不看標準答案，依據是 agent 之間的互評與回答是否一致。
成員與輪數，從頭到尾不變
辯論固定幾輪、每輪全員發言；角色由人手寫或 LLM 生成，事先定好，不看它們在協作裡的實際表現。
結果：隊伍一成不變，或重組時沒有有根據的檢查。
兩個階段，都依任務變形
第一階段依試跑時的同儕評分挑人；第二階段由 Ranker 刷掉排名在後的 agent，多數一致就停。
選人之後，MMLU 某些科目的準確率最多高出 25.0 個百分點。
注意：會診的比喻與「辯論」「自我協作」兩個例子都出自原文第 1 節；左邊的三輪與右邊的兩階段排法是整理者的示意。

怎麼讀這張網路
01
一層＝一步：這一步每個 agent 各回答一次。圖上畫 4 個 agent、4 步。
02
一個節點＝某個 agent 在這一步的那次回答；agent 可以是 LLM，也可以是程式直譯器這類工具。
03
一條邊＝把上一步的回答放進這一步的 prompt，也就是前向訊息傳遞；放之前先打亂順序。
04
最後一層的回答裡，出現最多次的那個經過後處理，就是答案。
05
t = 3 是重組步：Ranker 讀第 2 步的回答，只讓前 2 名往下走，其餘節點停用（第 4 卡）。
同一張網路，兩種用途
解題時沿著邊往前傳回答；選人時沿著同一組邊把評分往回傳（第 5 卡）。作者說它既是溝通結構，也是計算圖。
論文先定義網路，再講解題，最後講選人。
節點可以是工具
程式題的 Syntax Checker 是不用 LLM 的純工具，Unit Tester 帶著程式直譯器；工具節點只挑自己能處理的輸入。
四類任務裡只有程式題給了工具，和對手一致。
只連相鄰兩層
作者只考慮相鄰層之間的邊；每個 agent 的記憶
也只留最新一層前人的回答，避開 context 太長的問題。
邊也可以加在任兩個節點之間，表示更複雜的結構。

05 / 13貢獻分數：往回乘的評分
貢獻分數是同儕評分，沿著網路往回乘
第 3.4 節、附錄 B.2 與 Algorithm 2：候選團隊先試跑，每個節點作答時順便替上一層打分；再從最後一層往回，把貢獻依評分分下去
Step 1　試跑
全部候選 agent 解題，
含重組與提早停止
Step 2　同儕評分
替上一層每個回答打 1 到 5 分
前向
Step 3　正規化
每個評分者的分數除以
總和，變成權重 w
Step 4　反向聚合
從最後一層一層往回分
反向
Step 5　跨層加總
各層相加＝貢獻分數，
取前 k 名組成隊伍
起點與規則
最後一層：答案一致的節點平分 1（程式題是沒有語法錯誤的節點）。往回每一層：一個節點的貢獻＝Σ（下一層某節點的貢獻 × 那個節點給它的權重）。每一層的貢獻加起來都是 1。
圖 2 右半的示意值：第 4 步一個節點給第 3 步三個回答 0.4、0.5、0.1；第 3 步一個節點從後繼收回 0.7、0.5、0.4；四個 agent 的分數 0.65、0.35、1.15、0.20，選最高的 2 個。
三件事讓它可以直接拿來用
① 不需要標準答案
起點用「答案一致」代替「答對」，分數完全來自 agent 之間的互評；作者稱它為無監督的指標，沒有標籤的題目也能跑。
靈感來自反向傳播與神經元重要性分數。
② 只多一句 prompt
每個節點的 prompt 最後加一句：替其他解答
打 1 到 5 分，寫成 [[1, 5, 2, ...]]。
分數和回答寫在同一段回覆裡，一起取出。
評分前先打亂前人回答的順序，避免位置偏誤。
③ 每層加起來都是 1
每個評分者的權重和為 1，往回分的時候
總量不變；不同層、不同 agent 的分數，
因此能放在同一把尺上比較。
「和為 1、利於公平比較」是作者寫的，理由是整理者補的。
注意：依 Algorithm 2 與附錄 B.2 畫的；規則條的式子是第 3.4 節式 11 的文字版。圖 2 的數字是示意值，實驗裡選人後每一層是 4 個節點。

為什麼拿 Shapley value 當對照
它看一個 agent 加入各種組合後，整體表現平均多出多少；需要標準答案，也要把不同的子集合各跑一次，成員一多組合數就爆炸。所以只能拿來驗證，不能拿來選人。
直接可以拿去用的三條
① 先確認候選裡有對題的角色：多數 agent 和任務不合時，選人也救不了（附錄 A）。
② 工具型 agent 要靠評分才選得到：GPT-4 模擬的人選漏掉了 Unit Tester 與 Syntax Checker（C.3）。
③ 一次試跑的分數可以重用：同一組分數拿來試不同的寫程式與審查人數（表 8）。
注意：人選是用 GPT-4 讀任務與角色描述來模擬的；Shapley value 的實驗是從 7 個候選人裡隨機取三組、每組 3 人。

組隊：角色事先定好
有的研究依子任務挑工具，有的讓 LLM 依題目生成固定數量的角色。作者認為沒驗證過的描述，未必帶來想要的能力。

溝通結構：多半固定
辯論跑固定輪數，LLM-Blender 在一輪裡合併回答；也有研究發現，最佳結構會隨任務與成員組成而變。
