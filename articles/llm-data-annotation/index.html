讓 LLM 標註資料， 也讓它合成資料一份 EMNLP 2024 綜述， 把研究分成產生、評估、使用三段

資料標註費工又費錢，GPT-4 這類大型語言模型能接手其中一大部分。這篇 2024 年的綜述整理「讓 LLM 當標註者」的研究：LLM 能產生哪幾種資料，這些產出怎麼評估、怎麼篩選，又怎麼拿去微調、對齊與推論；最後談模型崩潰、幻覺、偏誤與算力這些代價。這一頁照它的分類逐段整理，每段只挑綜述自己舉的例子，不列書目。每章開頭先放一張圖解卡講重點，往下是詳細作法；想速讀就切到「只看圖卡」。

為什麼要找 LLM？綜述說資料的複雜、主觀與多樣讓標註很難做好，需要領域專業；大規模的人工標註或建資料集，非常耗資源。GPT-4、Gemini、LLaMA-2 這類模型能把標註自動化，在大量資料上保持一致，也能透過微調或 prompting 適應特定領域，明顯減輕傳統標註與合成方法的負擔。

它和其他 LLM 綜述的差別也寫得很清楚。既有的綜述多半整理架構、訓練方法與評估協定，關心的是模型做翻譯、對齊、寫程式、醫療分析這類終端任務的能力；這一篇只看「拿 LLM 來標註與合成資料」這件事。範圍另有一個限制：主要談純語言模型，不深入 LLaVA 這類新興的多模態 LLM。

第 2 節只有一段，卻定下全篇的兩個角色。標註者 A 把輸入資料變成標註，綜述關注的是 GPT-4、LLaMA 這類先進的 LLM；任務學習者 L 用這些標註資料去完成指定的任務，可以是另一個大模型（綜述引的是 Vicuna），也可以是 BERT 這種較簡單的模型。標註的內容也不只類別標籤，還包括信心分數、脈絡細節與其他 metadata，替原始資料補上各種輔助訊號。

第 3.1 節先交代背景：早期的 NLP 資料集主要靠人工標註者建出來；有了 LLM 以後，自動、生成式的方法越來越受重視。這一節是整個第 3 節最長的一段，底下只有兩個小標：指令多樣性與回應品質。

先看多樣性。綜述引的研究證實，指令的多樣對 LLM 的學習很關鍵，於是有許多方法想在原本的資料上擴增出更多樣的指令。依綜述的描述，大致可以分成三種取材方式（分法是整理者的）：

從現有樣本變化

混合、改寫、挑種子

Yoo 等人（2021）把兩個樣本混成一個新樣本；Li 等人（2023a）把同一個樣本改寫好幾次，幫 LLM 從不同角度理解；Köksal 等人用分群挑初始種子，確保種子本身夠多樣。

思考題 · 01

你的 agent 缺的是哪一種資料？

想一個你正在做的 agent 或 LLM 應用，它在哪一類請求上最常出錯。

如果錯在「沒見過這種請求」，缺的是指令的多樣，可以從種子擴增、換人設或換屬性產生新指令；如果錯在「見過但答不好」，缺的是回應品質，可以試多候選挑信心、附上檢索文件、用原則約束。這個二分是整理者的建議。

成對回饋的形式很單純：同一個問題的兩個回答，標出哪一個比較好。圖 2 第三列的例子：使用者問「2025 年的美國總統是誰？」，LLM 給出兩個輸出，A 說自己的知識有截止日、沒辦法預測，B 自信地說出一個名字；再請 LLM「選出對這個指令比較好的輸出」，它回答比較誠實、準確的是 A。綜述把自動造出這種偏好對的方法分成兩種：

兩種做法差在「好壞由誰決定」：排序法讓 LLM 或偏好模型在產生之後判斷，直接構造法在產生之前就用假設定好了。綜述說直接構造通常得先做各種假設，但沒有討論假設不成立的情況；假設錯了，造出來的一對可能好壞顛倒，這是整理者的提醒。

文字回饋不選邊，而是寫出意見。第 3.5 節說 LLM 產生的文字回饋通常點出目前輸出的缺點，或建議具體的改法，所以能拿來潤飾或評估回答。圖 2 第四列：使用者說自己對打桌球有興趣，LLM 回答那是社交、保持活躍的好方式；請它給回饋，它寫下「相關：回應和使用者的輸入有關，也對他的嗜好表示興趣」，並打了分數；LLM 再依這段回饋改寫，新的回答具體說到桌球能保持活躍、也能和別人交流。

綜述列的用途有三類。第一，在問答、翻譯、幻覺偵測這些任務裡，替 LLM 設計 prompt、產生有資訊量的回饋。第二，把辯論與同儕審查當成回饋，增強 LLM 的推理（Du 2023a 等）與評估（Li 2023d 等）能力。第三，分析 LLM 產生錯誤或不理想回答的原因，讓它反思、從錯誤中學（Wang 與 Li 2023、An 2023 等）。附錄表 2 列的 SELF-REFINE、Reflexion 都屬於這一節。

崩潰長什麼樣子？模仿別的模型的模型，常常複製了風格，卻達不到更強模型的事實精確度（Gudibande 2023、Shumailov 2023）。原因有兩種誤差：樣本有限造成的統計近似誤差，以及模型容量受限造成的函數近似誤差；兩者都會在一輪又一輪的訓練中被放大（Alemohammad 2023）。

第 8 章的自我演化，是同一個模型在自己產生的資料上反覆微調；這一講的資料飛輪，也是讓系統的產出回到資料裡。兩者都在做模型崩潰描述的事：拿模型的產出訓練模型。

思考題 · 03

你的資料飛輪，吃進去的有多少是人的？

回頭看你的系統：每一輪拿去改進它的資料，來自哪裡？使用者的真實請求、人寫的修正，還是模型自己的輸出？

可以替每一輪的訓練資料記下來源比例，並保留歷來的真實資料，不要每一輪只換成最新的合成資料。比例該多少，綜述沒有給數字，要靠自己的評估集觀察效能有沒有下滑。這些是整理者的建議。

幻覺。LLM 的幻覺嚴重損害它產生的標註的完整與可靠，脫離事實的輸出會讓錯誤資訊擴散。綜述說，處理幻覺要改進訓練流程，並透過自動與人工驗證替標註建立驗證機制；LLM 本身不透明，也讓人更難查出幻覺的原因。可能的解法：Yang 等人（2023d）的反向驗證從回答建出一個查詢，在 LLM 的內部知識裡找有沒有對得上的內容，做段落層級的幻覺偵測；Bertaglia 等人（2023）用 CoT prompting 產生預測的解釋，讓輸出有邏輯、可驗證；Li 等人（2023b）的 CoAnnotating 依不確定度在人與 LLM 之間分配工作，用自我評估與熵衡量可靠度；Zendel 等人（2024）提出人與 LLM 共同標註的流程。

偏誤與倫理。第 6.1 節說，LLM 標註最關鍵的疑慮之一是倫理，尤其在金融、司法、醫療這類高風險的決策。LLM 標註雖然有效率，少了人的洞察，可能帶來偏頗、不公平的結果；LLM 也讓人類標註者的工作變得多餘，可能擴大社會差距（Dillion 2023）。作者主張未來的研究要把技術進展和社會後果放在一起考慮：確保合乎倫理的使用、促進公平、保持透明。

算力與效率。模型越來越大、越來越複雜，需要大量運算資源；有效率的模型能降低推論延遲、耗能與雲端的營運成本。可能的解法有三種：剪枝減少參數，例如 Ma 等人（2023）依梯度資訊移除冗餘的神經元，同時保留大部分能力；專家混合（MoE）讓每個輸入只啟用一部分專家子模型；量化把表示參數的數字從 32 位元浮點降到 16 位元浮點、8 位元整數或更低。這些技術可以組合使用。

放回這一講：一張選資料的檢查表

這一講問的是 agent 需要什麼資料。綜述的回答可以讀成一張檢查表：你要的是示範（指令與回應、推理過程）、回饋（成對或文字），還是標籤；產出之後用什麼評估、用哪一種訊號篩；最後是拿去微調、對齊，還是放進推論時的 prompt。資料飛輪把這三段接成迴圈，模型崩潰提醒迴圈裡要一直有真實的資料。這一段是整理者的連結，不是綜述的主張。

Reference · 名詞速查

關鍵名詞，與它們在綜述的位置

先列全篇的角色，再依產生、評估、使用排，最後是挑戰。

data annotation
資料標註
替原始資料加上相關資訊：類別、信心分數、關係、語意角色、時間順序；引言列了八種（第 1 節）。
data synthesis
資料合成
直接產生新的訓練資料：指令、回應、推理、成對與文字回饋（引言的 ❽、第 3 節）。
annotator model（A）
標註者
把輸入變成標註的模型；綜述關注 GPT-4、LLaMA 這類 LLM（第 2 節）。
task learner（L）
任務學習者
用標註資料完成任務的模型，可以是另一個大模型，也可以是 BERT（第 2 節）。
instruction & response
指令與回應
LLM 微調與 ICL 資料的兩個基本元件；兩個標準是指令多樣、回應品質高（第 3.1 節）。
rationale
推理過程
解題的思考路徑；早期靠專家標，CoT 之後可以由 LLM 產生（第 3.3 節）。
pairwise feedback
成對回饋
兩個回答中哪個比較好；靠 LLM 排序或直接構造產生（第 3.4 節）。
textual feedback
文字回饋
指出輸出的缺點或建議改法，用來潤飾或評估回答（第 3.5 節）。
CoAnnotating
人機共同標註
依不確定度在人與 LLM 之間分配標註工作的框架（第 3.2、6.2 節）。
West-of-N
最好與最差配對
用預訓練的偏好模型挑出最高分與最低分的回答，配成一對偏好資料（第 3.4 節）。
Turking Test
標註準則測試
由人檢查 LLM 是否遵守資料標註準則，拿它的輸出和基準資料集比（第 4.1 節）。
LLM-as-a-judge
LLM 當評審
讓 LLM 評合成資料或回答的品質，可以設門檻決定去留（第 4.1 節）。
Pass@k
程式生成指標
程式生成的評估指標，綜述拿它當任務專屬評估的例子（第 4.1 節）。
rule-based filtering
規則篩選
依長度、關鍵字、格式、對話輪數與語意相似度篩掉資料（第 4.2 節）。
self-evolution
自我演化
LLM 同時當標註者與學習者，在自己標的資料上反覆微調，例如 self-improve（第 5.1 節）。
distillation
蒸餾
用大模型產生的資料訓練較小、較便宜的模型，也用來蒸餾醫學、金融、科學的知識（第 5.1 節）。
reward modeling
獎勵建模
用合成的偏好資料訓練或改進獎勵模型（第 5.2 節）。
DPO
直接偏好最佳化
不另外訓練獎勵模型，直接用偏好對調策略；綜述說這是合成偏好最常見的用法（第 5.2 節）。
in-context learning（ICL）
情境內學習
在 prompt 裡放任務描述與示範、不改權重；三部分都能用 LLM 的產出補強（第 5.3 節）。
model collapse
模型崩潰
用其他 LLM 的輸出訓練，效能逐漸下降；可能的解法是累積真實與機器資料（第 6.2 節）。
hallucination
幻覺
脫離事實的輸出，損害標註的可靠；可用反向驗證、人機分工處理（第 6.2 節）。
Mixture of Experts（MoE）
專家混合
每個輸入只啟用一部分專家子模型，是綜述列的效率解法之一，另兩個是剪枝與量化（第 6.2 節）。
Persona Hub
人設庫
從網路資料自動整理出的 10 億個人設，用來大規模產生多樣的合成資料（第 3.1 節）。
