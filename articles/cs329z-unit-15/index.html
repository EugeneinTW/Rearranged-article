Prologue · 整理者的引言

兩篇都在搭考場，相隔 21 個月

WebShop 在 2022 年 7 月上 arXiv，OSWorld 晚了 21 個月。兩篇都做了一個讓 agent 動手的環境、一批題目與自動評分，再拿模型和人比。這一頁不重述兩篇，而是把它們放在一起讀：介面、評分與差距各怎麼處理，數字各在什麼條件下量出來，後來的單元怎麼用它們。

CS 329Z 第 11 週星期三的「Frontiers & Open Problems」屬於「Open Problems & Final Demos」分區，是課程的最後一講。課程頁列的講題有六個：多模態 agent；web agent 與電腦操作（computer use）；科學 agent；長時間執行的 agent 架構；上線與可觀測性（tracing、監控、成本）；以及可靠度、擴展性、可解釋性的開放問題。這一講沒有必讀，兩篇選讀本站都整理過：

兩篇的證據形式相近，但有三個差別，後面每一章都要記得。第一，兩篇都是基準：各自搭環境、出題、寫評分，再拿模型和人比，都不是在提一種新的 agent。第二，受測的模型差了一個世代：WebShop 的 agent 是作者用人類示範與強化學習訓練的 BERT 與 BART（2022 年）；OSWorld 測的是不另外訓練、直接下 prompt 的 GPT-4V、Gemini、Claude-3 等模型（2024 年）。第三，兩篇都叫「成功率」，算法不同：WebShop 只算獎勵剛好是 1 的回合，平均獎勵另外叫分數（WebShop 第 4 章）；OSWorld 的獎勵在部分達成時也給一個小於 1 的分數（OSWorld 第 2 章）。所以兩篇的數字不直接互比，都是寫作當時的模型與分數。正式篇名與原文連結列在頁尾。

WebShop：高階的搜尋與點選

WebShop 的動作只有兩種：在搜尋頁輸入一段查詢，或在其他頁點一個文字按鈕。按鈕像網頁連結一樣點下去就換頁，作者特別寫明這不是 World of Bits 那種低階的滑鼠點擊（WebShop 第 2 章）。觀察有兩種模式：HTML 模式就是網頁本身，給人在瀏覽器裡操作；simple 模式拿掉多餘的中繼資料，只留文字與按鈕，模型全部在這個模式訓練與評估。所以 WebShop 的人類分數與模型分數，是在兩種不同的介面上量的。

作者的理由有兩個。一是環境雖然允許強化學習的 agent 直接看 HTML 模式的像素，作者認為那是很低階、沒有語意的動作空間；二是替任何新網頁寫一個轉成 simple 格式的翻譯器很直接，所以能搬到真實網站（第 2 章）。相關工作一節也說，MiniWoB 用低階的滑鼠點擊與按鍵當動作，難度與規模都不容易放大；WebShop 用高階的搜尋與點選，作者說比較能放大、也比較能搬到真實情境（第 12 章）。

搬遷的實驗在第 11 章：從測試集抽 100 條指令，三個模型不再微調，直接到 amazon.com 與 ebay.com 購物，事後照同一條式子人工評分。IL＋RL 在 Amazon 是 65.9 分、成功率 25%，在 eBay 是 62.3 分、21%；規則基線是 45.8 分、19% 與 31.7 分、7%。作者說這樣的搬遷只需要兩個小的程式補充（WebShop 第 11 章）。

OSWorld：原始的滑鼠與鍵盤

OSWorld 的動作要是一段合乎 pyautogui 語法的 Python：移動、點擊、右鍵、拖曳、打字、組合鍵都可以，也能放進迴圈；另外有 WAIT、FAIL、DONE 三個特殊動作（OSWorld 第 5 章）。作者對照 MiniWoB++、CC-Net、WebArena 這些替網頁設計的動作空間：它們沒有涵蓋電腦上所有的動作，碰到按右鍵、按住 Ctrl 點選多個項目就做不到，作者說這替 agent 能學到的東西設了上限。引言把 WebShop 列在同一類：既有的可執行環境簡化了人機互動的觀察與動作，任務也限在少數網頁領域（第 1 章）。

觀察是完整的桌面截圖（預設 1920×1080），另外提供 XML 格式的無障礙樹。表 5 用四種輸入比了一批模型（純文字模型只跑無障礙樹）：同一個 GPT-4V，只看截圖是 5.26%，加上無障礙樹是 12.17%，改用 SoM（在截圖上依無障礙樹畫編號框，讓模型用編號指元件）是 11.77%（OSWorld 第 9 章）。SoM 的效果因模型而異。附錄的一個例子裡，用 SoM 的 agent 在設定頁找核取方塊、最後點錯；沒用 SoM 的 agent 直接改 settings.json 就成功了，作者說 SoM 縮小了 agent 的動作空間，妨礙了探索與調整（第 12 章）。

作者也說，只看截圖的設定分數最低，但長期來看應該是終極的設定：它不需要額外的資訊；無障礙樹不見得每個軟體都支援好，裡面的 token 量也大（第 9 章）。

整理者的讀法

兩篇抽象掉的是不同的東西

  • WebShop：把「點哪裡」交給環境。畫面上能點的東西先變成一串文字按鈕，agent 只要挑一個；它考的是挑哪一個。
  • OSWorld：把「點哪裡」留給 agent。目標要自己對到像素座標；它考的除了挑哪一個，還有點不點得到。
  • SoM：OSWorld 裡最接近 WebShop 的設定，編號框像一串可以點的清單；但它沒有拿掉滑鼠與鍵盤的其他動作，沒有編號可用時也能直接寫座標。
  • 條件：兩篇的任務、模型與年份都不同，上面的數字回答不了哪一種介面的分數高。
跨單元的對照

其他單元也在替 agent 決定介面

單元 13 的 SWE-agent 主張 LM agent 是一種新的使用者，替它設計了一層 agent-computer interface：少量的搜尋、檢視、編輯指令，加上擋下語法錯誤的護欄。在 SWE-bench Lite 上，GPT-4 Turbo 用這套介面解出 18.00%，只給 Linux shell 是 11.00%（有示範）與 7.33%（沒有示範）；同一章也說，當時的 LM 缺少直接操作圖形介面所需的視覺理解（SWE-agent 第 1 章）。SWE-agent 的引言引了 OSWorld，當成「agent 通常直接用現成的應用程式」的例子之一。單元 14 的 LongNAP 把使用者的動作寫成一句話、不寫座標，作者說這個粒度能交給電腦操作的 agent 去做，引的例子之一也是 OSWorld（LongNAP 第 1 章）。單元 11 的〈Demystifying Evals for AI Agents〉比了瀏覽器 agent 的兩種觀察：讀 DOM 快但 token 用得多，看截圖慢但省 token（第 6 章）。這幾篇談的是寫程式、使用者模型與評估，不是同一個問題，這裡只並排。

還沒有答案的地方，兩篇自己也點出來了。WebShop 的作者說，將來要在功能更多的真實網站上部署，先把模型可以做哪些事寫清楚，是避免有害行為的關鍵（WebShop 第 11 章）。OSWorld 把提升 VLM 的 GUI 定位列為第一個方向，也說無障礙樹在不同 app 的品質不一，需要更聰明的方法過濾多餘的節點、補上缺漏的節點（OSWorld 第 13 章）。兩篇都沒有在同一組任務上，並排高階動作與原始的滑鼠鍵盤。

WebShop：一條式子，拿人工重評來檢查

按下購買時，程式拿指令要求的屬性、選項與價格上限，和買到的商品逐項比對，算出對上的比例，再乘上一個看商品類型對不對的分數；任務分數是平均獎勵乘以 100，成功率是獎勵剛好等於 1 的回合比例（WebShop 第 4 章）。每條指令都是工人看著一件目標商品寫的，每條付 0.15 美元，所以每一題都保證有解（第 3 章）。

這條式子和人的判斷差多少？作者從一般工人與專家的軌跡各抽 100 條，請人照同一個公式重評，但同義詞也算對。一般工人的軌跡，自動 74.9、人工 76.3，Pearson 相關 0.856；專家的軌跡是 81.5 對 89.9，相關 0.773。每一項的人工分數都不低於自動分數，作者說自動獎勵是實際表現一個相當接近的下界，誤差主要來自同義詞（第 5 章）。

部分分也讓分數與成功率分開：規則基線直接拿指令去搜、買第一件、不選選項，分數 45.6，成功率 9.6%（第 8 章）。作者自己列的限制是，指令只會用到屬性與選項，屬性有時太泛、選項有時太細（第 13 章）。

OSWorld：一題一支腳本，靠人審查

作者說一般的電腦任務沒辦法化約成統一的模式，所以每一題都寫專屬的評估：先做收尾（例如存檔、切到某個視窗），再用 getter 從虛擬機、雲端或無障礙樹取出關鍵資料，最後用評估函式判定（OSWorld 第 4 章）。有些題目的標準答案會隨時間改變，例如某人論文的引用數，getter 裡就放爬蟲，在評估當下取最新的值。每一題由不同的人前後審查三次；研究生替一題寫評估並檢查，平均約 2 人時。整個基準由 9 位學生作者花了三個多月、約 1,800 人時做成（第 6 章）。

作者承認，品質檢查之後仍可能誤判成功或誤判失敗，更多紅隊測試留給之後（第 4 章）。他們也說，目前的評估函式只檢查任務有沒有完成，看不到 agent 有沒有順手做了不必要的破壞（第 13 章）。

跨單元的對照

單元 11 的兩篇怎麼看 OSWorld 的評分

〈Demystifying Evals for AI Agents〉把 OSWorld 當成評估電腦操作 agent 的例子：任務結束後由腳本檢查檔案系統的狀態、應用程式的設定、資料庫的內容與 UI 元件的屬性（Demystifying 第 6 章）。ABC 檢查清單則拿 OSWorld 當分析對象：chrome 區的 46 題裡有 13 題因為網站改版而壞掉，很多評分依賴 HTML 元素的選擇器；這個問題讓 OSWorld 上最強的開源 agent 被低估了 28%，論文註明是絕對值（ABC 第 8 章）。ABC 的附錄替 OSWorld 逐條打分，沒拿分的包括 T.6（評分用到線上網頁）與 O.g.2（只查和任務相關的狀態，查不到多做的有害動作）（ABC 第 6 章）。ABC 沒有檢查 WebShop。

整理者的讀法

兩種評分，放大的方式不同

  • 題目怎麼放大：WebShop 靠同一條式子，新增一題只要一條指令；OSWorld 的比較表把 WebShop 記成 1 個範本產生約 1.2 萬題、1 個評估函式。OSWorld 新增一題要寫布置與評估，全部 369 題用到 134 個評估函式。
  • 誰檢查評分：WebShop 拿人工重評量出自動獎勵偏低；OSWorld 靠人審查每一題的腳本，論文沒有報告腳本和人工判斷一致的程度。
  • 環境會不會變：WebShop 的搜尋引擎是離線建好、結果固定的，作者說這讓模仿學習與重現結果都容易做（WebShop 第 2 章）；OSWorld 有些題目用線上網站，ABC 量到的低估就出在這裡。

還沒有答案的地方：WebShop 的作者希望之後的版本能在一件商品與指令的脈絡裡辨認同義詞（WebShop 第 5 章）；OSWorld 說完整的電腦環境太複雜，還沒找到有效率的方法偵測潛在的副作用（OSWorld 第 13 章）。一個完全不解題的 agent 會拿幾分，兩篇都沒有報告。WebShop 的規則基線不需要學習，但會搜尋與購買；OSWorld 有 30 題本來就做不到的題，回報 FAIL 才算對，作者提到有的設定很容易直接輸出 FAIL，讓這些題出現「假的成功」（OSWorld 第 10 章）。ABC 替 OSWorld 打分時，R.13（附上 trivial agent 的結果）是 0。

人類的失敗也有一個常見的模式：搜一次就買第一件，那件商品往往沒有指令要的選項；作者說這個任務需要耐心與一致性（WebShop 第 6 章）。

OSWorld：點不到規劃好的位置

人類在 OSWorld 的成功率是 72.36%，最高分的模型是只看無障礙樹的 GPT-4，12.24%（OSWorld 第 9 章）。作者從不同設定抽樣 550 個失敗例，超過 75% 有點錯座標的問題：程式註解裡的步驟規劃得又細又對，座標卻點不準，作者的形容是規劃強、執行弱。點錯又引出重複點擊與環境雜訊兩種錯誤。另一類失敗是操作知識：GIMP 的題目要調低亮度，agent 不知道哪個選單能調，只好亂試到步數用完（第 12 章）。

輸入設定的比較也落在同一段：同一個 GPT-4V，加上寫著元件位置的無障礙樹，成功率從 5.26% 升到 12.17%（第 9 章）。人類在五類題目之間都在 70% 上下；agent 在偏命令列的 OS 題高於偏圖形介面的 Office 題，工作流題多半不到 5%（第 10 章）。作者也看到，人覺得簡單的文字與設計題 agent 常做不到，能用幾行指令解決的題 agent 有時反而做得比人順（第 12 章）。

判斷題 · 01

要考 agent 在網頁上做事，該給它按鈕清單，還是滑鼠鍵盤？

給清單的一方：WebShop 的高階動作加一層翻譯，不再訓練就搬上 Amazon 與 eBay；單元 13 的 SWE-agent 替 agent 設計的介面，在 Lite 上是 18.00%，只給 shell 是 11.00%。給滑鼠鍵盤的一方：OSWorld 說只為網頁設計的動作替學習設了上限，只看截圖是長期的終極設定，SoM 的編號框在它的例子裡縮小了動作空間（都在第 2 章）。

還缺的證據：同一組任務、同一個模型，並排高階動作與原始滑鼠鍵盤的結果。兩篇的任務、模型與年份都不同。

挑一個你常用的網頁流程，做兩個版本：一個把頁面上能點的元素列成帶編號的清單，一個只給截圖與座標；各跑二三十次，記成功率、步數，以及失敗是選錯還是點錯。

判斷題 · 02

替 agent 評分，一條通用的式子夠不夠，還是每題要一支腳本？

一條式子：WebShop 的獎勵讓 1.2 萬條指令共用，人工重評顯示它偏嚴，大約是人工分數的下界。一題一支腳本：OSWorld 的 134 個評估函式檢查最後的狀態，每題審查三次；單元 11 的 ABC 發現，依賴線上網頁的題目會隨網站改版失準（都在第 3 章）。

還缺的證據：OSWorld 的腳本和人工判斷有多一致，論文沒有報告；WebShop 的式子只比對屬性、選項、價格與類型，作者自己把這列為限制。一個完全不解題的 agent 會拿幾分，兩篇都沒有報告。

拿你的 agent 的二十個輸出，各用三種方式評一次：一條通用的比對式子、針對每題寫的檢查、你自己看；把三者不一致的題挑出來，看是哪一種評分漏掉了什麼。也跑一次什麼都不做的 agent，看它拿幾分。

判斷題 · 03

agent 和人的差距，卡在決定要做什麼，還是卡在做出來？

卡在決定的證據：WebShop 的選項分差最多，Choice oracle 讓成功率到八成以上；單元 6 的 ReAct 在 WebShop 加上推理，成功率從 30.1% 到 40.0%。卡在做出來的證據：OSWorld 的失敗例超過 75% 點錯座標，規劃卻寫得對；補上元件的位置，GPT-4V 從 5.26% 到 12.17%（都在第 4 章）。

還缺的證據：同一個模型在同一個環境裡，分別補上「決定」與「執行」各自的 oracle，看哪一個讓分數升得多。兩篇各只做了一邊。

在你的 agent 上做兩個對照：一次替它把要操作的元素直接標出來（補執行），一次把該做哪一步的提示寫進 prompt（補決定）；比兩次各把成功率拉高多少。
