警告是給模型的機會
記憶壓力警告讓模型在逐出之前自己決定：哪些事實寫進工作脈絡、哪些長內容存進 archival storage。等到清空門檻，就由佇列管理器直接逐出。

逐出不等於忘記
佇列管理器把每一則進來的訊息，和模型的每一次輸出，都寫進 recall storage；被逐出之後，模型照樣可以用函式把它們找回來。
找回來的訊息，會被接回佇列的尾端，重新進到視窗。
摘要一層層疊上去
每次清空，都用「舊的遞迴摘要＋這次被逐出的訊息」寫出新摘要，放在佇列第一格；視窗裡因此一直留著一份整段歷史的濃縮版。

三個讓模型自己管記憶行得通的設計
① 何時搬，模型自己判斷
記憶的編輯與檢索完全由模型主導：對話太長時把事實存起來（圖 1），理解改變時改寫工作脈絡，例如把「男友」改成「前男友」（圖 4）。
沒有外部規則替它決定該存什麼、該找什麼；
佇列滿了的逐出，才由佇列管理器自動處理。
② 錯誤也是回饋
執行時的錯誤，例如主脈絡已滿還要往裡面加，會和結果一起送回模型；作者說這個回饋迴圈讓系統能從自己的行動學習、調整行為。
錯誤訊息進的是主脈絡，下一輪就看得到；
參數沒通過驗證的呼叫，不會被執行。
③ 知道自己的上限
模型要意識到脈絡有上限，自我編輯才有效：系統用 token 上限的警告提示它，檢索函式也做了分頁，一次呼叫不會撐爆視窗。

① 定時事件：不用等人開口
事件不只有使用者訊息，還有系統訊息（例如容量警告）、使用者動作（剛登入、剛上傳完文件）與定時事件；定時事件讓 MemGPT 在沒人提示時也會自己跑。

② 連鎖呼叫：多步才做得完
翻同一個查詢的多頁結果、從不同文件彙整資料，都要連續呼叫好幾個函式；帶 heartbeat 的呼叫做完，控制權立刻回到處理器，由它決定下一步。

③ yield：把控制權交回去
沒帶旗標的函式呼叫就是 yield：MemGPT 不再跑 LLM 處理器，直到下一個外部事件，例如使用者的新訊息，或排定的中斷。
yield 是作業系統的用詞：主動讓出執行權；

11 / 11結論：分層、函式、事件
分層、函式、事件：固定視窗也撐得起長期記憶
第 1、5 節：作者的結論是，記憶階層加上作業系統式的函式與事件，讓有限視窗的 LLM 在文件分析與多段對話都勝過既有做法；另外點名三個後續方向
01　分層
把視窗當成有限的
主記憶體
先決定什麼住在視窗裡、什麼放在外面：系統指令與工作脈絡常駐，對話紀錄與文件放在搜得到的外部儲存，要用時再搬進來。
✗ 把所有歷史都塞進 prompt
✓ 分層，外面的要搬進來才算數
02　函式與事件
搬記憶的，
是模型自己
給它函式 schema、記憶壓力警告、分頁的檢索與錯誤回饋，讓它自己決定存什麼、找什麼；多步的事靠 heartbeat 連鎖，做完就 yield。
✗ 固定流程檢索一次就交差
✓ 讓模型自己查、自己翻頁
03　上限
效果取決於模型
會不會呼叫函式
配 GPT-3.5 在文件問答明顯變差，MemGPT 常常沒翻完就停，配 GPT-4 Turbo 在巢狀鍵值不如配 GPT-4：記憶管理做得多好，看底層模型。
論文沒有報延遲與 token 成本；
評分靠 LLM 評審，文件問答只抽 50 題。
作者點名的三個後續方向（不排順序）
A
用到其他有大量或無界脈絡的領域
B
整合不同的記憶層技術，例如資料庫或快取
C
繼續改進控制流程與記憶管理的策略
出處：三個方向都在第 5 節結論。代價散在第 3 節：底層模型的函式呼叫能力、太早停止翻頁、嵌入式檢索的上限、評估的範圍；正文第 13 章把它們列在一起。
