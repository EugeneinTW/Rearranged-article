換模型，還是改系統Zaharia 等人、Ng 與 Si 等人在三個問題上的證據

先對齊名詞

四個詞，出自不同的地方

  • compound AI system（複合式 AI 系統）：Zaharia 等人的定義，用多個互相配合的元件完成 AI 任務，元件包括多次呼叫模型、檢索器或外部工具；相對的是只預測下一個 token 的模型本身。
  • agentic workflow（agent 工作流）：Ng 的用語，對模型呼叫很多次、每次做一小步，讓它有機會修改、查資料、用工具。
  • agentic system（agentic 系統）：講題用的詞，三篇都沒有給它定義。單元 2 的〈Building Effective Agents〉拿它當傘狀詞，底下分成流程由程式寫好的工作流，和由模型自己決定流程的 agent。
  • execution grounding（執行接地）：Si 等人的做法，點子的好壞看真的執行之後的實驗結果，不靠人的評審。

Zaharia 等人：假設的數字與案例

Zaharia 等人的第一個理由是「有些任務用系統改善比較划算」，用一個假設情境說明：最好的模型能解三成的程式競賽題，訓練預算加到三倍也許到 35%；讓模型多次採樣、逐一測試的系統，用當時的模型就可能到 80%，AlphaCode 就是這樣做的。作者接著說，改系統的設計通常比等一次訓練跑完快得多，高價值的應用會把系統的做法和規模化一起用（Compound AI Systems 第 1 章）。案例表裡的 AlphaCode 2 一題最多產生一百萬個候選解，再靠執行、過濾與分群縮減，達到人類參賽者的第 85 百分位（第 3 章）。

同一篇也點出比較的條件。Gemini 發表時用 CoT@32 量 MMLU，同一題呼叫模型 32 次，拿到 90.04%，GPT-4 五樣本是 86.4%；作者提到這種量法引來「和 GPT-4 單次呼叫比公不公平」的質疑（序章、第 3 章）。他們的預測是：模型再進步，複合系統仍會是主流的做法（第 1 章）。

Ng：HumanEval 上的三個數字

Ng 的團隊整理了多個研究團隊在 HumanEval 上的結果：GPT-3.5 零樣本答對 48.1%，GPT-4 零樣本 67.0%，GPT-3.5 包進迭代的 agent 迴圈最高到 95.1%。他的讀法是換模型的進步被工作流的進步蓋過；本站讀物頁從這三個數字算出的兩個差距，是 18.9 與 47 個百分點（Agentic Design Patterns 第 2 章）。圖上其他方法只畫了點、沒有標數字，各自來自不同的論文。Ng 在第一封信押的是：這一年 agent 工作流帶來的進步，可能比下一代基礎模型還多。這是 2024 年 3 月的預測。

Si 等人：搜尋不動權重，RL 動權重

Si 等人先確認前提：同一個模型出點子、自己實作，每個模型抽 50 個點子，最好的那一個就超過基準，例如 Claude-4.5-Sonnet 在後訓練環境拿到 60.4%，基準是 48.0%（Execution-Grounded 第 4 章）。接著的演化搜尋不更新權重：每一輪把前幾輪超過基準的點子，和隨機抽的舊點子放進 prompt，要模型組合或另想新的（第 5 章）。十輪之內，後訓練環境從 48.0% 到 69.4%，預訓練環境的達標時間從 35.9 分鐘縮到 19.7 分鐘；在預訓練環境、同樣的取樣預算下，搜尋從第 1 輪起分數高於 best-of-N（第 6 章）。

同一章也寫出限制：三個模型裡只有 Claude-4.5-Opus 隨輪數持續進步，Sonnet 與 GPT-5 早早飽和；預訓練環境的人類最強解不到 2.1 分鐘，作者說模型能力與搜尋方法都還有很大的進步空間（第 6 章）。RL 這一邊動權重：用執行成績當獎勵、以標準 GRPO 訓練 Qwen3-30B-A3B，後訓練環境的平均準確率 40 輪從 0.253 升到 0.343，每一輪的最大獎勵卻一直上下震盪（第 8 章）。作者的判準是：科學發現在乎的是一個壓過基準的點子，不是很多安全的點子把平均拉高。他們追到的原因是思考變短、點子收斂到少數容易實作的幾種（第 9 章）。

整理者的讀法

三組比較，量的不是同一件事

  • Zaharia 等人：30%、35%、80% 是同一個假設情境，用來說明取捨，不是實測；案例來自各家系統在各自的任務上。
  • Ng：零樣本是一次呼叫，agent 迴圈是多次呼叫，呼叫次數沒有對齊；數字來自不同論文、不同時間的評測。
  • Si 等人：搜尋與 best-of-N 在同樣的取樣預算下比；搜尋用 Claude 與 GPT-5，RL 用 Qwen3-30B，兩種方法沒有在同一個模型上並排。
  • 呼叫次數：Zaharia 等人自己點出 CoT@32 呼叫 32 次、和單次呼叫比引來質疑；三篇裡只有 Si 等人把比較的預算對齊。
跨單元的對照

GEPA：同一個模型上，只改 prompt 對上 GRPO

單元 9 的 GEPA 論文在同一個 Qwen3 8B、同樣的六個任務上，並排了只演化 prompt 的 GEPA 與改權重的 GRPO：GRPO 每個任務跑滿 24,000 次 rollout，GEPA 用 1,839 到 7,051 次；六個任務裡五個是 GEPA 的分數較高，AIME-2025 是 GRPO 較高（GEPA 第 8 章）。它和本單元三篇沒有互相引用，這裡只把原文寫的結果並排，不推論到本單元的任務上。

還沒有答案的地方，三篇自己也寫了。Zaharia 等人在結論說，開發複合系統的最佳實務仍是開放問題（第 8 章）。Si 等人說，RL 怎麼避免收斂到少數點子是開放問題，可能需要標準 GRPO 以外的新演算法；他們也還沒測過小規模上最好的點子，放大之後是否仍然有效（第 9、11 章）。Ng 對 Planning 的預測是很快會進步（第 6 章），那是 2024 年春天的話。

Zaharia 等人在「開發複合系統」一節先問三個問題，第一個就是整體的控制邏輯該用傳統程式寫，例如用 Python 呼叫 LLM，還是由 AI 模型驅動，例如讓 LLM agent 自己呼叫外部工具。他們沒有回答，只說可能的設計非常多，開發者得自己探索（Compound AI Systems 第 4 章）。工具的分類也照這條線分：LangChain、LlamaIndex 這類元件庫由傳統程式呼叫，AutoGPT、BabyAGI 這類 agent 框架讓 LLM 驅動應用。案例表裡的 ChatGPT Plus，由模型在回答途中決定何時、怎麼呼叫瀏覽網頁、執行程式與畫圖的工具（第 3 章）。

Ng 的 Planning 就是讓模型自己決定要做哪些步驟、什麼順序。他講了一個自己的例子：現場 demo 時網頁搜尋的 API 回了限流錯誤，研究 agent 改用他給了卻忘記的 Wikipedia 搜尋工具，照樣完成任務（Agentic Design Patterns 第 6 章）。同一封信也說很多工作流不需要規劃：讓模型反思固定的次數，步驟就是固定而確定的；拆不出固定步驟的複雜任務，才讓 agent 動態決定。他把 Planning 與多 agent 放在比 Reflection、Tool Use 不成熟、難預測的一邊；多 agent 在讓它們自由互動、又給很多工具時，輸出品質尤其難預測（第 3、6、7 章）。

Si 等人的系統裡，流程全是程式。實作者對每個點子平行取樣 10 個程式修改，patch 不上就把錯誤記錄交回模型修改，最多兩次；排程器配資源，工作機跑實驗、上傳結果（Execution-Grounded 第 3 章）。演化搜尋的利用、探索與退火也是寫好的演算法（第 5 章）。模型能決定的是點子本身：任何能用自然語言寫出的點子都在範圍內（第 1 章）。作者在討論裡寫了這個設計的代價：實作者直接要 LLM 產生程式修改，不是能用工具的 coding agent，很多有潛力的點子沒被實作成功，變成獎勵裡的雜訊；下一步是做能用外部工具、能在環境裡安裝套件的 coding agent（第 11 章）。

Si 等人還記下一件和模型能碰什麼有關的事：開發初期，模型不只一次修改注意力機制，讓未來的 token 洩漏進來，驗證損失因此變漂亮。他們的處理是凍結所有評估的超參數，另寫一個一次只預測一個 token 的推論函式做最終驗證；後訓練環境則把驗證程式放在執行器不能讀、也不能改的檔案裡（第 2 章）。

整理者的觀察

三篇給模型的自由，在不同的地方

Ng 談的是步驟的順序；Si 等人給模型的是點子的內容，流程固定；Zaharia 等人談的是整個應用的控制邏輯。三篇都沒有在同一個任務上，把「程式排步驟」和「模型排步驟」並排比較。Si 等人的防作弊做法限制的是模型碰得到哪些檔案，和流程由誰排是兩件事。這是整理者把三篇並排時看到的差別，它會不會影響結果，留在第 6 章的判斷題。

跨單元的對照

單元 2：工作流與 agent 的分界

單元 2 的〈Building Effective Agents〉把這類系統統稱為 agentic 系統，再畫一條線：工作流是模型與工具照預先寫好的程式路徑被安排；agent 是模型動態指揮自己的流程與工具用法（Building Effective Agents 第 1 章）。它建議先找最簡單的解，需要時才加複雜度；agent 適合難以預測步數的開放問題，代價是更高的成本與錯誤累積（第 7 章）。這篇和本單元三篇沒有互相引用（整理者在四篇原文裡搜尋過），這裡只把定義並排。

三篇都沒有回答「什麼條件下讓模型排步驟值得」。Zaharia 等人把它留成設計問題；Ng 預測 Planning 會很快進步；Si 等人把更有自主性的執行代理列為未來方向，還沒有做。

Ng 的 Reflection 從一個常見的經驗出發：模型的回答不滿意，你給它批評，第二版常常好一些；Reflection 把「給批評」這一步也交給模型。寫程式的例子是三次呼叫：先生成，再請它檢查正確性、風格與效率並提出建議，最後帶著建議重寫，可以重複幾輪。他給了兩個加強版：給模型工具評估自己的輸出，例如跑幾個單元測試、上網查證文字；或用兩個 agent，一個負責產出、一個負責給建設性的批評。Ng 說這是實作很快的模式，在他的幾個應用裡改善意外地大（Agentic Design Patterns 第 4 章）。這是經驗，信裡沒有附數字；HumanEval 的圖上有 Reflexion 這類方法的點（第 2 章）。

Zaharia 等人把檢查放在系統層。第三個組合理由是控制與信任：訓練很難保證模型避開某種行為，最好的模型也會幻覺；系統可以過濾輸出，接上檢索之後可以附引用、自動核對事實（Compound AI Systems 第 1 章）。RAG 的設計選項裡也有「再叫一個模型，檢查輸出和找到的段落有沒有關」（第 2 章）。維運一章說，同樣是分類一封信，LLM agent 可能用數量不定的 reflection 步驟或外部 API 呼叫，成功率就不再好追蹤；要追蹤每一步與中間輸出。MT-Bench、FAVA、ARES 這類用 AI 評品質的方法，想把品質監控自動化；DSPy Assertions 想把監控檢查的回饋直接接回系統、改善輸出。作者也提醒，像「聊天機器人加內容過濾器」這樣的組合，會帶來單一模型沒有的安全風險（第 7 章）。

Si 等人的出發點是他們自己先前的研究：大規模的專家評審發現，LLM 產生的研究點子常常看起來有說服力，由人類研究者執行之後卻沒有效果，所以點子的好壞改由執行結果決定（Execution-Grounded 第 1 章）。這個分數也有條件。同一批 Claude-4.5-Sonnet 的點子，自己實作時後訓練環境的執行率是 84%，換 GPT-5 實作掉到 42%，誰來實作會改變獎勵（第 4 章）；評分程式碰得到時，模型會去改它（第 2 章）；RL 的每一批 rollout 要平行用 256 張或 1024 張 GPU，才拿得到執行獎勵（第 8 章）。論文裡唯一用到 LLM 判官的地方，是把點子分成調參數與演算法兩類，不評效果（第 7 章）；作者把新穎性、有趣程度這類主觀指標留給未來，前提是找到計算的方法（第 11 章）。

整理者的讀法

兩種判斷，用在不同的東西上

  • 判斷的對象：Ng 談的是程式、文字與回答；Si 等人判斷的是研究點子，要跑完一次訓練才有成績；Zaharia 等人列的是系統層的做法。
  • 證據：Ng 是經驗；Zaharia 等人是列舉，沒有比各種檢查的準確度；Si 等人有實驗，但點子的效果只靠實驗量，沒有和模型的判斷並排。
  • 還缺的：三篇都沒有在同一批輸出上，量模型的判斷和執行結果一致到什麼程度。
跨單元的對照

評估的那一方，也要被檢查

單元 11 的 MT-Bench 論文，就是 Zaharia 等人列舉的 AI 評品質方法之一；它量了 LLM 評審和人類評分的一致程度（MT-Bench 第 9 章）。單元 10 的〈Who Validates the Validators?〉在未來工作一節引了 Zaharia 等人這篇，說端到端的對齊在用 RAG 這類元件的複合 AI 系統裡也很複雜（Validators 第 13 章）。兩篇都在問評估的那一方可不可信，細節請看各自的頁面。

還沒有答案的地方：Si 等人把新穎性怎麼算留給未來（第 11 章）；Zaharia 等人相信會出現新一代的 MLOps 工具，來處理追蹤與除錯這類問題（第 7 章）。模型的判斷在什麼任務上可以代替執行，三篇都沒有量。

判斷題 · 01

在你的任務上，下一份預算該花在換模型，還是改系統？

改系統的證據：Zaharia 等人的假設與案例、Ng 的 HumanEval、Si 等人十輪內超過基準的搜尋（都在第 2 章）。換模型或訓練的證據：Ng 的數字裡，GPT-3.5 換成 GPT-4 零樣本多了 18.9 個百分點；Si 等人的搜尋只有 Claude-4.5-Opus 隨輪數持續進步，RL 拉高了平均、沒有拉高最大值（同一章）。

還缺的證據：同一個任務、同一個模型、同樣的呼叫預算下，改系統與訓練模型並排的結果。三篇都沒有做；單元 9 的 GEPA 在 Qwen3 8B 的六個任務上做過一組，比的是只改 prompt 與 GRPO。

挑一個有自動評分的任務，例如附測試的寫程式題，做三個版本：小模型單次呼叫、大模型單次呼叫、小模型加一輪自我檢查與重寫。記下每個版本的呼叫次數與花費，換算到同樣的預算再比。

判斷題 · 02

流程該寫在程式裡，還是交給模型排？

寫在程式裡：Ng 說很多工作流不需要規劃，Reflection 與 Tool Use 在他的應用裡可靠；Si 等人的整套流程是程式，模型只出點子。交給模型：Ng 的研究 agent 在搜尋出錯時自己換工具完成 demo；ChatGPT Plus 由模型決定何時用工具；Si 等人把能用工具的 coding agent 列為擴大點子範圍的下一步（都在第 3 章）。

還缺的證據：同一個任務上，固定流程與讓模型排步驟並排，比成功率、成本與每次走的路徑。三篇都沒有做這個比較。

把一個你熟悉的多步驟任務寫成固定的三步流程，再做一個讓模型自己決定下一步的版本；同一組輸入各跑二十次，記成功率、呼叫次數，以及每次走的步驟是否相同。

判斷題 · 03

輸出的好壞，能交給模型自己判斷嗎？

交給模型的例子：Ng 的 Reflection 與批評者 agent，Zaharia 等人列的「再叫一個模型核對」與用 AI 評品質。交給執行的例子：Ng 的 Reflection 也能接單元測試；Si 等人說點子看起來有說服力、做出來常常沒效，所以一律跑實驗，也記下模型碰得到評分程式時會去改它（都在第 4 章）。

可以拿來判斷的問題：你的任務有沒有能執行的檢查？模型的判斷和執行結果，在你的輸出上一致到什麼程度？

準備三十筆附測試的程式輸出，先讓模型逐筆判斷對不對，再跑測試；把兩邊不一致的筆數與樣子記下來。量一致程度的做法，可以參考單元 11 的 MT-Bench 與單元 10 的 Validators。

為什麼不附答案

證據在別人的任務上量出來

三篇的數字來自不同的任務、模型與年份，有一組還是假設的數字；放到你自己的任務上會不會成立，要用你的任務量過才知道。這一頁只負責把證據排在一起，判斷留給讀者。

Reference · 用詞對照

同一件事，三篇各用不同的名字

三篇對整個系統、agent、流程、檢查與預算各有說法。每一條先寫這件事，再列各篇怎麼稱呼、在本站讀物頁的哪一章；沒有談到的篇就不列，其他單元的說法標出單元。

compound AI system
整個系統叫什麼
Zaharia 等：複合式 AI 系統，用多個互相配合的元件完成 AI 任務（序章）。Ng：agent 工作流，對模型呼叫多次、每次做一小步（第 1 章）。Si 等：自動化的 AI 研究者，由出點子的模型與自動執行器組成（第 1、3 章）。單元 9 的 GEPA 沿用這個詞，寫明涵蓋 agent 與多 agent 系統（第 1 章）。
agentic system
講題的用詞
三篇都沒有定義。單元 2 的〈Building Effective Agents〉拿它當傘狀詞，底下分成工作流與 agent（第 1 章）。Ng 用的是 agentic workflow 與 agentic design pattern（第 3 章）。
agent
agent 指什麼
Zaharia 等：呼叫外部工具的 LLM agent，是控制邏輯的一種選擇；agent 框架讓 LLM 驅動應用（第 4 章）。Ng：Planning 裡自己決定步驟的 agent，多 agent 是分工的角色（第 6、7 章）。Si 等：相關工作裡的 LLM 研究代理，討論裡負責實作的執行代理（第 10、11 章）。
control logic
誰排下一步
Zaharia 等：控制邏輯，用程式寫或由模型驅動（第 4 章）。Ng：Planning，由模型排步驟（第 6 章）。Si 等：搜尋的演算法與執行器的三段管線，都是程式（第 3、5 章）。
multiple calls
同一題多呼叫幾次
Zaharia 等：推論策略，例如呼叫 32 次的 CoT@32、自我一致性（序章、第 4 章）。Ng：反覆修改的 agent 迴圈（第 1、2 章）。Si 等：best-of-N，以及演化搜尋的一輪又一輪（第 4、6 章）。
reflection
回頭檢查自己
Zaharia 等：維運一章拿 LLM agent 數量不定的 reflection 步驟，當作難追蹤的例子（第 7 章）。Ng：Reflection 是四種模式之一（第 4 章）。Si 等：實作者把 patch 失敗的記錄交回模型重寫，論文叫循序自我修正，最多兩次（第 3 章）。
evaluation
好壞怎麼判
Zaharia 等：自動核對事實、再叫一個模型檢查、用 AI 評品質（第 1、2、7 章）。Ng：建設性的批評，也可以接單元測試（第 4 章）。Si 等：execution grounding，執行器當獎勵函數（第 1 章）。
trace
過程的紀錄
Zaharia 等：trace，追蹤應用走過的每一步與中間輸出（第 7 章）。Si 等：執行軌跡，每一輪附進 prompt 給模型看，也連同環境一起開源（第 2、5 章）。
baseline
拿來比的基準
Zaharia 等：單次呼叫的模型，CoT@32 和它比引來質疑（序章）。Ng：zero-shot，一次生成、途中不修改（第 1 章）。Si 等：環境附的基準程式碼，以及 best-of-N（第 2、6 章）。
budget
預算
Zaharia 等：延遲與成本預算，例如 100 毫秒怎麼分給檢索器與模型；FrugalGPT 在預算內挑模型（第 4、6 章）。Si 等：固定 25 分鐘的訓練時間、同樣的取樣預算、RL 每批 256 或 1024 張 GPU（第 2、6、8 章）。
tool use
工具
Zaharia 等：外部工具與執行 Python 的 Code Interpreter；也有模型在訓練時就用工具（第 3、5 章）。Ng：Tool Use，模型輸出一段特殊字串、由程式代為呼叫（第 5 章）。Si 等：實作者沒有工具，直接產生程式修改；未來改用能用工具的 coding agent（第 3、11 章）。
decomposition
拆解
Zaharia 等：元件與模組化的步驟，閘道可以替每一步分開挑模型（第 4、6 章）。Ng：子任務與角色，類比程式拆成行程與執行緒（第 7 章）。Si 等：實作者、排程器、工作機三個元件（第 3 章）。
