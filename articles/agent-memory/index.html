Agent Memory · 圖卡＋教材整合版

Agent Memory記憶就是決定 此刻哪些 token 在 context 裡

傳統的模型呼叫是無狀態的，每次互動都從零開始。Letta 這篇概念文章的主張是：agent 記得什麼，取決於這一刻 context window 裡有什麼，所以設計記憶就是設計 context。本頁分十一章重述：先看四種記憶，再看三種管理技巧（驅逐與摘要、記憶區塊、外部儲存），接著是 MemGPT 的記憶階層與睡眠時間 agent。每章開頭先放一張圖解卡講重點，往下是詳細說明；想速讀就切到「只看圖卡」。

Prologue · 整理者的引言

每次都從零開始的模型，做不出會學習的 agent

原文的起點是一個對比：傳統的模型呼叫是無狀態的，每次互動彼此孤立；有狀態的 agent 會把過去帶到下一次，才可能隨時間學習與調整。

這篇是 Stanford CS 329Z 第 4 週的選讀。那一講叫 Agent Memory Architectures，屬於 Memory & Multi-Agent Systems 分區，談短期與長期記憶、把記憶當成工具動作、用檔案系統當外部記憶、結構化的記憶，以及跨 agent 的記憶。同一講的必讀是 MemGPT 論文。整理者補充一句背景：Letta 是 MemGPT 的作者們成立的公司。讀這篇時可以把它當成必讀論文的延伸，文中有一節直接介紹 MemGPT，也有一節說明他們後來怎麼改進它的設計。

原文的導言只有一段。傳統的模型在無狀態的模式下運作：每一次互動都是孤立的，上一段對話的知識不會帶到下一段。作者承認這對基本任務和短命的 agent 行得通，但認為它從根本上限制了 AI 系統能做到的事。從無狀態的模型走向有狀態的 agent，是朝「真的能隨時間學習與調整」的系統演進。

本頁照原文的順序走：先定義什麼是 agent 記憶，再看它的四種元件、三種管理技巧，接著是兩個工程系統（MemGPT 與睡眠時間 agent），最後回到一個觀點：記憶不必照抄人腦，它就是 context 工程。

給初學者

先把六個名詞對齊

  • Token：模型讀寫文字的最小單位；context 的長度用 token 數來算。
  • Context window：模型一次看得到的 token 上限。原文把它比作 agent 的工作記憶。
  • 無狀態（stateless）：每次呼叫都不帶上一次的東西，模型只看得到這一次送進去的內容。
  • 有狀態的 agent（stateful agent）：把過去的互動與累積的經驗，帶進之後的每一輪。
  • 記憶區塊（memory block）：固定放在 context window 裡、可以被改寫的一段文字，有自己的標籤與字元上限。
  • MemGPT：把 context window 當成記憶體來管理的系統，本週必讀論文的主角。

原文對 agent 記憶的定義很短：agent 隨著時間記住了什麼資訊、又是怎麼記住的。基本的記憶可能只是記得先前的互動；進階的記憶系統則讓 agent 隨時間學習與進步，依累積的經驗調整自己的行為。

接著作者把「記得」落到一個具體的地方。agent 此刻「記得」什麼，根本上取決於這一刻 context window 裡有什麼。可以把 context window 想成 agent 的工作記憶：回答問題、推理、採取行動時，手上立刻用得到的資訊就是它。視窗外的東西存得再完整，這一輪的模型也看不到。

所以設計 agent 的記憶，本質上就是 context engineering（context 工程）：決定哪些 token 進入 context window，以及它們在裡面怎麼組織。記憶系統會組合幾種技巧，例如摘要、context 改寫、檢索，去管理幾種記憶元件，例如訊息、記憶區塊、外部資料庫。

原文把 agent 的記憶系統拆成幾個各有用途的元件，一共四種。前兩種住在 context window 裡，模型每一輪都直接看得到；後兩種存在視窗外，需要時才被找回來。

訊息緩衝區（message buffer）存放對話裡最近的訊息，提供即時的對話脈絡，讓對話接得下去。作者說，在 Letta 裡每個 agent 只維護一條持續不斷的訊息串，所有訊息都接在同一條序列上。

核心記憶（core memory）由放在 context 裡的記憶區塊組成，可以由 agent 自己管理，也可以由其他 agent 管理。每個區塊聚焦一個主題，例如關於使用者、組織或目前任務的記憶：一個區塊放使用者的偏好，另一個放 agent 的角色設定（persona）或目前的目標。作者點出它的關鍵特色：這些區塊可以透過 API 編輯，而且固定釘在 agent 的 context window 裡，是一種「受管理的 context 單位」。

回想記憶（recall memory）保存完整的互動歷史。訊息就算已經不在目前的視窗（也就是訊息緩衝區）裡，需要時仍然可以搜尋、取回。作者說，Letta 會自動把回想記憶存到磁碟，其他框架則要開發者自己處理保存。

歸檔記憶（archival memory）存放明確寫下來的知識，放在外部資料庫裡。它和回想記憶的差別在內容：回想記憶存的是原始的對話紀錄，歸檔記憶存的是處理過、建了索引的資訊。它可以用不同的儲存格式，例如向量資料庫或圖資料庫，再用專門的工具查詢，把資料取回 context window。

實作提示

先問「這段資訊該不該每一輪都被看到」

四種記憶的分界，實際上就是這個問題的答案。每一輪都需要的放核心記憶；只有最近幾輪需要的留在訊息緩衝區；偶爾才要回頭查的原始對話交給回想記憶；整理過、要長期查詢的知識放歸檔記憶。這個判斷順序是整理者依原文的定義排的。

整理者的思考題 · 01

你的 agent 現在「記得」的東西，各屬於哪一種？

把 agent 某一輪 context 裡的內容逐段標出來：哪些是最近的訊息、哪些是固定的區塊；再列出它能用工具查到、但不在視窗裡的資料。

整理者的建議：如果某個每一輪都要用的事實只存在外部資料庫，它就只能每次靠檢索回來，可以考慮改放進核心記憶，讓它一直在視窗裡。

agent 記憶最基本的難題，是 context window 的容量有限。摘要技術能壓縮資訊，同時保住必要的細節。原文把這件事分成兩部分：怎麼驅逐，以及怎麼摘要。

驅逐（eviction）發生在 context window 到達容量的時候，由驅逐策略決定要移除哪些資訊。移除之前，可以先把重要的細節摘要、存起來。原文的建議是一般只驅逐一部分訊息，舉的例子是 70%，目的是確保對話的連續性，讓最近的訊息仍然原封不動地留在視窗裡。

示意 · 一次驅逐（教學用假想程式碼，非原文，也不是 Letta 的實作） 
if tokens(window) >= LIMIT:                 # 視窗到達容量
    old, recent = split(buffer, 0.7)        # 只驅逐較舊的一部分，例如 70%
    summary = summarize(summary + old)      # 遞迴：連同舊摘要一起再摘要
    buffer = recent                         # 最近的訊息原封不動留下

被驅逐的訊息會經過遞迴摘要（recursive summarization）：它們和先前摘要過的內容一起再被摘要一次。對話越長，較舊的訊息對摘要的影響就越小，最近的訊息影響最大。

補充說明

被趕出視窗，不等於被忘記

照第 2 章的定義，回想記憶保存的是完整的互動歷史，訊息不在訊息緩衝區裡也能被搜尋出來。所以驅逐只是把原句從視窗裡移走：視窗裡留下的是摘要，完整的紀錄仍在視窗外。這段是整理者把兩節原文接起來的讀法。

你的 agent 的 system prompt，有告訴它自己的記憶長什麼樣嗎？

原文把「讓 agent 了解自己記憶限制的 prompt」列為三件要設計的事之一。打開你的 prompt，找找看有沒有寫出：哪些記憶在視窗裡、哪些要用工具查、各有什麼上限。

如果都沒寫，agent 只能自己猜什麼時候該去查外部記憶；先補一段說明，再觀察它查詢的時機有沒有變得合理。

Chapter 09 · Conclusion

記憶系統靠的是幾種技巧的組合

驅逐與摘要、記憶區塊、外部儲存與檢索，三者要一起用。原文最後推薦自家的 Letta API 與 Letta Code。

作者把 agent 記憶稱為 AI 發展最關鍵的前沿之一。他們的判斷是，agent 記憶的未來不在任何單一技巧，而在把多種做法用心地組合起來：謹慎的驅逐與摘要、聰明地管理記憶區塊，以及儲存與取回外部 context 的成熟系統。

原文的最後一段是產品推薦：想做出能形成記憶、隨時間學習、變得更聰明也更個人化的 agent，可以看 Letta API 與 Letta Code。本頁照原文保留這兩個產品名，沒有另外評估它們。

看得到的放在視窗裡，查得到的放在視窗外，每一輪決定哪些 token 要被拉回來。 整理自全文

下面這份清單不在原文裡，是整理者把全文的建議壓成的順序，讓你今天就能替自己的 agent 檢查一輪。

  1. 把 agent 某一輪的完整 context 印出來分類標出哪些是最近的訊息、哪些是固定的區塊、哪些是檢索回來的內容；這就是它此刻「記得」的全部。
  2. 替訊息緩衝區訂驅逐規則快滿時只驅逐較舊的一部分（原文舉 70%），移走前先摘要，新摘要要連同舊摘要一起做。
  3. 把每一輪都要用的事實放進記憶區塊每塊寫好標籤、說明與字元上限，讓 agent 能用工具改寫它。
  4. 分開存原始對話與整理過的知識完整對話存成可搜尋的回想記憶；處理過、建了索引的知識放歸檔記憶，並給 agent 查詢的工具。
  5. 在 prompt 裡寫出記憶的樣子與上限哪些在視窗裡、哪些要用工具查，讓 agent 知道什麼時候該去找。
  6. 記憶整理拖慢回應時，改成非同步把整理區塊的工作交給另一個 agent，在閒置時做；這是作者說的睡眠時間 agent 的做法。

Reference · 名詞速查

十七個名詞，看懂 agent 的記憶放在哪裡

依「定義、四種記憶、管理技巧、工程系統」的順序排，解釋都是整理者依原文的用法寫的。

Stateless LLM
無狀態的模型
每次互動彼此孤立，上一段對話的知識不會帶到下一段；原文的起點。
Stateful agent
有狀態的 agent
把過去的互動與累積的經驗帶進之後的每一輪，才能隨時間學習與調整。
Agent memory
agent 記憶
agent 隨時間記住什麼、怎麼記住；原文說它取決於此刻 context window 裡有什麼。
Context window
情境視窗
模型一次看得到的 token；原文把它比作 agent 的工作記憶。
Context engineering
context 工程
決定哪些 token 進入視窗、在裡面怎麼組織；原文說設計記憶本質上就是它。
Message buffer
訊息緩衝區
存最近的訊息，是唯一的短期記憶；內容終究會被驅逐。
Core memory
核心記憶
由記憶區塊組成、固定釘在視窗裡的記憶；可由 agent 自己或其他 agent 管理，也可透過 API 編輯。
Memory block
記憶區塊
視窗裡有結構、可編輯的一段，包含標籤、說明、值與字元上限。
Recall memory
回想記憶
完整的互動歷史，不在視窗裡也能搜尋取回；存的是原始對話。
Archival memory
歸檔記憶
明確寫下、處理過並建了索引的知識，存在外部資料庫，用專門的工具查詢。
Eviction
驅逐
視窗到達容量時移除部分訊息；原文建議只驅逐一部分，例如 70%。
Recursive summarization
遞迴摘要
被驅逐的訊息連同既有的摘要再摘要一次；越舊的訊息，影響越小。
Context rewriting
context 改寫
用工具改寫記憶區塊、整併重要資訊，讓視窗隨時間變好。
Vector DB / Graph DB
向量／圖資料庫
外部記憶的兩種存法：向量搜尋找相似的內容；圖結構讓 agent 沿著概念之間的關係推理。
RAG / retrieval
檢索
用工具把外部資料取回視窗；原文說它是記憶的工具，不是記憶本身。
MemGPT
MemoryGPT
仿作業系統的記憶階層：視窗像 RAM、外部儲存像硬碟，模型用函式呼叫自己搬資料。
Sleep-time agent
睡眠時間 agent
在閒置時非同步整理記憶區塊的另一個 agent；作者說回應更快、記憶品質更好。
