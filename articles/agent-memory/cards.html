無狀態：每次互動都孤立
傳統的模型呼叫不帶上一次的任何東西。原文說這對基本任務與短命的 agent 還行，但從根本上限制了系統能做到的事。

原文的分法：緩衝區的內容終究會被驅逐，所以算短期；其他三種都算長期。

取回的方式也不同：搜尋歷史，或用工具查資料庫。

被移走的原始訊息仍在回想記憶裡，需要時可以搜尋（第 03 卡）；視窗裡只留下它們的摘要
遞迴摘要
每驅逐一次，就把舊摘要和這次移走的訊息一起再摘要；對話越長，越舊的訊息在摘要裡的影響越小
只驅逐一部分
原文的建議：一般只驅逐部分訊息，舉的例子是 70%，讓最近的對話留在視窗裡，確保對話接得上。
70% 是原文的例子，不是固定的規定。
先摘要，再移走
移除之前，先把重要的細節摘要、存起來；被移走的訊息要和既有的摘要一起再摘要一次。
摘要一層一層疊上去，不是每次從頭寫。
越舊的訊息，影響越小
遞迴摘要讓較舊的訊息在摘要裡的份量一次比一次少，最近的訊息影響最大。
要找回原句，就去回想記憶裡搜尋。
注意：分段長度是示意，只有 70% 是原文寫出的數字，而且原文把它寫成例子；驅逐前後兩列的排法是整理者的畫法。

改寫區塊，context 越變越好
agent 依新資訊用工具改寫區塊，專門的 agent 也能改；原文叫它 context 改寫：整併重要資訊，讓視窗隨時間變好。

不照抄人腦，把記憶當成 context 來設計
模型是文字進、文字出的系統，它的「記憶」只有視窗裡的東西；原文要設計的不是仿人腦的記憶結構，而是下面三件事

視窗怎麼排
